# MotionTok 외부 서비스 정보

SSAFY 15기 자율 프로젝트 A706 `MotionTok(모톡)` 이 사용하는 **모든 외부 서비스**의 가입·발급·설정 정보를 정리한 문서입니다.

> **이 제출물에는 시크릿 실제 값이 포함되지 않습니다.** 각 서비스의 키가 어떤 환경변수로 들어가는지는 본 문서가, 배포 시 등록해야 할 변수 전체 목록은 `exec/배포환경변수.md` 가 다룹니다.
> 배포(운영)의 실제 값은 GitLab **Settings → CI/CD → Variables** 에만 있고 레포에는 없습니다. `.gitlab-ci.yml` 이 배포 때마다 그 값으로 `.env` 를 생성합니다.
> 로컬 개발용 값이 담긴 `MotionTok/Backend/.env` · `MotionTok/Frontend/.env` 는 **팀 내부 파일이며 제출물이 아닙니다.**
> 이 문서는 "어떤 변수에, 어디서 발급받은 값을, 어떤 콘솔 설정과 함께 넣어야 하는가" 만 다룹니다.

> **경로 표기**: 모든 경로는 레포 루트(`S15P11A706/`) 기준 상대경로입니다.

> ⚠️ **팀 로컬 `.env` 에는 없지만 GitLab CI/CD Variables 에는 반드시 등록되어야 하는 값**
> `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `CORS_ALLOWED_ORIGINS`, `PW_RESET_LINK_BASE`, `MAIL_FROM`, `MYSQL_ROOT_PASSWORD`, (필요 시) `TURN_SECRET` — 단 `TURN_SECRET` 은 `.gitlab-ci.yml` 에 `add TURN_SECRET "$TURN_SECRET"` 줄을 먼저 추가해야 반영됩니다(§5-2).
> 로컬 개발에서는 `application.yaml` 기본값으로 굴러가지만 운영에서는 기본값이 틀리거나 아예 없는 변수들입니다. 등록 여부 점검은 `exec/배포환경변수.md` 의 체크리스트를 쓰세요.
> 특히 `MYSQL_ROOT_PASSWORD` 는 `docker-compose.prod.yml` 에 기본값이 없어, 없으면 MySQL 컨테이너 root 비밀번호가 빈 값이 되고 healthcheck 도 실패합니다.

> ⚠️ **`GOOGLE_REDIRECT_URI` 는 죽은 변수입니다.**
> 팀 로컬 `MotionTok/Backend/.env` 에 `GOOGLE_REDIRECT_URI` 가 남아 있지만, 레포 전체(`*.java` / `*.yaml` / `*.ts` / `*.vue` / `*.gradle`)에서 이 이름을 읽는 코드가 **한 곳도 없습니다.** 실제 redirect URI 는 프론트가 `${window.location.origin}/auth` 로 직접 만들어 씁니다 (`MotionTok/Frontend/src/features/auth/socialAuthorize.ts:11`). **콘솔에는 `/oauth/google` 이 아니라 `/auth` 를 등록해야 합니다.**

## 1. Google OAuth 2.0 (소셜 로그인)

### 1-1. 용도

| 기능 | 설명 | 코드 위치 |
|---|---|---|
| 소셜 로그인 | `POST /auth/social/google` — 프론트가 받은 인가 코드를 백엔드가 토큰·유저정보로 교환 | `MotionTok/Backend/src/main/java/ssafy/a706/backend/auth/oauth/client/GoogleOauthClient.java` |
| 회원 탈퇴 재인증 | 소셜 전용 계정은 비밀번호가 없어 탈퇴 시 소셜 재인증으로 본인 확인 | `MotionTok/Backend/src/main/java/ssafy/a706/backend/user/service/UserService.java:289` |
| 인가 URL 조립 (FE) | `/auth` 화면의 구글 버튼 → `accounts.google.com` 리다이렉트 | `MotionTok/Frontend/src/features/auth/socialAuthorize.ts:49-61` |

관련 설정 바인딩: `MotionTok/Backend/src/main/java/ssafy/a706/backend/auth/oauth/OauthProperties.java` (prefix `app.oauth`), 로그인 서비스 `.../auth/service/AuthService.java:167`.

호출하는 구글 엔드포인트:

| 단계 | URL | 호출 주체 |
|---|---|---|
| Authorize | `https://accounts.google.com/o/oauth2/v2/auth` | 프론트(브라우저 리다이렉트) |
| Token 교환 | `https://oauth2.googleapis.com/token` | 백엔드 |
| 사용자 정보 | `https://openidconnect.googleapis.com/v1/userinfo` | 백엔드 |

읽는 필드: `sub`(고유 id), `email`, `email_verified`, `name`

### 1-2. 가입 및 발급 절차

1. https://console.cloud.google.com 접속 후 구글 계정으로 로그인
2. 상단 프로젝트 선택기 → **새 프로젝트** → 이름 입력(예: `MotionTok`) → **만들기**
3. 좌측 메뉴 **API 및 서비스 → OAuth 동의 화면**
   1. User Type: **외부(External)** 선택 → **만들기**
   2. 앱 이름 `MotionTok`, 사용자 지원 이메일·개발자 연락처 이메일 입력 → **저장 후 계속**
   3. 범위(Scopes) 단계에서 **범위 추가 또는 삭제** → `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile` 체크 → **업데이트** → **저장 후 계속**
   4. 테스트 사용자 단계에서 시연에 쓸 구글 계정을 **＋ ADD USERS** 로 추가 (게시 상태가 "테스트"면 등록된 계정만 로그인 가능)
4. 좌측 메뉴 **API 및 서비스 → 사용자 인증 정보**
   1. **＋ 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   2. 애플리케이션 유형: **웹 애플리케이션**
   3. 이름: `MotionTok Web`
   4. **승인된 자바스크립트 원본** 과 **승인된 리디렉션 URI** 를 아래 1-3 표대로 입력
   5. **만들기** → 팝업에 표시되는 **클라이언트 ID** 와 **클라이언트 보안 비밀번호** 복사

### 1-3. 콘솔에 등록해야 하는 설정 값

| 항목 | 로컬 개발용 | 배포용 |
|---|---|---|
| 승인된 자바스크립트 원본 | `http://localhost:5173` | `https://motok.co.kr` |
| **승인된 리디렉션 URI** | `http://localhost:5173/auth` | `https://motok.co.kr/auth` |
| scope | `openid email profile` (프론트가 `&scope=openid%20email%20profile` 로 고정 전송) | 동일 |
| 추가 파라미터 | `response_type=code`, `prompt=select_account` (코드에 하드코딩, 콘솔 설정 아님) | 동일 |

> **리디렉션 URI 는 `/auth` 하나뿐입니다.** 로그인이든 탈퇴 재인증이든 항상 같은 URI 를 쓰고, "왜 인가를 받으러 갔는지"는 `sessionStorage` 의 `motok.socialIntent` 로 구분합니다 (`socialAuthorize.ts:4-6, 14`).
> 로컬·배포 둘 다 시연할 예정이면 **두 URI 를 모두 등록**해 두세요.

### 1-4. 발급 결과를 넣을 환경변수

| 발급값 | 환경변수 | 넣는 곳 |
|---|---|---|
| 클라이언트 ID | `GOOGLE_CLIENT_ID` | 로컬 `MotionTok/Backend/.env` (팀 내부) / 배포 GitLab CI/CD Variables |
| 클라이언트 보안 비밀번호 | `GOOGLE_CLIENT_SECRET` | 동일 |
| 클라이언트 ID (동일 값) | `VITE_GOOGLE_CLIENT_ID` | 로컬 `MotionTok/Frontend/.env` (팀 내부) / 배포 GitLab CI/CD Variables |

배포 시에는 GitLab **Settings → CI/CD → Variables** 에 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `VITE_GOOGLE_CLIENT_ID` 를 등록합니다. (`.gitlab-ci.yml` 의 `add GOOGLE_CLIENT_ID ...` / deploy-frontend 의 `-e VITE_GOOGLE_CLIENT_ID`)

> **FE 의 `VITE_GOOGLE_CLIENT_ID` 는 빌드 시점에 번들에 박힙니다.** GitLab Variables 에 등록만 하고 `docker run` 의 `-e` 로 넘기지 않으면 반영되지 않습니다.
> 값이 비어 있으면 `isSocialConfigured('google')` 이 false 가 되어 **로그인 화면의 구글 버튼이 비활성화**됩니다 (`socialAuthorize.ts:25-27`).

### 1-5. 무료 한도 / 요금 / 주의사항

- **무료.** OAuth 2.0 로그인 자체는 과금 대상이 아닙니다.
- OAuth 동의 화면이 "테스트" 상태면 **등록한 테스트 사용자만** 로그인할 수 있습니다. 시연 계정을 미리 추가하세요.
- 리디렉션 URI 는 **완전 일치**로 검사됩니다. 끝의 `/` 유무, `http`/`https`, 포트까지 정확히 맞아야 하며, 틀리면 `redirect_uri_mismatch` 오류가 납니다.
- 백엔드에서 구글 client-id 가 비어 있으면 구글 로그인만 `401 SOCIAL_LOGIN_FAILED` 로 실패하고, 앱의 다른 기능은 정상 동작합니다 (`application.yaml` 주석).
- 외부 OAuth 호출용 WebClient 는 connect 5초 / response 5초 타임아웃입니다. 타임아웃도 `SOCIAL_LOGIN_FAILED` 로 매핑됩니다 (`.../global/config/WebClientConfig.java`).

## 4. LiveKit (WebRTC SFU, 자체 호스팅)

### 4-1. 용도

화상·음성·게임 화면 송출 전부를 담당하는 SFU 입니다. **LiveKit Cloud 를 쓰지 않고 우리 서버에서 컨테이너로 직접 띄웁니다** — 즉 외부 SaaS 가입이 필요 없고, "API 키/시크릿"도 우리가 만들어 넣는 값입니다.

| 구성요소 | 내용 | 코드/설정 위치 |
|---|---|---|
| 서버 이미지 | `livekit/livekit-server:v1.13.4` | `MotionTok/Backend/docker-compose.yml`, `docker-compose.prod.yml` |
| 로컬 설정 | 키가 파일에 하드코딩 (`devkey: devsecret-local-only-0123456789abcdef`) | `MotionTok/Backend/livekit/livekit.yaml` |
| 운영 설정 | 키는 파일에 없고 compose 가 `LIVEKIT_KEYS` 환경변수로 주입 | `MotionTok/Backend/livekit/livekit.prod.yaml` |
| 토큰 발급 | 백엔드가 HS256 JWT 를 **직접 서명** (LiveKit 서버 SDK 미사용, jjwt 사용) | `.../video/provider/LivekitTokenSigner.java`, `LivekitAccessProvider.java` |
| 토큰 API | `GET /v1/live-rooms/{roomId}/video-token` → `{ url, token, expiresIn }` | `MotionTok/Frontend/src/api/modules/sfu.ts` |
| 참가자 강제 퇴장 | `{baseUrl}/twirp/livekit.RoomService/RemoveParticipant` | `.../video/provider/SfuParticipantEjector.java` |
| 프론트 SDK | `livekit-client ^2.20.2` | `MotionTok/Frontend/package.json` |

### 4-2. 준비 절차 (가입 대신 "키 생성 + 포트 개방")

**로컬**
1. `MotionTok/Backend` 에서 `docker compose up -d livekit` (또는 `docker compose up -d` 로 전체 기동)
2. 별도 키 발급 불필요 — `livekit/livekit.yaml` 의 `devkey/devsecret-local-only-0123456789abcdef` 를 그대로 씁니다. `application.yaml` 기본값과 이미 일치합니다.

**배포(EC2)**
1. 운영 전용 키/시크릿을 직접 생성합니다. 임의의 랜덤 문자열이면 되며, 시크릿은 충분히 길게 잡습니다.
   ```bash
   # 예: 키와 시크릿 생성
   openssl rand -hex 8    # → LIVEKIT_API_KEY 로 사용
   openssl rand -hex 32   # → LIVEKIT_API_SECRET 로 사용
   ```
2. GitLab **Settings → CI/CD → Variables** 에 `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` 등록
3. EC2 **보안그룹(또는 UFW)** 에 아래 포트를 인바운드 허용
4. `docker compose -f docker-compose.prod.yml up -d --build` (CI 가 자동 수행)

### 4-3. 등록/개방해야 하는 설정 값

| 항목 | 로컬 | 배포 |
|---|---|---|
| 접속 URL | `ws://localhost:7880` | `wss://motok.co.kr/livekit` (nginx 가 `/livekit` prefix 제거 후 `http://livekit:7880` 으로 프록시) |
| 시그널링 포트 | `7880` 호스트 노출 | `expose` 만 — 호스트 비공개, nginx 만 접근 |
| TCP 폴백 | `7881` | **`7881/TCP` 인바운드 개방 필수** |
| RTC 미디어 | `7882/udp` (단일 포트 멀티플렉스) | **`50000-50100/UDP` 인바운드 개방 필수** (nginx 미경유, 직행) |
| `use_external_ip` | `false` | **`true`** — EC2 는 자기 공인 IP 를 모르는 NAT 구조라 이 값이 없으면 미디어 연결이 무조건 실패 |

> ⚠️ **UDP 포트 범위는 `livekit.prod.yaml` 의 `port_range_start`/`port_range_end` 와 보안그룹 개방 범위가 반드시 일치**해야 합니다 (파일 주석에 명시).

### 4-4. 발급 결과를 넣을 환경변수

| 환경변수 | 기본값 | 넣는 곳 | 비고 |
|---|---|---|---|
| `LIVEKIT_URL` | `ws://localhost:7880` | `.env` / CI Variables | 운영 `wss://motok.co.kr/livekit` |
| `LIVEKIT_API_KEY` | `devkey` | 동일 | |
| `LIVEKIT_API_SECRET` | `devsecret-local-only-0123456789abcdef` | 동일 | |
| `LIVEKIT_TOKEN_TTL` | `10m` | 선택 | |
| `RTC_PROVIDER` | `livekit` | 선택 | `livekit` \| `openvidu` \| `mesh` |

> **같은 `.env` 를 Spring 앱과 LiveKit 컨테이너가 공유합니다.** compose 가 `LIVEKIT_KEYS: "${LIVEKIT_API_KEY}: ${LIVEKIT_API_SECRET}"` 형식(콜론+공백)으로 컨테이너에 넘기므로, 두 값이 일치해야 백엔드가 서명한 토큰을 LiveKit 이 검증할 수 있습니다 (`docker-compose.prod.yml`).

### 4-5. 무료 한도 / 요금 / 주의사항

- **자체 호스팅이므로 LiveKit 자체 이용료는 없습니다.** 비용은 EC2 인스턴스 요금과 아웃바운드 트래픽뿐입니다.
- 운영 compose 에서 livekit 서비스만 `mem_limit` 을 **의도적으로 걸지 않았습니다** — 2000명 규모 실측이 없어 추측으로 조이면 영상이 통째로 끊기기 때문입니다 (`docker-compose.prod.yml` 주석).
- `nginx` 는 `depends_on: livekit` 이라 livekit 컨테이너가 없으면 **nginx 기동 시 upstream 해석에 실패**합니다.
- `OPENVIDU_*` 설정도 코드에 있으나 `RTC_PROVIDER` 기본값이 `livekit` 이고 CI 가 `OPENVIDU_*` 를 넣지 않으므로 **운영은 LiveKit 고정**입니다.

모든 업로드 객체에 `Cache-Control: public, max-age=31536000, immutable` 을 붙입니다.

### 6-2. 로컬 — MinIO (가입 불필요)

로컬 개발은 compose 가 MinIO 를 띄우고 **버킷 생성·공개 정책까지 자동으로 처리**합니다.

1. `MotionTok/Backend` 에서 `docker compose up -d`
2. `minio-init` one-shot 컨테이너가 자동 실행:
   - `mc alias set local http://minio:9000 $ACCESS_KEY $SECRET_KEY`
   - `mc mb --ignore-existing local/$BUCKET`
   - `mc anonymous set download local/$BUCKET/public` ← **`public/` prefix 만 익명 읽기 허용**
3. 웹 콘솔 `http://localhost:9001` 로 접속해 업로드된 객체를 눈으로 확인 (계정은 `S3_ACCESS_KEY`/`S3_SECRET_KEY`, 기본 `minioadmin`/`minioadmin`)

| 환경변수 | 로컬 값 (`MotionTok/Backend/.env` — 팀 내부, 제출물 아님) |
|---|---|
| `S3_ENDPOINT` | `http://localhost:9000` |
| `S3_PATH_STYLE` | `true` |
| `S3_BUCKET` | `motok-local` |
| `S3_REGION` | `us-east-1` (MinIO 는 리전을 안 보지만 SDK 가 요구) |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | `minioadmin` / `minioadmin` |
| `S3_PUBLIC_BASE_URL` | `http://localhost:9000/motok-local` |

### 6-3. 배포 — AWS S3

#### 가입 및 발급 절차

1. https://aws.amazon.com 에서 AWS 계정 생성 (결제 수단 등록 필요)
2. https://s3.console.aws.amazon.com/s3 → **버킷 만들기**
   1. 버킷 이름 입력 (전 세계 고유), 리전 **아시아 태평양(서울) ap-northeast-2** 선택
   2. **퍼블릭 액세스 차단 설정** → "모든 퍼블릭 액세스 차단" **해제** (아래 버킷 정책으로 `public/*` 만 열기 위함)
   3. **버킷 만들기**
3. 생성한 버킷 → **권한 → 버킷 정책 → 편집** → 아래 정책 입력 후 저장
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Sid": "PublicReadForPublicPrefix",
         "Effect": "Allow",
         "Principal": "*",
         "Action": "s3:GetObject",
         "Resource": "arn:aws:s3:::<버킷명>/public/*"
       }
     ]
   }
   ```
   > 로컬 MinIO 의 `mc anonymous set download .../public` 과 **같은 역할**입니다 (`docker-compose.yml` 주석: "AWS에서는 이 역할을 버킷 정책이 대신한다(public/* 만 s3:GetObject 허용)").
4. 버킷 → **권한 → CORS(교차 오리진 리소스 공유)** 설정
   브라우저가 presigned URL 로 **직접 PUT** 하므로 CORS 허용이 필요합니다.
   ```json
   [
     {
       "AllowedHeaders": ["*"],
       "AllowedMethods": ["PUT", "GET"],
       "AllowedOrigins": ["https://motok.co.kr", "http://localhost:5173"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3000
     }
   ]
   ```
   `TODO(확인필요): 운영 버킷에 실제로 설정된 CORS 규칙 — 레포에 CORS 설정 파일/문서가 없어 위 내용은 코드 동작(브라우저 직접 PUT)에서 역산한 권장값입니다.`
5. 자격증명 준비 — 아래 둘 중 하나
   - **(권장) EC2 IAM 역할**: EC2 인스턴스에 `s3:PutObject`/`s3:GetObject`/`s3:DeleteObject`/`s3:HeadObject` 권한 정책이 붙은 IAM 역할을 연결. 이 경우 `S3_ACCESS_KEY`/`S3_SECRET_KEY` 를 **등록하지 않으면** 코드가 `DefaultCredentialsProvider` 로 자동 전환합니다 (`StorageProperties.hasStaticCredentials()`).
   - **IAM 사용자 액세스 키**: IAM → 사용자 → 액세스 키 만들기 → `S3_ACCESS_KEY`/`S3_SECRET_KEY` 로 등록

#### 콘솔에 등록해야 하는 설정 값 (요약)

| 항목 | 로컬(MinIO) | 배포(AWS S3) |
|---|---|---|
| 버킷 생성 | `minio-init` 자동 | 콘솔에서 수동 생성 |
| `public/` 공개 | `mc anonymous set download` 자동 | **버킷 정책**으로 `public/*` 만 `s3:GetObject` 허용 |
| CORS | 불필요(같은 오리진 프록시 아님, 로컬은 대개 무관) | `https://motok.co.kr` (+ 로컬 테스트 시 `http://localhost:5173`) 허용 |
| 주소 방식 | path-style (`S3_PATH_STYLE=true`) | virtual-hosted (기본 `false`) |

#### 발급 결과를 넣을 환경변수 (배포)

| 환경변수 | 배포 값 | CI 등록 |
|---|---|---|
| `S3_BUCKET` | 생성한 버킷명 | ✅ |
| `S3_REGION` | `ap-northeast-2` (기본값과 같으면 생략 가능) | ✅ |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | IAM 액세스 키 (IAM 역할 사용 시 생략) | ✅ |
| `S3_PUBLIC_BASE_URL` | `https://<버킷>.s3.ap-northeast-2.amazonaws.com` | ✅ |
| `S3_ENDPOINT` | **등록하지 않음** | ❌ 의도적 |
| `S3_PATH_STYLE` | **등록하지 않음** | ❌ 의도적 |

> `.gitlab-ci.yml:72-75` 주석: "S3_ENDPOINT / S3_PATH_STYLE 은 일부러 등록하지 않는다: 비어 있으면 실제 AWS 로 붙고… 등록하지 않는 것만으로 운영이 자동으로 AWS 모드가 된다"

> **퍼블릭 URL 은 조립하지 않습니다.** 코드는 `S3_PUBLIC_BASE_URL + "/" + key` 를 그대로 씁니다 (`StorageService.java:178-180`). path-style(MinIO)과 virtual-hosted(AWS)의 주소 구조가 달라, 버킷명으로 조립하면 한쪽이 깨지기 때문입니다.

> ⚠️ **nginx CSP 와 연동됩니다.** `MotionTok/Backend/nginx/conf.d/motok.conf` 의 CSP 가 `img-src ... https://*.amazonaws.com`, `connect-src ... https://*.amazonaws.com` 을 허용합니다. `S3_PUBLIC_BASE_URL` 을 CloudFront 등 **다른 도메인**으로 바꾸면 CSP 에도 그 도메인을 추가해야 아바타가 뜹니다.

### 6-4. 무료 한도 / 요금 / 주의사항

- **MinIO: 무료** (로컬 컨테이너).
- **AWS S3: 유료.** 프리티어(신규 계정 12개월)는 표준 스토리지 5GB, GET 20,000건, PUT 2,000건 수준입니다. 이 프로젝트의 업로드 상한(아바타·아이템 2MB, 음원 20MB)을 고려하면 시연 규모에서는 프리티어 안쪽이지만, **정확한 요금은 AWS 요금 페이지를 확인하세요.**
- `S3_BUCKET` 또는 `S3_PUBLIC_BASE_URL` 이 비어 있으면 **앱은 정상 기동하고 업로드만** `STORAGE_UNAVAILABLE` 로 실패합니다 (`StorageProperties.isConfigured()`).

- **유료입니다.** fal.ai 는 크레딧 선불 방식이며, 생성 1건마다 모델별 단가로 차감됩니다. `TODO(확인필요): 현재 팀 계정의 잔여 크레딧과 모델 단가` — 레포에서 확인 불가.

  - 상한 경고 로그는 상태 전이 시 1회만 남깁니다
  - 상한 주석: "GPU 가 조용히 죽으면 전량 fal 로 흘러 크레딧이 하루에 소진될 수 있다"

3. https://myaccount.google.com/apppasswords 접속
4. **앱 이름** 에 `MotionTok` 입력 → **만들기**
5. 팝업에 표시되는 **16자리 문자열**(공백 4칸으로 구분되어 표시)을 복사
   - ⚠️ 이 창을 닫으면 다시 볼 수 없습니다.
6. `.env` 에 넣을 때는 **공백을 모두 제거**하고 16자 붙여서 입력합니다.
   (팀 로컬 `.env` 의 `MAIL_PASSWORD` 도 공백 없는 16자 소문자 형식입니다.)

### 9-5. 무료 한도 / 요금 / 주의사항

- **무료.** 개인 Gmail 계정의 SMTP 발송 한도는 일반적으로 하루 수백 통 수준이며, 시연 규모에서는 충분합니다.
- ⚠️ **SSAFY 개발망에서는 SMTP 포트(587/465)가 차단됩니다.** 이 경우 아래 로그 폴백을 쓰세요.

  **로그 폴백 사용법 (로컬 전용 — `.env` 를 손으로 쓰는 환경에서만 됩니다)**: `.env` 에서 `MAIL_HOST` 를 **빈 값으로 선언**(`MAIL_HOST=`)하면, `JavaMailSender` 빈이 없거나 host 가 blank 일 때 메일을 발송하지 않고 로그로만 출력합니다.
  ```java
  // VerificationMailSender.java:32-37
  if (sender == null || mailHost == null || mailHost.isBlank()) {
      log.warn("[메일 미설정] {} 인증번호 = {} (SMTP 미설정이라 실제 발송하지 않음)", email, code);
      return;
  }
  ```
  비밀번호 재설정도 같은 패턴(`[메일 미설정] {} 비밀번호 재설정 링크 = {}`)이라, **SMTP 계정 없이 서버 로그만 보고 가입·재설정 흐름을 끝까지 테스트**할 수 있습니다.

  > ⚠️ 단, `application.yaml` 의 `spring.mail.host: ${MAIL_HOST}` 에는 **기본값이 없습니다.** 변수를 아예 삭제하지 말고 반드시 `MAIL_HOST=` 처럼 **빈 값으로 선언**하세요. (`TODO(확인필요): MAIL_HOST 를 완전히 제거했을 때 앱이 기동 실패하는지 — 정적으로 기본값이 없다는 사실만 확인했고 실행 검증은 하지 않았습니다.`)

  > ⚠️ **배포에서는 이 우회가 그대로 통하지 않습니다.** CI 가 매 배포마다 `.env` 를 새로 만들고, `add() { [ -n "$2" ] && echo "$1=$2" >> .env; return 0; }` 가 빈 값을 걸러내므로 GitLab Variables 의 `MAIL_HOST` 를 빈 값으로 두면 `.env` 에 **줄 자체가 들어가지 않아** "빈 값 선언"이 아니라 "미설정"이 됩니다. `${MAIL_HOST}` 에 기본값이 없으니 결과는 기동 실패입니다. 배포에서 SMTP 를 끄려면 둘 중 하나를 택하세요.
  > - GitLab Variables 의 `MAIL_HOST` 값에 **공백 1칸 등 blank 문자열**을 넣어 `add` 의 `-n` 검사를 통과시켜 `MAIL_HOST= ` 줄이 남게 한다. 애플리케이션 쪽은 `@Value("${spring.mail.host:}")` 를 `isBlank()` 로 보므로 로그 폴백이 그대로 동작합니다 (`VerificationMailSender.java:25, 34`). 다만 `.env` 의 공백 값이 compose 를 거쳐 그대로 전달되는지는 실행 검증 전입니다(§16 TODO #14).
  > - `application.yaml` 을 `host: ${MAIL_HOST:}` 로 고쳐 **기본값(빈 문자열)을 부여**한다 (`MAIL_PORT`/`MAIL_USERNAME`/`MAIL_PASSWORD` 도 동일하게 기본값이 없으니 함께 손봐야 합니다).

- `MAIL_HEALTH_ENABLED=true` 로 켜면 SMTP 가 막힌 망에서 종합 `/actuator/health` 가 **503 + 호출마다 5초 지연**이 발생합니다. 기본값 `false` 를 유지하세요.
- 앱 비밀번호는 계정 보안 페이지에서 **언제든 취소(Revoke)** 할 수 있습니다. 유출이 의심되면 즉시 취소하고 재발급하세요(§15).

## 10. Let's Encrypt / certbot (HTTPS 인증서)

### 10-1. 용도

`https://motok.co.kr` 의 TLS 인증서를 발급·자동 갱신합니다. 웹캠(`getUserMedia`)은 보안 컨텍스트(HTTPS 또는 localhost)에서만 동작하므로 **배포에는 HTTPS 가 필수**입니다.

| 구성요소 | 내용 | 위치 |
|---|---|---|
| 발급 스크립트 | 최초 1회 실행 | `MotionTok/Backend/init-letsencrypt.sh` |
| 갱신 컨테이너 | `certbot/certbot`, 12시간마다 `certbot renew` 루프 | `MotionTok/Backend/docker-compose.prod.yml` |
| 반영 | nginx 가 6시간마다 self `nginx -s reload` | 동일 |
| 인증서 경로 | `/etc/letsencrypt/live/motok.co.kr/{fullchain,privkey}.pem` (named volume `certbot-conf`) | `MotionTok/Backend/nginx/conf.d/motok.conf` |
| ACME webroot | `/var/www/certbot` (named volume `certbot-www`) | 동일 |

### 10-2. 발급 절차 (가입 불필요, EC2 에서 1회)

**선행 조건** (`init-letsencrypt.sh` 주석):
1. 가비아 DNS 에 `motok.co.kr` A레코드 → EC2 고정 public IP 등록, **전파 완료**
2. EC2 보안그룹 인바운드 **80, 443 을 `0.0.0.0/0` 허용** (Let's Encrypt 검증용)
3. `MotionTok/Backend/.env` 파일이 존재

**실행** (EC2, `MotionTok/Backend` 디렉터리에서 **딱 한 번**):
```bash
chmod +x init-letsencrypt.sh && ./init-letsencrypt.sh
```

스크립트가 하는 일 (5단계):
1. 더미 인증서 생성 (nginx 가 뜨려면 인증서 파일이 먼저 있어야 함)
2. `docker compose -f docker-compose.prod.yml up -d nginx`
3. 더미 제거
4. webroot 방식으로 실제 발급 — `certbot certonly --webroot -w /var/www/certbot -d motok.co.kr --email <이메일> --agree-tos --no-eff-email --force-renewal`
5. `nginx -s reload`

스크립트 안의 값: `DOMAIN="motok.co.kr"`, `EMAIL="<인증서 만료 알림 받을 이메일>"` — **다른 도메인으로 포팅할 때 이 두 줄을 바꿉니다.**

### 10-3. 환경변수

**없습니다.** 도메인·이메일은 `init-letsencrypt.sh` 안에 직접 적혀 있고, 인증서는 Docker named volume 에 보관됩니다.

### 10-4. 무료 한도 / 요금 / 주의사항

- **무료.**
- Let's Encrypt 는 **rate limit** 이 있습니다(동일 도메인 주당 발급 횟수 제한). `--force-renewal` 을 반복 실행하면 한도에 걸릴 수 있으니 최초 1회만 실행하세요.
- 갱신은 완전 자동입니다 — certbot 컨테이너가 12시간마다 `renew` 를 시도하고(만료 30일 이내일 때만 실제 갱신), nginx 가 6시간마다 reload 해서 반영합니다. **수동 개입 불필요.**
- 인증서 발급 검증은 HTTP-01 방식이므로 **80 포트가 열려 있어야** 합니다. nginx 의 80번 서버 블록이 `/.well-known/acme-challenge/` 만 `root /var/www/certbot` 으로 서빙하고 나머지는 443 으로 301 리다이렉트합니다.

## 12. GPU 워커 (자체 호스팅, 공유 시크릿)

### 12-1. 용도

AI 아이템 생성을 팀 GPU 서버에서 처리하는 경로입니다(`AI_PROVIDER=GPU` 또는 `AUTO`). **외부 SaaS 가 아닙니다.**

GPU 서버는 외부에서 호출할 수 없는 위치에 있어, **워커가 백엔드로 주기적으로 물어보는 폴링 구조**입니다 (`.../shop/controller/InternalAiJobController.java:19-20`).

| 엔드포인트 | 동작 |
|---|---|
| `GET /api/internal/ai-jobs/next` | 처리할 job 1건 반환 (없으면 204) |
| `POST /api/internal/ai-jobs/{jobId}/complete` | 결과 이미지 제출 |
| `POST /api/internal/ai-jobs/{jobId}/fail` | 실패 보고 |

**인증은 JWT 가 아니라 공유 시크릿 헤더 `X-Internal-Key`** 입니다. `SecurityConfig` 는 이 경로를 permitAll 로 열고, 실제 방어선은 `.../global/security/InternalApiKeyFilter.java` 입니다.

### 12-2. 준비 절차

1. 충분히 긴 랜덤 문자열을 하나 만듭니다.
   ```bash
   openssl rand -hex 32
   ```
2. 백엔드 `INTERNAL_API_KEY` 환경변수에 등록
3. GPU 워커 쪽에도 **동일한 값**을 설정하고, 모든 요청에 `X-Internal-Key: <값>` 헤더를 실어 보내도록 구성

### 12-3. 환경변수

| 환경변수 | 기본값 | 비고 |

## 15. 키 재발급/교체가 필요할 때

### 15-1. 공통 절차

| 환경 | 값을 바꾸는 곳 | 반영 방법 |
|---|---|---|
| **로컬** | `MotionTok/Backend/.env` / `MotionTok/Frontend/.env` (팀 내부, 제출물 아님) | 백엔드는 **재기동**, 프론트는 **`pnpm dev` 재시작** |
| **배포** | GitLab → 프로젝트 → **Settings → CI/CD → Variables** | `main` 브랜치에 커밋을 푸시해 파이프라인 재실행. CI 가 `.env` 를 새로 만들고 `docker compose -f docker-compose.prod.yml up -d --build` 수행 |

> ⚠️ **프론트는 `VITE_API_BASE_URL` 만 예외입니다.** `MotionTok/Frontend/.env` 를 고쳐도 `pnpm dev`(mode=development)에는 반영되지 않습니다 — mode 별 파일인 `MotionTok/Frontend/.env.development`(`VITE_API_BASE_URL=/api`, git 추적 중)가 `.env` 를 이기기 때문입니다. dev 에서 다른 백엔드를 보려면 `.env.development.local` 에 절대 URL 로 덮어쓰세요. `VITE_GOOGLE_CLIENT_ID`·`VITE_KAKAO_REST_KEY` 는 `.env.development` 에 없으므로 `.env` 값이 그대로 쓰이고, `pnpm dev` 재시작만으로 반영됩니다.

> **배포는 `.env` 파일을 직접 수정하지 않습니다.** CI 가 매 배포마다 GitLab Variables 로부터 `MotionTok/Backend/.env` 를 새로 생성해 덮어씁니다. EC2 에서 손으로 고쳐도 다음 배포에 날아갑니다.

> **`add()` 헬퍼 규칙**: `add() { [ -n "$2" ] && echo "$1=$2" >> .env; return 0; }` — CI 는 값이 비어 있으면 `.env` 에 줄 자체를 넣지 않습니다. 빈 문자열을 넣으면 Spring 이 `application.yaml` 기본값 대신 빈 값을 써서 기동이 실패하기 때문입니다. 따라서 변수를 끄고 싶을 때 **GitLab Variables 에서 값을 비우든 변수 자체를 삭제하든 `.env` 에 줄이 안 들어가 결과는 같습니다.** 단 `MAIL_*` 4종(`MAIL_HOST`·`MAIL_PORT`·`MAIL_USERNAME`·`MAIL_PASSWORD`)은 `application.yaml` 에 기본값이 없어 **어느 쪽이든 기동 실패**로 이어지니 주의하세요 (§9-5).
