**로컬 개발 구성 차이**

```
[브라우저] ──► Vite dev server :5173 ──프록시(/api, /ws)──► Spring Boot :8080 (IDE 직접 실행)
                                                              │
                    docker compose up -d 로 띄우는 인프라 ──────┤
                    mysql :3307 / redis :6379 / livekit :7880 / minio :9000·9001
```

- 로컬에는 nginx·certbot·node-exporter가 없고, **MinIO가 AWS S3를 대신**합니다.
- 로컬 백엔드(app)는 컨테이너가 아니라 **IDE 또는 `gradlew bootRun`으로 직접 실행**합니다.

### 2-5. 제품별 주요 설정 값

> 제출 요건의 **"설정 값"** 항목입니다.
> **JVM 실행 옵션은 §5-2**, **nginx 설정은 §6-9** 에 이미 상세히 있으므로 여기서는 상호참조만 걸고, 그 두 곳에 없는 **WAS(내장 Tomcat) · DB · Redis · JPA** 설정값을 정리합니다.

| 제품 | 설정 키 | 값 | 왜 그 값인가 | 근거 |
|---|---|---|---|---|
| **WAS**<br>(내장 Tomcat) | `server.port` | `8080` | 앱 HTTP 포트. 운영 compose는 이 포트를 **호스트에 바인딩하지 않고 `expose`만** 해서 nginx만 접근합니다(§6-2) | `application.yaml:49` |
| **WAS** | `server.tomcat.mbeanregistry.enabled` | **`true`** | 기본값 `false`. **켜야 `tomcat_threads_busy` / `tomcat_threads_config_max` 지표가 나옵니다.** 커넥션 풀 다음으로 중요한 포화 신호인데, 끄면 "스레드가 몇 개 차올랐나"를 아예 볼 수 없습니다. 비용은 기동 시 MBean 등록뿐이고 **요청 경로에는 관여하지 않습니다** | `application.yaml:50-56` |
| **WAS** | `server.tomcat.keep-alive-timeout` | **`120s`** | ★ **nginx upstream의 `keepalive_timeout 30s`와 짝을 이루는 값입니다.** nginx는 app으로 가는 커넥션을 재사용하려고 열어 두는데, **톰캣이 먼저 끊으면 nginx가 이미 닫힌 커넥션에 요청을 실어 보내 간헐 502**가 뜹니다. 톰캣 기본값은 `connectionTimeout`(20초)을 따라가 nginx(30초)보다 **짧아서**, 그대로 두면 재현이 안 되는 502가 됩니다. 톰캣을 확실히 더 길게 잡아 **항상 nginx가 먼저 닫도록** 순서를 고정한 것입니다. **한쪽만 바꾸지 마세요**(§7-8 #3) | `application.yaml:57-63` + `nginx/conf.d/motok.conf`의 `upstream backend`(§6-9) |
| **WAS**<br>(관리 포트) | `management.server.port` | **`9090`** | ★ **8080과 분리합니다.** 톰캣 스레드가 전부 잠기면 같은 포트에 있는 actuator도 응답하지 못해 **"죽는 순간의 지표"를 잃습니다** — 그 순간이 가장 알고 싶은 때입니다. 이 포트는 외부에 열지 않고 `127.0.0.1`에만 바인딩합니다(§6-2) | `application.yaml:75-79` |
| **WAS**<br>(관리 포트) | `management.endpoints.web.exposure.include` | **`health,prometheus`** | ★ **`heapdump`·`env`는 절대 열지 않습니다.** `heapdump`는 호출 한 번으로 힙 전체를 덤프해 서버를 멈추고, `env`는 **시크릿을 통째로 뱉습니다.** 관측이 부하·유출이 되면 측정값 자체가 오염됩니다 | `application.yaml:80-83` |
| **WAS**<br>(관리 포트) | `management.endpoint.health.show-details`<br>`management.endpoint.health.probes.enabled` | `always`<br>`true` | 9090은 SSH 터널로만 접근하므로 DB·Redis 상태까지 보이는 편이 진단에 낫습니다. `probes.enabled=true`가 `/actuator/health/liveness`를 만드는데, **운영 compose healthcheck가 이 경로를 보므로 없으면 앱이 멀쩡해도 컨테이너가 영원히 unhealthy**가 됩니다(§6-4) | `application.yaml:100-115` |
| **JVM** | 실행 옵션 6종 | `-XX:MaxRAMPercentage=60.0` 외 | **→ §5-2 「ENTRYPOINT JVM 옵션」 표 참조** (중복 서술 생략) | `MotionTok/Backend/Dockerfile` |
| **웹서버**<br>(nginx) | main · server · gzip 설정 | `worker_connections 16384`, upstream `keepalive 128`, CSP, 캐시 정책 등 | **→ §6-9 「nginx 설정」 참조** (중복 서술 생략) | `nginx/nginx.conf`, `nginx/conf.d/*.conf` |
| **DB**<br>(MySQL) | `--character-set-server`<br>`--collation-server` | **`utf8mb4`**<br>**`utf8mb4_unicode_ci`** | 게임명·규칙문·아이템명·닉네임·채팅이 전부 한글이고 이모지가 섞일 수 있습니다. `utf8mb3`면 4바이트 문자에서 깨집니다 | `docker-compose.yml:13-14`<br>`docker-compose.prod.yml:86-87` |
| **DB**<br>(JDBC URL) | `serverTimezone` | **`Asia/Seoul`** | 컨테이너 기본 존이 UTC라 시각이 9시간 밀렸던 문제의 **3중 방어 중 하나**입니다(§7-3) | `application.yaml:12` |

## 3. 환경 변수 상세

> **시크릿 실제 값은 이 문서에 적지 않습니다.** 값을 찾는 경로는 두 갈래입니다.
>
> | 구분 | 어디에 있나 | 제출물 |
> |---|---|---|
> | **배포(운영) 값** | GitLab **Settings > CI/CD > Variables**. `.gitlab-ci.yml`이 배포 때마다 이 값으로 `MotionTok/Backend/.env`를 생성합니다 | 값은 제출하지 않고 **변수 키 목록만** — `exec/배포환경변수.md` |
> | **로컬 개발 값** | 팀 내부 `MotionTok/Backend/.env` · `MotionTok/Frontend/.env` (둘 다 `.gitignore`) | **제출물에 없습니다.** 새로 받는 경우 §4 STEP 2 절차로 직접 작성 |
>
> ⚠️ 아래 표의 **"로컬 값"** 열은 팀 내부 `.env` 기준 참고값이고, **"배포 값"** 열은 `.gitlab-ci.yml`과 `docker-compose.prod.yml`이 결정하는 값입니다.

### 3-1. 설정 주입 구조

- 스프링 프로파일을 **전혀 사용하지 않습니다**(`application-*.yaml` 없음, `@Profile` 0건).
- 환경 분리는 **환경변수 + compose 파일 분리**로 합니다.
- `application.yaml` 상단에서 `.env`를 properties로 import합니다.

```yaml
spring:
  config:
    import:
      - optional:file:.env[.properties]
      - optional:file:Backend/.env[.properties]
```

→ 즉 **워킹 디렉터리의 `.env`** 또는 **`Backend/.env`** 를 읽습니다. 둘 다 `optional`이라 없어도 기동은 시도합니다.
→ 운영에서는 CI가 `MotionTok/Backend/.env`를 생성하고 compose가 `env_file: .env`로 app 컨테이너에 주입합니다.

문법 규칙:

| 표기 | 의미 |
|---|---|
| `${VAR}` | 기본값 없음 = **필수**. 미설정 시 플레이스홀더 해석 실패 |
| `${VAR:기본값}` | 선택. 미설정 시 기본값 적용 |
| `${VAR:}` | 빈 문자열이 기본값. 미설정 시 해당 기능만 비활성(degrade) |

배포 환경변수는 **키만** 문서화하고 값은 GitLab **Settings > CI/CD > Variables** 에 둡니다(`exec/배포환경변수.md`). 그래서 제출물에는 대조할 `.env` 파일이 없고, 대신 **"코드가 요구하는 변수 집합"** 과 **"`.gitlab-ci.yml`이 `.env`에 써 넣는 변수 집합"** 을 양방향으로 맞춰 봤습니다.

| 구분 | 대조 대상 | 규모 |
|---|---|---|
| **요구 측** | `MotionTok/Backend/src/main/resources/application.yaml`의 `${...}` 플레이스홀더 전부 + `MotionTok/Backend/docker-compose.prod.yml`의 `${...}` | — |
| **등록 측** | `.gitlab-ci.yml` `deploy-backend`의 heredoc **9줄** + `add()` **39줄** = 48개, `deploy-frontend`의 `-e` **3개** | 51개 |

#### (A) 코드가 요구하는데 `.gitlab-ci.yml`이 등록을 시도하지 않는 변수

> ✅ **기동을 막는 누락은 없습니다.**
> `application.yaml`에서 **기본값이 없는**(= 미설정 시 `Could not resolve placeholder`로 기동 실패) 변수는 `DB_HOST`·`DB_PORT`·`DB_NAME`·`DB_USERNAME`·`DB_PASSWORD`·`JWT_SECRET`·`MAIL_HOST`·`MAIL_PORT`·`MAIL_USERNAME`·`MAIL_PASSWORD` **10개**인데, **10개 전부 CI가 등록을 시도**합니다. compose 전용인 `MYSQL_ROOT_PASSWORD`도 heredoc에 있습니다.
>
> 아래는 "CI에 등록 줄이 없어 `application.yaml` 기본값으로 굳는" 변수들이며, 🟢 표시는 **의도된 것**입니다.

| 변수 | 굳는 값(yaml 기본값) | 판정 | 영향 |
|---|---|---|---|
| **`TURN_SECRET`**<br>(+ `TURN_HOST`/`TURN_PORT`/`TURN_CREDENTIAL_TTL`) | (빈 값) | 🟠 **점검 필요** | 미설정이면 TURN 자격증명을 만들지 못해 **STUN-only로 degrade**합니다. 대칭 NAT 환경 사용자는 mesh 모드에서 연결이 안 될 수 있습니다. 릴레이가 필요하면 `add TURN_SECRET "$TURN_SECRET"` 줄을 CI에 추가해야 합니다(§7-8 #10) |
| `S3_ENDPOINT` / `S3_PATH_STYLE` | (빈 값) / `false` | 🟢 의도적 | **비어 있어야** 실제 AWS S3(virtual-hosted)로 붙습니다. 등록하면 오히려 깨집니다(§6-5) |
| `SWAGGER_ENABLED` | `false` | 🟢 의도적 | 운영에 API 문서를 열지 않기 위해 |
| `RTC_PROVIDER`<br>`OPENVIDU_URL`/`_API_KEY`/`_API_SECRET`/`_TOKEN_TTL` | `livekit`<br>로컬 dev 기본값 | 🟢 의도적 | LiveKit 고정. OpenVidu 경로는 미사용이라 등록 줄 자체가 없습니다 |
| `JPA_SHOW_SQL` | `false` | 🟢 무해 | 운영에서 SQL 로그를 켤 이유가 없음 |
| `JWT_GUEST_EXPIRATION_MS` | `1800000`(30분) | 🟢 무해 | `ACCESS`/`REFRESH` 두 개만 등록 줄이 있고 게스트는 기본값으로 충분 |
| `LIVEKIT_TOKEN_TTL` | `10m` | 🟢 무해 | |
| `S3_PRESIGN_TTL` | `3m` | 🟢 무해 | |
| `GMS_API_URL` | SSAFY 릴레이 URL | 🟢 무해 | 고정 주소라 등록 불필요 |
| `AI_ITEM_COST` / `AI_JOB_TIMEOUT_MINUTES` | `1500` / `5` | 🟢 무해 | 정책값. 바꿀 때만 등록하면 됨 |
| `LOGIN_FAIL_THRESHOLD`<br>`GUEST_PER_MINUTE` / `GUEST_PER_HOUR` | `5`<br>`10` / `100` | 🟢 무해 | 시연 등으로 한도를 올려야 하면 **CI에 `add` 줄을 새로 넣어야** 합니다(변수만 등록해서는 반영되지 않음) |
| `LOG_DIR` | `logs` | 🟢 무해 | `.env`가 아니라 `docker-compose.prod.yml`이 `LOG_DIR: /logs`로 직접 주입합니다(`:24`) |

> ⚠️ **`add()`는 값이 비면 줄 자체를 생략합니다.** 그래서 "GitLab Variables에 키는 등록했는데 값이 빈 문자열"이면 위 표와 **같은 상태**(= yaml 기본값)가 됩니다.
> 특히 **`MAIL_*` 4개는 yaml 기본값이 없어** 이 경우 기본값으로 떨어지는 게 아니라 **기동 자체가 실패**합니다(§6-3 · §6-5).

#### (B) `.gitlab-ci.yml`이 등록하는데 코드 어디에서도 안 쓰이는 변수

> ✅ **죽은 변수 없음.** heredoc 9개 + `add()` 39개 = **48개를 전부 역추적**한 결과, `application.yaml`에 없는 것은 `MYSQL_ROOT_PASSWORD` 하나뿐이고 그것도 compose가 실제로 씁니다. 나머지 47개는 모두 `application.yaml`의 플레이스홀더로 소비됩니다.

| 변수 | 실제 소비처 | 판정 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | Spring이 아니라 **`docker-compose.prod.yml:80`(mysql `environment`)와 healthcheck(`:104`)** | 🟢 정상 (compose 전용) |
| `DB_NAME` | `application.yaml:12`(JDBC URL) **+** `docker-compose.prod.yml:81`(`MYSQL_DATABASE`) 양쪽 | 🟢 정상 |
| `DB_USERNAME` / `DB_PASSWORD` | `application.yaml:13-14` **+** `docker-compose.prod.yml:82-83`(`MYSQL_USER`/`MYSQL_PASSWORD`) 양쪽 | 🟢 정상 |
| `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` | `application.yaml:141-142` **+** `docker-compose.prod.yml`의 `LIVEKIT_KEYS: "${LIVEKIT_API_KEY}: ${LIVEKIT_API_SECRET}"` 양쪽. **두 곳이 같은 값이어야 토큰 검증이 됩니다**(§6-3) | 🟢 정상 |
| 나머지 42개 | 전부 `application.yaml` 플레이스홀더 | 🟢 정상 |

**프론트엔드** — CI가 `-e`로 넘기는 값은 `VITE_API_BASE_URL`(CI에 `/api` 하드코딩) · `VITE_GOOGLE_CLIENT_ID` · `VITE_KAKAO_REST_KEY` **3개**이고, 코드가 읽는 `import.meta.env.VITE_*`도 정확히 이 3개입니다(`src/api/http.ts:22`, `src/features/auth/socialAuthorize.ts:20-21`). **누락도 잉여도 없습니다.**
단, `MotionTok/Frontend/src/api/env.d.ts`에 타입 선언만 있는 `VITE_WS_BASE`는 **실사용 0건**이라 등록할 필요가 없습니다(STOMP URL은 `API_BASE`에서 계산).

#### (C) 이름만 남아 있고 아무도 읽지 않는 변수 — `GOOGLE_REDIRECT_URI`

팀 내부 `MotionTok/Backend/.env`에는 `GOOGLE_REDIRECT_URI` 줄이 남아 있지만, **레포 어디에서도 읽히지 않습니다.** `application.yaml`·Java·`.gitlab-ci.yml` 어디에도 이 이름이 없고, 프론트가 redirect URI를 코드에서 **`window.location.origin + '/auth'`로 직접 만들어** 씁니다(`MotionTok/Frontend/src/features/auth/socialAuthorize.ts`). 즉 값도 틀렸고 쓰이지도 않는 **죽은 변수**이니 배포 변수로 옮기지 마세요.

> ✅ **OAuth 콘솔에 등록해야 하는 실제 redirect URI는 `{origin}/auth` 입니다.**
> - 로컬: `http://localhost:5173/auth`
> - 운영: `https://motok.co.kr/auth`
> `/oauth/google` 을 등록하면 소셜 로그인이 동작하지 않습니다. §6-7 참고.

### 5-2. 백엔드 — Docker 이미지

`MotionTok/Backend/Dockerfile`은 **멀티스테이지**입니다. 호스트에 JDK/Gradle이 없어도 빌드됩니다.

```bash
cd MotionTok/Backend
docker build -t motiontok-backend:latest .
```

| 스테이지 | 베이스 이미지 | 하는 일 |
|---|---|---|
| build | `eclipse-temurin:21-jdk` | 빌드 스크립트만 먼저 복사 → `./gradlew dependencies`(의존성 레이어 캐싱) → `src` 복사 → `./gradlew bootJar --no-daemon` |
| run | `eclipse-temurin:21-jdk` | jar를 `/app/app.jar`로 복사, `/logs/jfr` 생성, `EXPOSE 8080 9090` |

**런타임을 `21-jre`가 아니라 `21-jdk`로 둔 것은 의도적입니다** — JRE 이미지에는 `jcmd`/`jstack`/`jmap`이 없어 장애 시 스레드 덤프·JFR 스냅샷을 뜰 수 없습니다. build 스테이지와 같은 이미지라 레이어를 공유해 디스크 비용은 사실상 0입니다.

**ENTRYPOINT JVM 옵션**

```
java -XX:MaxRAMPercentage=60.0 \
     -XX:+HeapDumpOnOutOfMemoryError \
     -XX:HeapDumpPath=/logs/ \
     -XX:StartFlightRecording=name=beta,maxsize=2g,maxage=6h,settings=profile,dumponexit=true,filename=/logs/beta.jfr \
     -XX:FlightRecorderOptions=stackdepth=128,repository=/logs/jfr \
     -Dfile.encoding=UTF-8 \
     -jar /app/app.jar
```

| 옵션 | 이유 |
|---|---|
| `MaxRAMPercentage=60.0` | 기본 25%인데 compose에 `mem_limit`이 없던 시절 JVM이 호스트 전체를 보고 힙을 과하게 잡았음. 나머지 40%는 WebSocket 다이렉트 버퍼 몫 |
| `HeapDumpOnOutOfMemoryError` + `HeapDumpPath=/logs/` | OOM 사후 분석 |
| `StartFlightRecording` | 오버헤드 약 2%, 종료 시 자동 덤프 |
| `FlightRecorderOptions=stackdepth=128,repository=/logs/jfr` | 기본 stackdepth 64는 스프링 스택에서 잘림. repository를 호스트 볼륨에 두어 SIGKILL 시에도 청크가 남고 `jfr assemble /logs/jfr out.jfr`로 복구 가능 |
| `-Dfile.encoding=UTF-8` | 로그에 한글(닉네임·채팅)이 들어감 |

> `/logs/jfr` 디렉터리를 이미지에 **미리 생성**해 둡니다. JFR은 지정 경로가 없으면 JVM 자체가 기동하지 않습니다.

**`.dockerignore`** — `build/`, `.gradle/`, `.git/`, `.idea/`, `*.iml`, `docs/`, `.env`, `.env.*`
비밀값은 이미지에 굽지 않고 실행 시 compose `env_file`로 주입합니다.

### 6-3. `.env` 배치 (배포)

배포에서는 **CI가 `MotionTok/Backend/.env`를 자동 생성**합니다. 수동으로 만들 필요가 없습니다.

CI가 넣는 **운영 고정값**:
```
DB_HOST=mysql
DB_PORT=3306
REDIS_HOST=redis
REDIS_PORT=6379
```
+ CI Variables에서 오는 값 중 **heredoc에 무조건 쓰이는 5개**: `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `JWT_SECRET` (배포 필수는 이 5개가 전부가 아닙니다 — 아래 `add()` 예외와 §6-5 참고)

나머지 선택 변수는 `add()` 헬퍼로 처리됩니다:
```sh
add() { [ -n "$2" ] && echo "$1=$2" >> .env; return 0; }
```
→ **CI 변수가 비어 있으면 줄 자체를 넣지 않습니다.** 빈 문자열을 넣으면 Spring이 `application.yaml`의 기본값 대신 빈 값을 써서 기동에 실패하기 때문입니다.

> ⚠️ **`MAIL_*` 4개는 예외입니다.** `MAIL_HOST`/`MAIL_PORT`/`MAIL_USERNAME`/`MAIL_PASSWORD`는 `application.yaml`에 기본값이 없어(`${MAIL_HOST}` 형태), `add()`가 줄을 생략하면 `Could not resolve placeholder`로 **기동 자체가 실패**합니다. 이 4개는 반드시 GitLab Variables에 값을 넣어야 합니다.

이 `.env`는 세 곳이 함께 읽습니다.
1. Spring (`spring.config.import`)
2. `app` 컨테이너 (`env_file: .env`)
3. `livekit` 컨테이너 (`LIVEKIT_KEYS: "${LIVEKIT_API_KEY}: ${LIVEKIT_API_SECRET}"`) — **Spring과 LiveKit이 같은 키를 공유해야 토큰 검증이 됩니다.**

### 6-4. 배포 기동 명령


**기동되는 서비스**

| 서비스 | 컨테이너명 | 이미지 | 호스트 포트 | mem_limit |
|---|---|---|---|---|
| app | `motiontok-app` | `motiontok-backend:latest` (로컬 빌드) | `127.0.0.1:9090` / 8080은 `expose`만 | 6g |
| mysql | `motiontok-mysql` | `mysql:8.4` | 없음 | 3g |
| redis | `motiontok-redis` | `redis:7.4-alpine` | 없음 | 1g |
| livekit | `motiontok-livekit` | `livekit/livekit-server:v1.13.4` | 7881/tcp, 50000-50100/udp | **의도적으로 없음** |
| nginx | `motiontok-nginx` | `nginx:1.27-alpine` | 80, 443 | **의도적으로 없음** |
| certbot | `motiontok-certbot` | `certbot/certbot` | 없음 | — |
| node-exporter | `motiontok-node-exporter` | `prom/node-exporter:v1.8.2` | `127.0.0.1:9100` (`network_mode: host`) | 128m |

> **livekit·nginx에 `mem_limit`을 두지 않은 것은 의도적입니다.** livekit은 2000명 규모 실측이 없어 추측으로 조이면 영상만 통째로 끊기고, nginx는 유일한 입구라 OOM으로 죽으면 사이트 전체가 내려갑니다.

**운영 compose에만 있는 튜닝** (로컬과 다른 점)

| 서비스 | 항목 | 값 | 이유 |
|---|---|---|---|
| app | `ulimits.nofile` | 65535 / 65535 | 컨테이너 기본 soft 1024에서는 약 950 WebSocket 연결부터 "Too many open files" |
| app | `stop_grace_period` | 60s | JFR dumponexit 여유 |
| app | logging | json-file 100m × 3, `mode: non-blocking`, buffer 4m | |
| app | healthcheck | `curl -fsS http://localhost:9090/actuator/health/liveness` (30s/5s/5회/start 90s) | **종합 health가 아니라 liveness** — SMTP가 막혀도 재시작되면 안 됨 |
| mysql | command 추가 | `--innodb-buffer-pool-size=1G --slow-query-log=1 --slow-query-log-file=/var/lib/mysql/slow.log --long-query-time=0.5` | |
| redis | command 추가 | `--maxmemory 512mb --maxmemory-policy noeviction` | **캐시가 아니라 저장소라 LRU 계열 금지** |
| redis | `mem_limit` | 1g (maxmemory의 2배) | AOF rewrite fork의 copy-on-write 여유 |
| livekit | 설정 파일 | `livekit.prod.yaml` (`use_external_ip: true`, 포트 범위 50000-50100) | EC2는 자기 공인 IP를 모르는 NAT 구조 |
| nginx | logging | json-file **10m** × 3 | 다른 서비스(100m)보다 작게 |

### 6-7. OAuth 콘솔 설정

> ⚠️ redirect URI는 프론트가 코드에서 `window.location.origin + '/auth'`로 만듭니다. 팀 내부 `.env`에 남아 있는 `GOOGLE_REDIRECT_URI`(`/oauth/google`)는 **아무도 읽지 않는 죽은 값**이니 그대로 등록하지 마세요(§3-6 (C)).

**Google Cloud Console**
1. OAuth 2.0 클라이언트 ID(웹 애플리케이션) 생성 → client ID / client secret 발급
2. **승인된 리디렉션 URI**에 등록:
   - `http://localhost:5173/auth` (로컬)
   - `https://motok.co.kr/auth` (운영)
3. 발급값 → 백엔드 `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, 프론트 `VITE_GOOGLE_CLIENT_ID`
4. 요청 scope는 코드에 `openid email profile` 하드코딩

**Kakao Developers**
1. 앱 생성 → **REST API 키** 발급 (= `KAKAO_CLIENT_ID` = `VITE_KAKAO_REST_KEY`)
2. 카카오 로그인 활성화 → **Redirect URI**에 위와 동일한 두 주소 등록
3. **동의항목**: 코드가 `kakao_account.email`(+`is_email_verified`/`is_email_valid`)과 `profile.nickname`을 읽으므로 **카카오계정(이메일)·프로필 정보(닉네임)** 동의항목을 켜야 합니다
4. client secret은 콘솔에서 "사용 설정"한 경우에만 `KAKAO_CLIENT_SECRET`에 등록

> **네이버 로그인은 미구현**입니다. 백엔드 `OauthProvider` enum은 `GOOGLE`, `KAKAO` 둘뿐이며 그 외는 400(`UNSUPPORTED_OAUTH_PROVIDER`)을 반환합니다.

### 6-9. nginx 설정

파일은 3개뿐이며 compose가 read-only로 마운트합니다.

| 파일 | 마운트 위치 | 역할 |
|---|---|---|
| `MotionTok/Backend/nginx/nginx.conf` | `/etc/nginx/nginx.conf` | main 컨텍스트 (`worker_processes auto`, `worker_rlimit_nofile 65535`, `events { worker_connections 16384; }`) |
| `MotionTok/Backend/nginx/conf.d/motok.conf` | `/etc/nginx/conf.d/motok.conf` | server 블록 (80/443), 프록시·캐시·보안헤더 |
| `MotionTok/Backend/nginx/conf.d/gzip.conf` | `/etc/nginx/conf.d/gzip.conf` | 압축 설정 |

**주요 location**

| location | 동작 |
|---|---|
| `/` | `try_files $uri $uri/ /index.html` — **SPA 폴백** (`root /usr/share/nginx/html`) |
| `/api/` | `proxy_pass http://backend` (`upstream backend { server app:8080; keepalive 128; keepalive_requests 10000; keepalive_timeout 30s; }`), `proxy_read_timeout 60s` |
| `= /api/games/draw/judge` | 정확일치라 `/api/` 설정을 상속하지 않아 헤더·타임아웃 재선언 (AI 채점 60s) |
| `/ws` | **STOMP WebSocket** — `Upgrade`/`Connection: upgrade`, `proxy_read_timeout 3600s` |
| `/livekit/` | `rewrite ^/livekit/(.*)$ /$1 break` → `proxy_pass http://livekit:7880`, Upgrade 헤더, `proxy_read_timeout 3600s` |
| `/assets/` | `expires 1y; Cache-Control "public, immutable"` (Vite 해시 파일명) |
| `/mediapipe/` | `expires 30d` — **`immutable` 금지.** 파일명이 고정이라 같은 이름으로 교체되며, 낡은 wasm + 새 JS 래퍼가 섞이면 게임이 아예 안 뜸 |
| `/fonts/` | `expires 1y; immutable` — 폰트 교체 시 **파일명 자체를 변경**해야 함 (`DNFBitBitv2`) |
| `= /index.html` | `Cache-Control "no-cache"` |
| `= /rum` | 앱을 거치지 않고 nginx가 로그만 기록. `limit_req zone=rum burst=10 nodelay`(12r/m), `empty_gif` |
| `= /nginx_status` | `stub_status`, `127.0.0.1`·`172.16.0.0/12`만 허용 |
| `/swagger-ui/`, `/v3/api-docs` | 프록시는 있으나 `SWAGGER_ENABLED:false`라 운영에서는 열리지 않음 |

**보안 헤더 (CSP)**
```
default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline';
font-src 'self' data:; img-src 'self' data: blob: https://*.amazonaws.com; media-src 'self' blob:;
worker-src 'self' blob:; connect-src 'self' blob: https://*.amazonaws.com;
frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'
```

| 지시자 | 빼면 안 되는 이유 |
|---|---|
| `script-src 'wasm-unsafe-eval'` | **MediaPipe wasm 컴파일 필수. 없으면 게임이 통째로 안 뜸** |
| `style-src 'unsafe-inline'` | Vue `:style` 바인딩 필수 |
| `img-src`/`connect-src` `https://*.amazonaws.com` | S3 아바타·AI 아이템 |

그 외 `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.

**로그 마스킹** — `map $request $request_masked`로 LiveKit이 쿼리스트링에 싣는 `?access_token=<JWT>`를 `access_token=***`로 치환합니다. **`access_log`는 반드시 server 레벨에만** 걸어야 합니다(http 레벨에 걸면 마스킹 안 된 기본 줄이 병기되어 토큰이 유출됩니다).

**gzip** — `gzip on; gzip_comp_level 5; gzip_min_length 1024;`
대상: `text/plain text/css text/xml text/javascript application/javascript application/json application/xml image/svg+xml`
**wasm·woff2·png·jpg·webp는 의도적 제외** (10.6MB wasm 실시간 압축은 버스터블 인스턴스의 CPU 크레딧을 소모).

### 6-10. CI/CD 파이프라인

`.gitlab-ci.yml` — `stages: [deploy]` **단일 stage** (빌드/테스트 stage 없음).

전역 변수:
```yaml
variables:
  GIT_CLEAN_FLAGS: -ffd
```
기본 `-ffdx`의 `x`(무시된 파일까지 삭제)가 docker(root)가 만든 산출물을 gitlab-runner 권한으로 지우려다 `Permission denied`로 실패하던 문제 때문입니다.

| job | 트리거 | 하는 일 |
|---|---|---|
| `deploy-backend` | `main` 브랜치 AND `MotionTok/Backend/**/*` 또는 `.gitlab-ci.yml` 변경 | ① CI Variables → `.env` 생성 ② `docker compose -f docker-compose.prod.yml up -d --build` ③ `docker exec motiontok-nginx nginx -s reload \|\| true` ④ `docker image prune -f` |
| `deploy-frontend` | `main` 브랜치 AND `MotionTok/Frontend/**/*` 또는 `.gitlab-ci.yml` 변경 | ① `docker run --rm node:22-alpine`에서 `pnpm install --frozen-lockfile && pnpm build` ② `mkdir -p /srv/motok/frontend` ③ `cp -r dist/. /srv/motok/frontend/` ④ `find /srv/motok/frontend/assets -type f -mtime +7 -delete` |

**프론트 배포에서 `rm -rf` 하지 않고 덮어쓰는 이유**
Vite 청크는 배포마다 해시 파일명이 바뀝니다. 통째로 지우면 배포 전부터 열려 있던 탭이 아는 청크가 서버에서 사라지고, 그 탭은 지연 로딩되는 화면(상점·게임)에 들어가는 순간 404가 납니다. 화면에는 아무 일도 일어나지 않고 콘솔에만 남아 "게임 시작을 눌렀는데 카메라만 보인다"로 나타납니다. `cp`가 이번 배포 파일의 mtime을 갱신하므로 **7일 넘게 어느 배포에도 없던 파일만** 정리됩니다.

**nginx 재시작이 필요 없는 이유** — `/srv/motok/frontend`가 bind mount라 파일 교체가 즉시 반영됩니다.

**CI가 `nginx -s reload`를 하는 이유** — 컨테이너가 재생성되면 IP가 바뀌는데, nginx는 기동 시 upstream 호스트명을 해석해 캐시하므로 reload로 다시 해석시켜야 합니다.

### 7-1. 🔴 SSAFY 개발망에서 SMTP(587/465) 차단 → 메일 발송 불가

**증상**
SSAFY 교육망/개발망에서 아웃바운드 SMTP 포트(587, 465)가 막혀 있어 Gmail SMTP 접속이 되지 않습니다. 회원가입 인증번호·비밀번호 재설정 메일이 발송되지 않고, SMTP 연결이 타임아웃(5초)까지 매달립니다.

**우회 — `MAIL_HOST`를 빈 값으로 두면 로그 폴백이 동작합니다 (코드에 실제로 구현되어 있음)**

`MotionTok/Backend/src/main/java/ssafy/a706/backend/auth/email/VerificationMailSender.java`
```java
JavaMailSender sender = mailSenderProvider.getIfAvailable();
// host가 비어 있으면 빈이 있어도 실제 발송은 불가능하므로 로그로 대체한다.
if (sender == null || mailHost == null || mailHost.isBlank()) {
    log.warn("[메일 미설정] {} 인증번호 = {} (SMTP 미설정이라 실제 발송하지 않음)", email, code);
    return;
}
```
`PasswordResetMailSender.java`도 동일 패턴으로 `"[메일 미설정] {} 비밀번호 재설정 링크 = {}"` 를 남깁니다.

**적용 방법 (⚠️ `.env`를 직접 쓰는 로컬 전용 우회입니다)** — `MotionTok/Backend/.env`에서 `MAIL_HOST` 값만 비웁니다.

> 배포에는 쓸 수 없습니다. CI가 `.env`를 매번 새로 생성하고 `add()`가 빈 값을 걸러내므로, GitLab Variables의 `MAIL_HOST`를 비우면 "빈 값 선언"이 아니라 **줄 자체가 없는 미설정**이 됩니다. `application.yaml`에 기본값이 없어 그대로 기동 실패입니다(§6-3).
```properties
MAIL_HOST=
MAIL_PORT=587
MAIL_USERNAME=
MAIL_PASSWORD=
```

> ⚠️ **변수를 통째로 지우지 마세요.** `application.yaml`의 `${MAIL_HOST}`에는 기본값이 없어 **`Could not resolve placeholder`로 기동에 실패합니다.** 코드는 `@Value("${spring.mail.host:}")`로 **빈 값**을 전제로 폴백하므로 "빈 값 선언"이 정답입니다.
> `TODO(확인필요): MAIL_HOST 변수를 완전히 제거했을 때 앱이 기동 실패하는지 — 실행 검증 미수행(정적 분석으로 기본값 부재만 확인)`

**동작 방식** — 인증번호/재설정 링크가 **애플리케이션 로그에 그대로 출력**되므로, 메일함 대신 콘솔을 보고 가입·비밀번호 재설정 흐름을 끝까지 테스트할 수 있습니다.

**함께 확인할 것** — `MAIL_HEALTH_ENABLED`는 반드시 `false`(기본값)로 두세요. 켜면 종합 `/actuator/health`가 SMTP에 실제 접속하여, 막힌 망에서는 **503 + 호출마다 5초 지연**이 발생하고 DB·Redis의 정상 여부를 가립니다. (컨테이너 healthcheck는 `liveness`를 보므로 재시작에는 영향이 없습니다.)

### 7-2. 🔴 SSAFY 개발망에서 Docker Hub CDN 차단 → 이미지 pull 실패

**증상**
`docker compose up -d` 또는 `docker pull` 시 Docker Hub의 CDN(레이어 저장소) 접근이 차단되어 이미지 다운로드가 멈추거나 실패합니다. 매니페스트는 받아지는데 레이어 다운로드에서 timeout/EOF가 나는 형태가 많습니다.

**우회 — Google의 Docker Hub 미러(`mirror.gcr.io`)에서 pull 한 뒤 원래 이름으로 retag**

```bash
docker pull mirror.gcr.io/library/node:22-alpine

# 2) compose/Dockerfile이 기대하는 원래 이름으로 태그를 붙인다

docker tag mirror.gcr.io/library/redis:7.4-alpine  redis:7.4-alpine
docker tag mirror.gcr.io/library/nginx:1.27-alpine nginx:1.27-alpine
docker tag mirror.gcr.io/library/node:22-alpine    node:22-alpine
```

### 7-3. 🔴 컨테이너 타임존이 UTC라 시각이 9시간 밀리던 문제

**증상**
포인트 내역·신고 일시 등 화면의 모든 시각이 **9시간 전으로** 표시되었습니다.

**원인**
저장되는 시각은 전부 `LocalDateTime.now()`(= JVM 기본 존)인데, 배포 컨테이너의 베이스 이미지(`eclipse-temurin`)의 기본 타임존이 **UTC**입니다. 로컬(KST)에서 쓴 값과 서버에서 쓴 값이 9시간 어긋난 채 같은 컬럼에 섞였습니다.

**해결 — 앱 레벨에서 `Asia/Seoul` 고정 (3중 방어)**

| # | 위치 | 설정 |
|---|---|---|
| 1 | **`MotionTok/Backend/src/main/java/ssafy/a706/backend/BackendApplication.java`** | `@PostConstruct void fixDefaultTimeZone() { TimeZone.setDefault(TimeZone.getTimeZone("Asia/Seoul")); }` |
| 2 | `MotionTok/Backend/src/main/resources/application.yaml` (datasource URL) | JDBC URL에 `serverTimezone=Asia/Seoul` |
| 3 | `docker-compose.prod.yml` (운영) | app·mysql·redis·nginx 전부 `TZ: Asia/Seoul`. alpine 이미지(redis·nginx)는 tzdata가 없어 `/etc/localtime:/etc/localtime:ro` 호스트 바인드 병행 (livekit·certbot·node-exporter에는 없음) |
| 3' | `docker-compose.yml` (로컬) | **`TZ: Asia/Seoul`은 mysql 하나뿐**입니다. app·nginx 서비스 자체가 없고(백엔드는 IDE에서 직접 실행), redis에는 `TZ`도 `/etc/localtime` 바인드도 없습니다. 로컬 JVM은 이미 KST라 1번 방어로 충분합니다 |

**compose의 `TZ`에만 맡기지 않는 이유** — 그 설정을 빠뜨린 채 뜬 인스턴스가 조용히 UTC로 기록해도 어디에서도 드러나지 않습니다. 앱에서 고정하면 어디서 돌든 동일합니다.

> ⚠️ **이 수정 이전에 저장된 행은 여전히 UTC 기준**입니다. 과거 데이터의 시각은 9시간 어긋난 채 남아 있습니다.

| 서비스 | 의존 | 조건 |
|---|---|---|
| `app` | `mysql` | **`service_healthy`** (healthcheck 통과까지 대기) |
| `app` | `redis` | `service_started` |

| `minio-init` (로컬) | `minio` | `service_healthy` |

컨테이너가 재생성되면 IP가 바뀌므로 배포 후 `docker exec motiontok-nginx nginx -s reload`가 필요합니다(CI가 자동 수행).

### 7-6. DB 스키마 관리 방식 — 마이그레이션 툴 없음

| 항목 | 사실 |
|---|---|
| 방식 | **JPA `spring.jpa.hibernate.ddl-auto: update`** (하드코딩, 환경변수 오버라이드 불가) |
| Flyway / Liquibase | **미사용** |
| `schema.sql` / `data.sql` | **없음** (`sub1/` 아래 파일들은 개인 관통 과제로 MotionTok과 무관) |
| DB 생성 | compose의 `MYSQL_DATABASE=${DB_NAME}`이 빈 스키마를 만들고, 테이블은 Hibernate가 기동 시 생성 |
| 예외: 수동 DDL 러너 | `MotionTok/Backend/src/main/java/ssafy/a706/backend/game/LeaderboardSchemaMigration.java` — `ApplicationRunner`가 `JdbcTemplate`로 `leaderboards` 테이블의 옛 유니크 인덱스 제거 + `best_achieved_at` 컬럼 추가/백필/NOT NULL 전환을 **멱등하게** 수행. `ddl-auto`가 행이 있는 테이블에 NOT NULL 컬럼을 넣지 못하기 때문 |
| 마스터 데이터 시딩 | SQL이 아니라 **코드 시더**(모두 멱등, 기동 시 자동 실행) — `GameCatalogSeeder`(게임 4행: id 1·4·10·11), `RhythmGameSeeder`(게임 1행: id 2), `ShopItemSeeder`(아이템 8행) |

> ⚠️ `ddl-auto: update`는 컬럼 **추가**만 하고 삭제·타입 변경은 하지 않습니다. 엔티티에서 필드를 지워도 DB 컬럼은 남습니다.

### 7-8. 알려진 이슈 / 주의사항

| # | 항목 | 내용 |
|---|---|---|
| 1 | **nginx gzip 중복 선언** | `nginx.conf`에 gzip 지시자를 넣으면 `conf.d/gzip.conf`와 중복되어 `[emerg] "gzip" directive is duplicate`로 **기동 자체가 거부**됩니다. 설정 검증은 반드시 `nginx.conf` + `conf.d`를 함께 마운트한 상태로 하세요 |

| 3 | **keepalive 타임아웃 순서** | nginx upstream `keepalive_timeout 30s` < 톰캣 `keep-alive-timeout 120s`. **백엔드가 먼저 끊으면 간헐 502**가 발생합니다. 항상 nginx가 먼저 닫도록 순서를 고정한 것이니 한쪽만 바꾸지 마세요 |

| 5 | **폰트 교체 시 파일명 변경 필수** | `/fonts/`는 `expires 1y; immutable`이고 빌드 해시가 없습니다. 폰트를 바꾸면 파일명(`DNFBitBitv2`) 자체를 변경해야 합니다 |
| 6 | **`VITE_*`는 빌드 시점에 박힘** | GitLab Variables에 등록만 하고 CI에서 `-e`로 넘기지 않으면 번들에 반영되지 않습니다 |

### 8-3. ERD와 실제 스키마 (참고)

실제 테이블은 **18개**입니다 (`@Entity` 18개 = 덤프 `CREATE TABLE` 18개, 1:1 일치).

| charset | `utf8mb4` / `utf8mb4_unicode_ci`, 전 테이블 `ENGINE=InnoDB` |

> ✅ 이 덤프에는 계정·플레이 데이터가 없고 `games`·`item` 마스터 시드만 들어 있어 **개인정보가 포함되지 않습니다.** (이메일 0건, `password_hash` 0건, 소셜 `provider_uid` 0건)

**덤프 생성 경위** — 뜨기 직전에 **최신 소스로 jar를 빌드해 앱을 1회 부팅**(`ddl-auto: update`)시켜 스키마를 최신으로 맞춘 뒤 덤프했습니다. 그 부팅으로 로컬 DB에 없던 `leaderboard_weekly`·`chart_leaderboard` 두 테이블이 생성되어 **18개**가 채워졌고, 같은 부팅에서 `ShopItemSeeder`가 아이템 시드를 **6종 → 8종**으로 늘린 결과도 덤프에 함께 들어가 있습니다.

### 9-2. 복원 (새 환경)

**전제**: MySQL 컨테이너가 기동되어 있어야 합니다 (§4 STEP 3).

덤프에 `CREATE DATABASE IF NOT EXISTS`가 들어 있으므로 **빈 MySQL에 그대로 부으면 스키마까지 만들어집니다.**

**Windows (PowerShell) — 권장: 컨테이너 안으로 복사 후 실행 (인코딩 안전)**
```powershell
docker cp C:\Users\SSAFY\IdeaProjects\S15P11A706\exec\motiontok_dump.sql motiontok-mysql:/tmp/dump.sql
docker exec motiontok-mysql sh -c "mysql -uroot -proot --default-character-set=utf8mb4 < /tmp/dump.sql"
docker exec motiontok-mysql rm -f /tmp/dump.sql
```

**Linux / macOS / Git Bash**
```bash
docker exec -i motiontok-mysql mysql -uroot -proot --default-character-set=utf8mb4 < exec/motiontok_dump.sql
```

> - `-uroot -proot`은 로컬 compose 기본값(`MYSQL_ROOT_PASSWORD:-root`)입니다. `.env`에 `MYSQL_ROOT_PASSWORD`를 넣었다면 그 값으로 바꾸세요.
> - 앱 계정(`ssafy`)으로도 복원 가능하지만, `CREATE DATABASE` 권한이 필요하므로 **root 권장**입니다.
> - **PowerShell 5.1에서 `<` 리다이렉션은 인코딩(UTF-16/BOM)을 섞어 한글을 깨뜨릴 수 있습니다.** 위 "복사 후 실행" 방식을 쓰세요.

**✅ 검증**
```bash
docker exec motiontok-mysql mysql -uroot -proot -e "USE motiontok; SHOW TABLES; SELECT COUNT(*) AS games FROM games; SELECT COUNT(*) AS item FROM item;"
```
→ 테이블 18개, `games` 5행, `item` 8행이 보이면 복원 성공. (`users` 등 나머지 16개 테이블은 행이 0인 것이 정상입니다.)

> 복원 후 백엔드를 기동하면 `ddl-auto: update`가 스키마 차이를 보정하고, 코드 시더(`GameCatalogSeeder`·`RhythmGameSeeder`·`ShopItemSeeder`)가 **멱등하게** 동작하므로 중복 행이 생기지 않습니다.

### 9-3. 덤프 생성 (재생성이 필요할 때)

> ⚠️ **아래 `--databases motiontok` 명령은 전체 데이터를 덤프합니다.** 개발 중 만들어진 계정 데이터(이메일·`password_hash`·소셜 `provider_uid`·아바타 URL)가 그대로 들어가므로, **재생성한 파일을 그대로 제출물에 커밋하면 개인정보가 다시 포함됩니다.** 제출본과 동일하게 마스터 데이터만 담으려면 아래 "마스터 데이터만 뽑기"를 쓰세요.

**권장 — 컨테이너 안에서 파일 생성 후 복사 (인코딩 안전, PowerShell·Git Bash 공통)**
```powershell
docker exec motiontok-mysql sh -c "mysqldump -ussafy -pssafy --databases motiontok --single-transaction --routines --triggers --events --hex-blob --default-character-set=utf8mb4 --result-file=/tmp/motiontok_dump.sql"
docker cp motiontok-mysql:/tmp/motiontok_dump.sql C:\Users\SSAFY\IdeaProjects\S15P11A706\exec\motiontok_dump.sql
docker exec motiontok-mysql rm -f /tmp/motiontok_dump.sql
```

**Git Bash 한 줄 변형**
```bash
docker exec motiontok-mysql mysqldump -ussafy -pssafy --databases motiontok \
  --single-transaction --routines --triggers --events --hex-blob --default-character-set=utf8mb4 \
  > exec/motiontok_dump.sql
```

**마스터 데이터만 뽑기 (제출본 `exec/motiontok_dump.sql`을 만든 방식 — 개인정보 제외)** — 스키마(전 테이블)와 데이터(`games`·`item`만)를 따로 뜬 뒤 이어 붙입니다.
```bash
docker exec motiontok-mysql sh -c "mysqldump -ussafy -pssafy --no-data --databases motiontok --single-transaction --routines --triggers --events --default-character-set=utf8mb4 > /tmp/schema.sql"
docker exec motiontok-mysql sh -c "mysqldump -ussafy -pssafy --no-create-info motiontok games item --single-transaction --hex-blob --default-character-set=utf8mb4 > /tmp/data.sql"
docker exec motiontok-mysql sh -c "cat /tmp/schema.sql /tmp/data.sql > /tmp/motiontok_dump.sql"
docker cp motiontok-mysql:/tmp/motiontok_dump.sql C:\Users\SSAFY\IdeaProjects\S15P11A706\exec\motiontok_dump.sql
docker exec motiontok-mysql sh -c "rm -f /tmp/schema.sql /tmp/data.sql /tmp/motiontok_dump.sql"
```

**옵션 근거**

| 옵션 | 이유 |
|---|---|
| `--databases motiontok` | `CREATE DATABASE IF NOT EXISTS` + `USE`를 넣어 빈 DB에 그대로 복원 가능. 이미 만들어진 스키마 안에만 넣으려면 이 옵션을 빼고 `motiontok`만 씁니다 |
| `--single-transaction` | 전 테이블 InnoDB라 락 없이 일관 스냅샷 |
| `--routines --triggers --events` | 현재 0건이지만 넣어도 무해 (`--triggers`는 기본 ON, 문서 명확성을 위해 명시) |
| `--hex-blob` | `ai_item_job.sketch_base64`(LONGTEXT)·`bit(1)` 컬럼 안전 |
| `--default-character-set=utf8mb4` | 게임명·규칙문·아이템명이 전부 한글이라 필수 |
| ⚠️ `--column-statistics=0` | **넣지 마세요.** 클라이언트·서버가 둘 다 컨테이너 안 8.4라 불필요하고, 버전에 따라 unknown option으로 실패합니다 |

**운영 EC2에서 뜰 경우** — 컨테이너명은 동일(`motiontok-mysql`)하지만 **계정·비밀번호·DB명이 서버 `.env` 값**이므로 `-u`/`-p`/DB명을 그 값으로 바꿔야 합니다.
