# 랭킹 주간 탭 — 프론트 인계 노트

백엔드 작업 완료분과, 그에 맞춰 프론트에서 처리해야 할 것들. API 상세는
[모톡_API_명세서.html](모톡_API_명세서.html) v0.2.38 → `GET /games/{gameId}/leaderboard` 참고.

## 백엔드가 바뀐 것

### 1. 동점 처리 — 공동 순위가 사라졌다

정렬이 `점수 DESC, 달성 시각 ASC, userId ASC`인 **전순서**가 됐다. 게임이니까 1·2·3등은 무조건
갈린다는 결정에 따른 것이고, 같은 점수면 **먼저 달성한 사람이 위**다.

전에는 Redis ZSET이 정렬을 맡았는데, 점수 하나로는 "같은 점수면 먼저 달성한 사람" 같은 2차 기준을
표현할 수 없었다. 그래서 순위 권위를 MySQL로 옮기고 ZSET을 걷어냈다.

내 순위(`myRank`)도 같은 규칙으로 센다 — "나보다 앞선 사람 수 + 1". 전에는 목록 안이면 재순번,
밖이면 ZREVRANK 원시 순위라 정의가 달랐다. 이제 하나다.

### 1-1. 협동 게임에는 역대 탭이 없다

`games.mode = 'COOP'`인 게임(그림으로 말해요)은 **ALLTIME 순위표를 내주지 않는다**(200 + 빈
`entries`). 협동은 전원이 같은 점수를 받고([coopResults](../Backend/src/main/java/ssafy/a706/backend/game/GameSessionService.java)),
그 점수도 AI 추측 순위에 따른 여섯 값(100·80·60·40·20·0)뿐이라
([DrawJudge](../Backend/src/main/java/ssafy/a706/backend/game/draw/DrawJudge.java)) 역대
최고점이 곧 전부 100점으로 수렴한다. 1위는 "100점을 제일 먼저 겪은 사람"으로 영구히 굳고, 그마저
개인 실력이 아니라 그날 팀의 결과다.

**주간은 그대로 있다.** 합계는 판마다 쌓여 값이 흩어지고 매주 리셋되므로 협동에서도 성립한다.

화면은 COOP 게임을 고르면 역대 탭을 아예 감춘다(모드 토글에서 SOLO를 감추는 것과 같은 방식).

### 2. 기간 파라미터 추가

```
GET /games/{gameId}/leaderboard?mode=MULTI&period=ALLTIME|WEEKLY&week=2026-08-05&limit=20
```

- `period` 기본 `ALLTIME` — **기존 호출은 아무것도 안 바꿔도 그대로 동작한다.**
- `WEEKLY`는 그 주에 얻은 점수의 **합**. 매주 초기화된다.
- `week`는 보고 싶은 주의 **아무 날짜나** 주면 서버가 KST 월요일로 스냅한다. 주 경계를 프론트에서
  계산하지 마라 — 규칙은 서버 한 곳에만 있어야 한다. 생략하면 이번 주.

### 3. 응답 필드 추가 (전부 추가만, 삭제·변경 없음)

| 필드 | 위치 | 설명 |
|---|---|---|
| `period` | Response | `ALLTIME` \| `WEEKLY` |
| `weekStart` | Response | WEEKLY일 때 **실제 집계한 주**의 월요일. `"8/3~8/9"` 라벨용. ALLTIME이면 null |
| `achievedAt` | Entry | 그 점수를 찍은 시각 — **동점을 가르는 기준** |
| `avatarUrl` | Entry | 원래부터 내려가고 있었는데 명세에만 빠져 있었다. 문서만 보정 |

## 프론트에서 해야 할 것

### A. 탭 UI

`RankingView.vue`의 `{{ selectedGame }} 전체 순위` 헤더 아래에 기간 탭(전체 기록 / 주간)을 붙이면
된다는 요청. 기존 `mode-switch`(멀티/혼자)와 같은 축이 하나 더 생기는 형태다.

**기본 탭은 주간을 권한다.** 전체기간 최고점은 "먼저 달성한 사람이 위"라서, 점수 상한이 있는
게임은 상위권이 한 번 정해지면 아무도 못 끌어내린다. 그게 버그가 아니라 그 랭킹의 성격(명예의
전당)이고, 그래서 매주 새로 겨루는 주간 랭킹을 짝으로 만든 것이다.

### B. 닉네임 검색 팬아웃 — 기간 축은 훑지 말 것

`bestRankElsewhere()`가 지금 `게임 × 모드`를 전부 `Promise.all`로 훑는다(게임 5개 × 모드 2 =
10요청). 기간까지 넣으면 20요청이 된다.

**검색은 지금 보고 있는 기간 안에서만 하는 걸 권한다.** 요청 수도 요청 수지만, "주간엔 없어서
전체 탭으로 저절로 넘어감"은 사용자가 누르지 않은 탭이 혼자 바뀌는 동작이라 이상하다.

### C. `focusHit()`의 주석이 무효가 됐다

```js
// 동점자 처리에 따라 rank는 건너뛸 수 있어 페이지 계산이 어긋난다
page.value = Math.floor(board.value.entries.indexOf(hit) / PAGE_SIZE) + 1
```

전순서라 rank는 절대 건너뛰지 않는다 — `rank === indexOf + 1`이 항상 성립한다. 지금 코드도 맞게
동작하니 급하진 않지만, 주석이 사실과 달라졌다.

### D. 포디움 문구

`<b>이번 주의 챔피언</b>`인데 지금은 전체기간 기록을 그리고 있다. 주간 탭이 생기면 그 문구가
진짜로 맞는 탭이 하나 생긴다 — 탭에 따라 문구를 바꾸든지, 지금 문구를 고치든지.

### E. `MOCK_BOARD` 폴백을 주간 탭에도 쓸지

주간은 **"이번 주 아직 아무도 안 함"이 정상 상태**다. 전체기간 순위표는 텅 비면 어색하니 예시를
띄우는 게 말이 됐지만, 주간에 가짜 기록이 뜨면 곤란하다. 주간 탭은 폴백 없이 빈 상태
("이번 주 첫 기록의 주인공이 되어 보세요")로 두는 걸 권한다.

### F. `bestScore` 이름 — 같이 바꾸자

WEEKLY에서 이 필드는 최고점이 아니라 **합계**다. `score`로 바꾸는 게 맞는데, 지금 백엔드만 바꾸면
배포된 랭킹 화면이 깨지므로 손대지 않았다.

탭 작업을 하면서 프론트를 같이 고칠 수 있을 때 알려 주면 그때 백엔드도 같이 rename한다. 전환기용
중복 필드는 두지 말자 — 그런 필드는 안 지워진다.

## 참고 — 이번 스코프에서 뺀 것

**모톡 전체 랭킹(게임 무관)은 만들지 않았다.** 축이 될 만한 값은 `pointsEarned`인데, 지금
`PointCalculator`가 `scoreBonus = score / 10`으로 **점수 0~100을 전제**하고 있다. 핑거 스타는
`completedCount × 100`(최대 2000)이라 900점대면 8인 1등도 꼴찌도 똑같이 상한 100을 받는다. 낚시도
같은 문제다. 이 상태로 전체 랭킹을 만들면 "핑거 스타 판수 = 전체 순위"가 된다.

포인트 공식은 S15P11A706-83 소유라 여기서 건드리지 않았다. 별도 이슈로 다뤄야 한다.
