# 대기실 채팅 + 게임 제안 프론트엔드 작업 요청 · 참고 문서

> 기준: **모톡 API 명세서 v0.2.14** (대기실 채팅 -74 · 게임 제안 채널 추가, 지라 S15P11A706-74)
> 백엔드 구현 완료 · 통합 테스트 통과. **신규 화면 기능 2개**(채팅창, 게임 제안 버튼) 연동 요청입니다.
> 작성일: 2026-07-23

---

## 0. 가장 중요한 것 하나만 — 새 연결을 만들지 마세요

> 채팅은 **시그널링에서 이미 쓰고 있는 그 STOMP 연결(`/ws`)을 그대로 재사용**합니다.
> 새로 하는 일은 **구독 1개 추가 + 발신 목적지 2개**뿐입니다.
> (에러 큐 `/user/queue/errors` 는 시그널과 공용 — 이미 구독 중이면 추가 구독 불필요)

---

## 1. 연결·인증 (이미 하고 있는 것 — 확인용)

| 항목 | 값 |
|---|---|
| 엔드포인트 | `ws(s)://…/ws` (SockJS/STOMP — 시그널과 동일) |
| 인증 | STOMP **CONNECT 프레임 헤더**에 `Authorization: Bearer {accessToken}` (회원·게스트 공통) |
| 주의 | WebSocket 핸드셰이크 HTTP 헤더가 아닙니다 — `stompClient.connectHeaders`에 넣어야 합니다 |

## 2. 채널 계약

| 용도 | 방향 | destination | 페이로드 |
|---|---|---|---|
| 채팅 수신 | 구독 | `/topic/rooms/{roomId}/chat` | `ChatMessage` (아래) |
| 내 에러 수신 | 구독 | `/user/queue/errors` | `{ code, message, path }` |
| 채팅 발신 | 발행 | `/app/rooms/{roomId}/chat` | `{ "text": "안녕하세요!" }` |
| **게임 제안 발신** | 발행 | `/app/rooms/{roomId}/game-suggest` | `{ "gameId": 7, "gameName": "몸으로 말해요" }` |

## 3. 수신 페이로드 — ChatMessage는 type 판별 union

일반 채팅과 게임 제안이 **같은 토픽**으로 옵니다. `type`으로 분기하세요.

```jsonc
// 일반 채팅 (type: TALK) — gameId·gameName은 null
{ "type": "TALK", "userId": "guest-abc", "nickname": "성령",
  "text": "안녕하세요!", "gameId": null, "gameName": null,
  "sentAt": "2026-07-23T06:16:00Z" }

// 게임 제안 (type: GAME_SUGGEST) — text는 서버가 만든 폴백 문구
{ "type": "GAME_SUGGEST", "userId": "guest-abc", "nickname": "성령",
  "text": "'몸으로 말해요' 게임을 제안했습니다.", "gameId": 7, "gameName": "몸으로 말해요",
  "sentAt": "2026-07-23T06:16:00Z" }
```

TypeScript 타입 제안:

```ts
type ChatMessage = {
  userId: string        // participantId — 회원: userId, 게스트: guest-xxxx (v0.2.13에서 string 확정)
  nickname: string
  text: string
  sentAt: string        // ISO-8601
} & (
  | { type: 'TALK';         gameId: null;   gameName: null }
  | { type: 'GAME_SUGGEST'; gameId: number; gameName: string }
)
```

## 4. 게임 제안 — UI 규칙 (이번 기능의 핵심)

> 대기실의 같은 버튼 자리가 역할에 따라 달라집니다.
> **방장** → "게임 선택" (기존 동작 그대로, 백엔드 변경 없음)
> **비방장** → **"게임 제안"** → 누르면 게임 목록에서 고른 게임을 `/app/rooms/{roomId}/game-suggest`로 발행

- 발행 페이로드의 `gameName`은 **게임 카탈로그(`GET /games`)의 name을 그대로** 넣어 주세요.
  게임 도메인이 아직 백엔드 미구현이라 서버는 gameId 실존 검증을 못 하고 형식 검증만 합니다
  (도메인 구현 후 서버 검증으로 강화 예정 — 그때도 프론트 계약은 안 바뀝니다).
- **버튼 노출 분기는 프론트 책임입니다.** 서버는 방장 여부를 구분하지 않습니다
  (참가자면 누구나 발신 가능 — 방장이 보내도 에러는 아님).
- 수신 측 렌더링: `type === 'GAME_SUGGEST'`면 일반 말풍선 대신 **제안 카드**(게임명 + "이 게임 어때요?" 등)로
  그리는 걸 권장합니다. 급하면 `text` 폴백 문구를 그대로 뿌려도 됩니다.
- 방장 화면에서 제안 카드에 "이 게임으로 선택" 바로가기를 붙이면 UX가 좋아집니다
  (선택 자체는 기존 게임 선택 플로우 — 이번 백엔드 범위 밖).

## 5. 렌더링 지침 (채팅 공통)

- **자기 메시지도 토픽으로 돌아옵니다** — 발신 시 로컬에 append하지 말고, 수신 기준으로만 그리세요.
  전원이 같은 순서를 보게 되고 "전송 성공" 확인도 겸합니다.
- **이력이 없습니다** — 채팅은 서버에 저장하지 않습니다(명세 확정). 입장 전 대화는 볼 수 없고,
  새로고침하면 화면에서 사라지는 게 정상입니다.
- `sentAt`은 서버 시각입니다. 클라이언트 시계로 시각을 만들지 마세요.

## 6. 에러 — `/user/queue/errors`로만 옵니다 (본인에게만)

| code | 언제 | 프론트 처리 제안 |
|---|---|---|
| `COMMON_INVALID_INPUT` | 채팅: 빈 문자열·공백만·**500자 초과** / 제안: gameId 없음·0 이하, gameName 빈 값·**50자 초과** | 입력창에서 선제 차단(글자수 카운터) + 토스트 |
| `CHAT_NOT_IN_ROOM` | 방 참가자가 아닌데 발신 | 방 목록으로 이동 안내 |
| `ROOM_NOT_FOUND` | 방이 사라짐(전원 퇴장 등) | 방 목록으로 이동 안내 |
| `COMMON_UNAUTHORIZED` | CONNECT 없이 발신 등 | 재연결 플로우 |

## 7. 참고 코드 (stompjs 예시)

```ts
// 연결은 기존 시그널용 client 재사용
client.subscribe(`/topic/rooms/${roomId}/chat`, (frame) => {
  const msg: ChatMessage = JSON.parse(frame.body)
  appendMessage(msg)                          // type으로 말풍선/제안 카드 분기
})

// 채팅 발신
client.publish({ destination: `/app/rooms/${roomId}/chat`,
                 body: JSON.stringify({ text }) })

// 게임 제안 발신 (비방장 "게임 제안" 버튼)
client.publish({ destination: `/app/rooms/${roomId}/game-suggest`,
                 body: JSON.stringify({ gameId: game.id, gameName: game.name }) })
```
