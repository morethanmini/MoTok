## 0. 이 문서의 범위

이 문서는 **배포(운영) 환경변수의 "키(변수명)와 용도"만** 정리합니다.

- ❌ **실제 시크릿 값은 이 문서에 없고, 제출물 어디에도 포함하지 않습니다.**
  값은 전부 **GitLab → Settings > CI/CD > Variables** 에 등록돼 있으며 레포에는 존재하지 않습니다.
- 값 형식을 보여줘야 하는 자리에는 `xxxx` 로 마스킹한 예시만 적습니다.
  (`minioadmin`·`devkey`·`ssafy` 같은 **로컬 개발 기본값**은 코드에 그대로 공개돼 있는 더미라 예외적으로 표기합니다.)
- 로컬 개발용 값은 이 문서의 주인공이 아닙니다 → §6 참고.

### 0-1. 값이 주입되는 경로

```
GitLab Settings > CI/CD > Variables
  └─▶ .gitlab-ci.yml  (deploy-backend 잡이 heredoc + add() 로 .env 파일 생성)
        └─▶ MotionTok/Backend/.env
              └─▶ docker compose -f docker-compose.prod.yml
                    ├─ app 컨테이너: env_file: .env      → 컨테이너 환경변수
                    ├─ mysql 컨테이너: ${MYSQL_ROOT_PASSWORD} 등 compose 보간
                    └─ livekit 컨테이너: LIVEKIT_KEYS="${LIVEKIT_API_KEY}: ${LIVEKIT_API_SECRET}"
                          └─▶ Spring application.yaml 의 ${VAR} 플레이스홀더
```

프론트엔드는 경로가 다릅니다 — `.env` 를 거치지 않고 CI 가 `docker run -e` 로 빌드 컨테이너에 직접 넘깁니다(§3).

### 0-2. 이 문서를 읽을 때 알아야 할 문법 규칙

| `application.yaml` 표기 | 의미 |
|---|---|
| `${VAR}` | **기본값 없음 = 필수.** 미설정 시 플레이스홀더 해석 실패 → 기동 실패 |
| `${VAR:기본값}` | 선택. 미설정 시 기본값으로 동작 |
| `${VAR:}` | 빈 문자열이 기본값. 미설정 시 **해당 기능만** 비활성(degrade), 앱 기동에는 영향 없음 |

## 1. 필수 변수 — 없으면 앱이 기동하지 않음

`application.yaml` 전체에서 **기본값 없는 `${VAR}`** 를 전수 확인한 결과는 10개입니다:
`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`.

이 중 `DB_HOST`·`DB_PORT` 는 CI 가 하드코딩하므로(§1-2) **GitLab 에 등록해야 하는 필수 변수는 8개**이고,
여기에 `application.yaml` 에는 없지만 `docker-compose.prod.yml` 이 기본값 없이 요구하는 `MYSQL_ROOT_PASSWORD` 를 더해 **총 9개**입니다.

### 1-1. GitLab CI/CD Variables 에 반드시 등록해야 하는 9개

| 변수명 | 용도 | 값 형식(마스킹 예시) | 어디서 얻는가 | 미설정 시 증상 |
|---|---|---|---|---|
| `DB_NAME` | 운영 MySQL 스키마명. app 의 JDBC URL 과 mysql 컨테이너의 `MYSQL_DATABASE` 가 같이 씀 | `motiontok` 형태의 스키마명 | 팀이 정하는 값 | heredoc 이라 `DB_NAME=` 빈 줄이 들어감 → JDBC URL 에 DB 이름이 빠지고 mysql 이 스키마를 만들지 않음 → **기동 실패** |
| `DB_USERNAME` | 운영 MySQL 계정. mysql 컨테이너의 `MYSQL_USER` 로도 쓰임 | `xxxx` | 팀이 정하는 값(최초 기동 시 mysql 이 이 계정을 생성) | 빈 값 → DB 인증 실패 → **기동 실패** |
| `DB_PASSWORD` | 위 계정의 비밀번호. `MYSQL_PASSWORD` 로도 쓰임 | `xxxxxxxxxxxx` | 팀이 정하는 값 | 빈 값 → DB 인증 실패 → **기동 실패** |
| `MYSQL_ROOT_PASSWORD` | mysql 컨테이너 root 비밀번호. 최초 초기화와 healthcheck(`mysqladmin ping -uroot`)가 씀 | `xxxxxxxxxxxx` | 팀이 정하는 값 | **prod compose 에 기본값이 없음.** 빈 값이면 mysql 이 기동을 거부하고, app 은 `depends_on: service_healthy` 라 영원히 대기 → **배포 전체 실패** |
| `JWT_SECRET` | JWT(HS256) 서명 키 | `xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` (**32바이트=256bit 이상**) | 팀이 생성한 랜덤 문자열 (예: `openssl rand -base64 48`) | `JwtTokenProvider` 가 `Keys.hmacShaKeyFor()` 로 키를 만드는데 빈 값/짧은 값은 예외를 던짐 → 빈에서 **기동 실패**. `application.yaml` 주석에도 `Do NOT ship the default secret` 명시 |
| `MAIL_HOST` | SMTP 호스트 (회원가입 인증번호·비밀번호 재설정 메일) | `smtp.gmail.com` | 사용하는 메일 서비스 | `${MAIL_HOST}` 에 기본값이 없고 `add()` 는 빈 값이면 줄을 안 씀 → `Could not resolve placeholder` → **기동 실패** |
| `MAIL_PORT` | SMTP 포트 | `587` (STARTTLS) | 위와 동일 | 위와 동일 → **기동 실패** |
| `MAIL_USERNAME` | SMTP 계정 | `xxxx@gmail.com` | 위와 동일 | 위와 동일 → **기동 실패** |
| `MAIL_PASSWORD` | SMTP 비밀번호(Gmail 은 **앱 비밀번호**) | `xxxx xxxx xxxx xxxx` (Gmail 앱 비밀번호는 16자) | Google 계정 > 보안 > 앱 비밀번호 | 위와 동일 → **기동 실패** |

> ⚠️ **`MAIL_*` 4개가 "선택처럼 보이는" 함정**
> 이 4개는 `.gitlab-ci.yml` 에서 `add()` 로 처리됩니다. `add()` 는 값이 비면 **줄 자체를 쓰지 않으므로**
> 다른 `add()` 변수들은 미등록해도 `application.yaml` 기본값으로 안전하게 돕니다.
> 그런데 `MAIL_*` 만은 기본값이 아예 없어서, 미등록 = 플레이스홀더 미해결 = 기동 실패입니다.
> **`add()` 목록에 있다고 선택 변수가 아닙니다. 반드시 등록하세요.**
>

> 위 판정은 `application.yaml:34` 의 `host: ${MAIL_HOST}` 에 기본값이 없다는 정적 사실에 근거합니다.

> 단 이 우회는 **`.env` 를 직접 쓰는 로컬 전용**입니다 — CI 의 `add()` 가 빈 값을 걸러내므로
> GitLab Variables 에 빈 값으로 등록하면 '미설정'과 같아 기동에 실패합니다. 포팅매뉴얼 §7-1 참고.)

### 1-2. CI 가 하드코딩하는 값 — GitLab 에 등록하지 않는다

아래 4개는 `application.yaml` 이 읽지만 **GitLab 에 등록하는 값이 아닙니다.**
CI 가 heredoc 안에 고정 문자열로 박아 넣습니다. GitLab 에 등록해도 덮어쓰이지 않고 무시됩니다.
(`DB_HOST`·`DB_PORT` 는 기본값이 없어 필수, `REDIS_HOST`·`REDIS_PORT` 는 기본값이 있어 선택이지만
운영 값이 로컬과 달라 함께 고정합니다.)

| 변수명 | CI 가 박는 값 | 왜 고정인가 |
|---|---|---|
| `DB_HOST` | `mysql` | 같은 compose 네트워크의 컨테이너 이름 |
| `DB_PORT` | `3306` | 컨테이너 내부 직결(호스트 포트 매핑 없음) |
| `REDIS_HOST` | `redis` | 같은 compose 네트워크의 컨테이너 이름 |
| `REDIS_PORT` | `6379` | 컨테이너 내부 직결 |

> 이 값을 바꾸려면 GitLab Variables 가 아니라 `.gitlab-ci.yml` 의 heredoc 을 직접 수정해야 합니다.

## 2. 기능별 선택 변수 — 미설정 시 해당 기능만 비활성

각 표의 **"기본값"** 열이 이 문서의 핵심입니다 — 등록하지 않았을 때 무슨 값으로 도는지를 뜻합니다.
**"CI 전달"** 열은 `.gitlab-ci.yml` 이 그 변수를 `.env` 로 넘기는지 여부입니다.

> 🚨 **`CI 전달: ❌` 인 변수를 GitLab 에 등록해도 아무 효과가 없습니다.**
> 코드(`application.yaml`)는 그 변수를 읽지만 `.gitlab-ci.yml` 에 해당 `add()` 줄이 없어 `.env` 에 기록되지 않고,
> 컨테이너까지 도달하지 못합니다. 운영에서 그 값을 바꾸려면 **`.gitlab-ci.yml` 에 `add()` 줄을 먼저 추가**해야 합니다.

### 2-1. CORS·링크 도메인

> 이 그룹을 안 넣으면: **운영 도메인에서 브라우저가 CORS 로 전부 차단되고, 비밀번호 재설정 메일 링크가 localhost 로 나갑니다.**
> (앱은 정상 기동하므로 서버 로그만 보면 멀쩡해 보입니다 — 가장 놓치기 쉬운 그룹)

| 변수명 | 용도 | application.yaml 기본값 | CI 전달 | 값 형식(마스킹 예시) |
|---|---|---|---|---|
| `CORS_ALLOWED_ORIGINS` | 허용 오리진 목록(콤마 구분) | `http://localhost:5173` | ✅ | `https://xxxx.co.kr` |
| `PW_RESET_LINK_BASE` | 비밀번호 재설정 메일에 들어갈 링크 베이스 | `http://localhost:5173/auth/reset-password` | ✅ | `https://xxxx.co.kr/auth/reset-password` |
| `MAIL_FROM` | 인증 메일 발신자 주소 | `no-reply@mottok.local` (가짜 도메인) | ✅ | `no-reply@xxxx.co.kr` |
| `MAIL_HEALTH_ENABLED` | 종합 `/actuator/health` 에 SMTP 점검 포함 여부 | `false` | ✅ | `true` / `false` |

> `MAIL_HEALTH_ENABLED=true` 로 켜면 SMTP 가 막힌 망에서 종합 health 가 503 이 되고 호출마다 5초씩 매달려
> DB·Redis 상태를 가립니다. 컨테이너 healthcheck 는 liveness 를 보므로 재시작 동작에는 영향이 없습니다.

### 2-2. JWT 만료

> 이 그룹을 안 넣으면: **토큰 수명이 기본값(access 30분 / refresh 14일 / guest 30분)으로 돕니다.** 기능 손실은 없습니다.

| 변수명 | 용도 | application.yaml 기본값 | CI 전달 | 값 형식 |
|---|---|---|---|---|
| `JWT_ACCESS_EXPIRATION_MS` | Access 토큰 수명(ms) | `1800000` (30분) | ✅ | `1800000` |
| `JWT_REFRESH_EXPIRATION_MS` | Refresh 토큰 수명(ms). Redis `auth:refresh:{userId}` TTL 과 동일 | `1209600000` (14일) | ✅ | `1209600000` |
| `JWT_GUEST_EXPIRATION_MS` | 게스트 토큰 수명(ms). 게스트는 Refresh 가 없어 이 값이 곧 이용 가능 시간 | `1800000` (30분) | ❌ | `1800000` |

> `JWT_GUEST_EXPIRATION_MS` 는 `.gitlab-ci.yml` 에 `add()` 줄이 없습니다 → 운영은 항상 30분 고정입니다.

### 2-3. 소셜 로그인

> 이 그룹을 안 넣으면: **구글·카카오 로그인이 401 `SOCIAL_LOGIN_FAILED` 로 실패합니다.** 일반 이메일 로그인은 정상.
> 프론트도 짝이 되는 `VITE_*` 를 함께 넣어야 합니다(§3) — 백엔드만 넣으면 버튼이 비활성 상태로 보입니다.

|---|---|---|---|---|
| `GOOGLE_CLIENT_ID` | 구글 OAuth 클라이언트 ID | `` (빈 값) | ✅ | Google Cloud Console > OAuth 2.0 클라이언트 |
| `GOOGLE_CLIENT_SECRET` | 구글 OAuth 클라이언트 시크릿 | `` (빈 값) | ✅ | 위와 동일 |

> 이 그룹을 안 넣으면: **화상(카메라 공유)이 동작하지 않습니다.** 앱 기동에는 영향 없습니다.
> Spring 의 토큰 서명 키와 livekit 컨테이너의 `LIVEKIT_KEYS` 가 **같은 `.env` 를 공유**하므로 두 값은 자동으로 일치합니다.

> `.gitlab-ci.yml` 에 이 둘의 `add()` 줄 자체가 없으므로, **아무것도 하지 않는 것만으로 운영이 자동으로 AWS 모드**가 됩니다.

## 3. 프론트엔드 빌드 변수 (`VITE_*`)

프론트는 백엔드와 **주입 경로가 완전히 다릅니다.** `.env` 파일을 만들지 않고,
CI 의 `deploy-frontend` 잡이 빌드용 `node:22-alpine` 컨테이너에 `docker run -e` 로 직접 넘깁니다.

```
GitLab Variables ─▶ docker run -e VITE_XXX="$VITE_XXX" node:22-alpine  (pnpm build)
                      └─▶ dist/ (값이 번들에 박힘) ─▶ /srv/motok/frontend ─▶ nginx 서빙
```

| 변수명 | 용도 | 코드 기본값 | CI 처리 | 값 형식(마스킹 예시) |
|---|---|---|---|---|
| `VITE_API_BASE_URL` | 백엔드 REST base URL | `http://localhost:8080/api` (`http.ts:22`) | **CI 가 `/api` 로 하드코딩** — GitLab 에 등록할 필요 없음 | `/api` |
| `VITE_GOOGLE_CLIENT_ID` | 구글 OAuth 클라이언트 ID (authorize URL 에 실림) | `''` | ✅ GitLab Variables | `xxxxxxxx.apps.googleusercontent.com` |
| `VITE_KAKAO_REST_KEY` | 카카오 REST API 키 (백엔드 `KAKAO_CLIENT_ID` 와 **같은 값**) | `''` | ✅ GitLab Variables | `xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` |

### 3-1. 반드시 알아야 할 세 가지

1. **빌드 시점에 번들에 박힙니다 → 런타임 교체 불가.**
   값을 바꾸면 컨테이너 재시작이 아니라 **재빌드 + 재배포**가 필요합니다.
   백엔드 변수처럼 "CI 변수만 고치고 재배포" 로는 안 되고, 프론트 잡이 실제로 돌아야 반영됩니다.
2. **GitLab Variables 에 등록만 하고 `-e` 를 안 넘기면 반영되지 않습니다.**
   빌드가 별도 컨테이너 안에서 도는 구조라, `.gitlab-ci.yml` 의 `docker run` 에 `-e` 줄이 있어야만 vite 가 읽습니다.
   새 `VITE_*` 를 추가할 때 가장 흔한 실수입니다.
3. **`VITE_API_BASE_URL=/api` 는 상대경로라 CORS 가 발생하지 않습니다.**
   프론트와 API 가 브라우저 입장에서 같은 오리진이 되기 때문입니다.

### 3-2. 🔒 `VITE_*` 에 시크릿을 넣으면 안 되는 이유

> **`VITE_` 로 시작하는 값은 예외 없이 브라우저 번들에 평문으로 들어갑니다.**
> 누구나 개발자 도구 > Sources 나 `dist/assets/*.js` 에서 꺼내 볼 수 있습니다. 난독화는 방어가 아닙니다.

- 지금 들어 있는 2개는 **원래 공개되는 값**이라 안전합니다 — 구글 client_id 와 카카오 REST 키는
  authorize URL 의 쿼리스트링에 그대로 실려 나가는 값입니다(시크릿이 아닙니다).
- 반대로 아래 값들은 **절대 `VITE_*` 로 만들지 마십시오**:
  - `FAL_KEY` — 노출되면 제3자가 우리 fal 크레딧을 소진합니다.
  - `GMS_API_KEY` — 그래서 AI 채점은 프론트가 아니라 **서버에서만** 호출합니다.
  - `GOOGLE_CLIENT_SECRET`, `KAKAO_CLIENT_SECRET`, `JWT_SECRET`, `S3_SECRET_KEY`, `INTERNAL_API_KEY`, `DB_PASSWORD`
- 판별 기준 한 줄: **"이 값이 트위터에 올라가도 괜찮은가?" 가 아니면 백엔드에 두십시오.**

## 4. GitLab CI/CD Variables 등록 방법

### 4-1. 등록 절차

1. GitLab 에서 프로젝트로 이동합니다.
2. 좌측 메뉴 **Settings > CI/CD** 를 엽니다.
3. **Variables** 섹션의 **Expand** 를 누릅니다.
4. **Add variable** 을 클릭합니다.
5. **Key** 에 변수명을 **정확히 그대로** 입력합니다(대소문자·언더스코어 포함. `.gitlab-ci.yml` 이 이 이름으로 읽습니다).
6. **Value** 에 실제 값을 붙여 넣습니다. **앞뒤 공백과 줄바꿈이 섞이지 않게** 주의하십시오
   (붙여넣기 사고가 가장 흔한 배포 실패 원인입니다).
7. **Type** 은 `Variable` 로 둡니다(`File` 로 하면 값 대신 임시 파일 경로가 들어가 `.env` 가 깨집니다).
8. **Flags** 의 `Protected` / `Masked` 를 상황에 맞게 체크합니다(§4-2).
9. **Add variable** 로 저장합니다.
10. 값을 반영하려면 **재배포가 필요합니다.** `main` 브랜치에 커밋을 올리거나, GitLab 의 **CI/CD > Pipelines > Run pipeline** 으로 파이프라인을 다시 돌립니다.
    (`deploy-backend` 는 `MotionTok/Backend/**` 또는 `.gitlab-ci.yml` 변경 시,
    `deploy-frontend` 는 `MotionTok/Frontend/**` 또는 `.gitlab-ci.yml` 변경 시에만 실행되는 `changes` 규칙이 걸려 있습니다.)

### 4-2. Masked / Protected 체크박스의 의미

| 플래그 | 의미 | 주의점 |
|---|---|---|
| **Masked** | 잡 로그에 값이 찍히면 `[MASKED]` 로 가려 줍니다 | **값 자체를 숨기는 게 아니라 로그 출력만 가립니다.** 그리고 값이 형식 요건을 못 맞추면 GitLab 이 체크 자체를 거부합니다 |
| **Protected** | **protected 브랜치/태그**에서 도는 잡에만 전달됩니다 | 🚨 배포는 `main` 에서 돕니다. **`main` 이 protected 가 아니면 Protected 변수는 잡에 전달되지 않아 빈 값이 됩니다** — 필수 변수라면 그대로 기동 실패로 이어집니다 |

**Masked 요건** — 대략 다음을 만족해야 합니다: 한 줄일 것 / 최소 길이(8자 이상) / 공백·줄바꿈 없음 / Base64 계열 문자셋.
따라서 아래 변수들은 **Masked 를 못 걸 수 있습니다** — 그래도 정상이며, Masked 를 끄고 등록하면 됩니다:

- `FAL_PROMPT`, `FAL_NEGATIVE_PROMPT` — 공백이 있는 긴 문장
- `CORS_ALLOWED_ORIGINS` — 콤마·슬래시가 섞인 URL 목록
- `MAIL_PASSWORD` — Gmail 앱 비밀번호는 4글자씩 공백으로 끊긴 형태로 발급됩니다(공백을 제거해 붙이면 Masked 가능)
- `MAIL_PORT`, `FAL_STEPS` 같은 짧은 숫자 값 — 길이 요건 미달

> 이 프로젝트가 쓰는 GitLab 인스턴스의 버전은 확인하지 않았습니다. UI 가 거부하면 Masked 를 끄고 등록하십시오.

> Protected 를 켜기 전에 **Settings > Repository > Protected branches** 에서 `main` 을 먼저 확인하십시오.

### 4-3. 🚨 `add()` 헬퍼 주의 — 이 문서에서 가장 중요한 함정

`.gitlab-ci.yml` 의 선택 변수 처리는 다음 한 줄이 전부입니다:

```sh
add() { [ -n "$2" ] && echo "$1=$2" >> .env; return 0; }
```

즉 **값이 비어 있으면 `.env` 에 줄 자체를 쓰지 않습니다.**

- ✅ **대부분은 이게 안전장치입니다.** 줄이 없으면 Spring 이 `application.yaml` 의 기본값 `${VAR:default}` 를 씁니다.
  반대로 빈 문자열(`VAR=`)을 넣으면 Spring 은 그걸 "설정된 값"으로 보고 **기본값 대신 빈 값**을 써서 기동이 깨집니다.
  그래서 일부러 이렇게 만들었습니다.
- 🚨 **단, `MAIL_HOST`·`MAIL_PORT`·`MAIL_USERNAME`·`MAIL_PASSWORD` 4개만은 예외입니다.**
  이들은 `application.yaml` 에 기본값이 없어서(`${MAIL_HOST}`), 줄이 없으면 돌아갈 기본값도 없습니다
  → `Could not resolve placeholder` → **기동 실패**.
  `add()` 목록에 있다고 안심하지 말고 §1 의 필수 9개에 포함해 반드시 등록하십시오.
- 반면 heredoc 으로 쓰이는 `DB_NAME`·`DB_USERNAME`·`DB_PASSWORD`·`MYSQL_ROOT_PASSWORD`·`JWT_SECRET` 5개는
  **조건 없이 무조건 기록**됩니다. 미등록이면 `DB_NAME=` 같은 **빈 값 줄**이 생겨 역시 기동에 실패합니다.

## 6. 로컬 개발 값은 어디에 있나

### 6-1. 위치

| 파일 | 내용 | 레포 포함 여부 |
|---|---|---|
| `MotionTok/Backend/.env` | 백엔드 로컬 개발용 값(변수 30개) | ❌ **`.gitignore` 대상**(`MotionTok/Backend/.gitignore:39`) — 레포에 없습니다 |
| `MotionTok/Frontend/.env` | 프론트 로컬 개발용 값 | ❌ **`.gitignore` 대상**(`MotionTok/.gitignore:5`) — 레포에 없습니다 |
| `MotionTok/Frontend/.env.development` | `VITE_API_BASE_URL=/api` 한 줄 | ✅ **git 추적 중**(시크릿 없음). `pnpm dev` 에서 `.env` 를 이깁니다 |

- 두 `.env` 는 **팀원 로컬에만 존재**하며 시크릿이 들어 있어 제출물에 포함하지 않습니다.
- **로컬 재현 절차는 `exec/포팅매뉴얼.md` §4(로컬 실행 방법)** 를 보십시오.
  변수별 로컬 값 설명은 같은 문서 §3(환경 변수 상세)에 정리돼 있습니다.

### 6-2. 로컬 ↔ 배포에서 값이 **반드시** 달라지는 변수

| 변수 | 로컬 | 배포 |
|---|---|---|
| `DB_HOST` | `localhost` | `mysql` (compose 서비스명, CI 고정) |
| `DB_PORT` | 호스트 매핑 포트 | `3306` (컨테이너 직결, CI 고정) |
| `DB_NAME` / `DB_USERNAME` / `DB_PASSWORD` | 로컬 compose 계정 | GitLab CI 변수 |
| `REDIS_HOST` / `REDIS_PORT` | `localhost:6379` | `redis:6379` (CI 고정) |
| `JWT_SECRET` | 로컬 개발용 키 | GitLab CI 변수 (**로컬 키를 그대로 쓰지 마십시오**) |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173` | 운영 도메인 |
| `PW_RESET_LINK_BASE` | `http://localhost:5173/auth/reset-password` | 운영 도메인 기반 URL |
| `MAIL_FROM` | 기본 `no-reply@mottok.local` | 운영 발신 주소 |
| `LIVEKIT_URL` | `ws://localhost:7880` | `wss://<운영도메인>/livekit` |
| `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` | `devkey` / `devsecret-local-only-...` (로컬 더미) | GitLab CI 변수 |
| `S3_ENDPOINT` / `S3_PATH_STYLE` | MinIO 주소 / `true` | **비움 / `false`** (등록하지 않는 것이 정답) |

> 💡 로컬은 `S3_ENDPOINT`(MinIO)와 `S3_PATH_STYLE=true` 를 쓰지만, **운영은 이 둘을 등록하지 않아야** 실제 AWS S3 로 붙습니다.
> "로컬 `.env` 를 그대로 GitLab 변수로 옮기기" 를 하면 여기서 반드시 깨집니다.

> 반대로 아래 둘은 **로컬과 배포의 값이 같아** 위 표에 넣지 않았습니다 — 다르다고 오해하기 쉬운 자리라 따로 적어 둡니다.
> - `SWAGGER_ENABLED` — 팀 로컬 `.env` 에도 이 줄이 없어 로컬도 기본값 `false` 입니다(문서를 열어 볼 때만 `true` 로 추가). 운영도 미설정 = `false`.
> - `VITE_API_BASE_URL` — 로컬(`.env.development`)도 `/api`, 배포(CI 하드코딩)도 `/api` 입니다. **값은 같고 주입 경로만 다릅니다**(`.env.development` vs `docker run -e`).

## 부록. 배포 후 30초 점검

```bash
# EC2 에서
cat MotionTok/Backend/.env | cut -d= -f1   # 어떤 키가 실제로 주입됐는지(값 없이 키만) 확인
docker compose -f MotionTok/Backend/docker-compose.prod.yml ps   # 전 컨테이너 상태
curl -fsS http://localhost:9090/actuator/health   # SSH 터널 경유 관리 포트(외부 비공개)
```

- `.env` 에 `MAIL_HOST` 줄이 없으면 → 앱이 뜨지 않습니다(§1).
- `.env` 에 `DB_NAME=` 처럼 **값이 빈 줄**이 보이면 → 해당 GitLab 변수가 미등록입니다(§4-3).
- `.env` 에 `S3_ENDPOINT` 줄이 **보이면** → 운영이 AWS 가 아니라 호환 서버 모드로 붙습니다.
  이건 CI 가 쓰는 줄이 아닙니다(`.gitlab-ci.yml` 에 `add S3_ENDPOINT` 줄 자체가 없습니다).
  서버에서 `.env` 를 손댔거나 `.gitlab-ci.yml` 에 `add()` 줄이 추가된 것이니 그쪽을 되돌리십시오(§2-5).
