## 1. 시연 사전 준비

### 1-1. 접속 URL

| 환경 | URL | 비고 |
|---|---|---|
| **배포(권장)** | `https://motok.co.kr` | nginx가 HTTPS 종료. 카메라는 HTTPS에서만 동작하므로 시연은 **반드시 배포 환경 권장** |
| 로컬 프론트 | `http://localhost:5173` | Vite dev 서버 기본 포트. `localhost` 는 보안 컨텍스트라 HTTP여도 카메라 동작 |
| 로컬 백엔드 | `http://localhost:8080` | Vite dev 프록시가 `/api`, `/ws` 를 여기로 넘김 |
| 로컬 Actuator | `http://localhost:9090/actuator/health` | 관리 포트 분리 |

> **로컬 시연 시 주의**
> - `http://127.0.0.1:5173` 이 아니라 반드시 **`http://localhost:5173`** 으로 접속해야 합니다. 브라우저가 `localhost` 만 보안 컨텍스트로 인정하므로, IP로 접속하면 `getUserMedia` 가 막혀 카메라가 아예 안 켜집니다.
> - 로컬은 백엔드 인프라(MySQL·Redis·LiveKit·MinIO)가 떠 있어야 합니다. `MotionTok/Backend` 에서 `docker compose up -d` (LiveKit 포함 화상 시연 시 필수).

### 1-2. 필요한 기기 / 브라우저

| 항목 | 요구사항 | 근거 |
|---|---|---|
| OS / 기기 | **데스크톱 PC 또는 노트북**. 모바일 브라우저는 지원 범위 밖 | `MotionTok/Frontend/src/features/unsupported/UnsupportedView.vue` (요구사항 문구만 존재 — 실제 차단 게이트는 없음. 모바일로 접속해도 그대로 진입되며 카메라·모션 인식이 정상 동작하지 않을 뿐) |
| 브라우저 | **Chrome 최신 버전** 권장 | 동일 |
| 웹캠 | **최소 1280×720 권장**. 앱은 640×400 으로 요청하지만 화질이 낮으면 손·자세 인식률이 떨어짐 | `MotionTok/Frontend/src/features/device-setup/DeviceSetupView.vue` (`getUserMedia({video:{width:640,height:400}, audio:true})`) |
| 마이크 | 필수 (권한 요청에 `audio: true` 포함) | 동일 |
| 대수 | **최소 2대**, `그림으로 말해요` 시연까지 하려면 **3대** | 게임 10번은 `minPlayers = 3` |
| 네트워크 | 유선 LAN 권장. LiveKit 미디어는 **UDP 50000-50100** 사용. 사내망에서 UDP가 막히면 TCP 7881로 폴백 | `MotionTok/Backend/livekit/livekit.prod.yaml`, `docker-compose.prod.yml` |
| 초기 다운로드 | 첫 접속 시 **모션 인식 모델 약 17MB** 다운로드(손 7.8MB + 자세 9.4MB). 시크릿 창은 매번 다시 받음 | `MotionTok/Frontend/src/composables/motionModels.ts` |

### 1-3. 필요한 계정

시연에 필요한 계정은 **최소 3개 + 관리자 1개**입니다.

| 역할 | 용도 | 사전 준비 |
|---|---|---|
| **계정 A (발표자 · 방장)** | 로비 → 방 생성 → 게임 시작. 포인트 보유 필수 | 포인트 **1,500P 이상** 확보(AI 아이템 제작 시연용) |
| **계정 B (참가자 1)** | 코드 입장 · 채팅 · 게임 참여 | — |
| **계정 C (참가자 2)** | `그림으로 말해요` 3인 조건 충족용 | — |
| **관리자 계정** | `/admin` 대시보드 시연 | DB `users.role = 'ADMIN'` 으로 지정 후 **반드시 재로그인** |
| 신규 가입 시연용 이메일 | STEP 2 회원가입 라이브 시연 | 인증 메일을 실제로 받을 수 있는 주소 |

> **관리자 계정 만드는 법**
> 별도 관리자 승격 화면이 없으므로 DB에서 직접 역할을 바꿉니다.
> ```powershell
> docker exec -it motiontok-mysql mysql -ussafy -pssafy motiontok -e "UPDATE users SET role='ADMIN' WHERE email='<관리자이메일>';"
> ```
> (운영 EC2는 계정·비밀번호가 서버 `.env` 값이므로 `-u/-p` 를 그 값으로 교체)
>
> ⚠️ **역할 변경 후 반드시 로그아웃 → 재로그인** 해야 합니다. 관리자 메뉴 노출 여부는 액세스 토큰의 `role` claim 으로 판단하므로, 예전 토큰을 들고 있으면 헤더에 `관리자` 버튼이 나타나지 않습니다. (`MotionTok/Frontend/src/router/index.ts`)

### 1-4. 카메라 · 마이크 권한

- `/device-setup` 진입 즉시 `getUserMedia` 가 자동 호출되어 브라우저 권한 팝업이 뜹니다.
- **권한을 허용하기 전까지 `대기실 입장` 버튼은 비활성(disabled)** 입니다. 이 버튼이 회색이면 권한부터 확인하세요.
- 이미 "차단"으로 저장된 상태면 화면에 다음 안내가 뜹니다:
  > `브라우저가 차단하고 있어요. 주소창의 자물쇠 아이콘 → 사이트 설정에서 카메라·마이크를 허용으로 바꾼 뒤 다시 시도해 주세요.`
- **시연 전에 각 PC에서 미리 1회 허용해 두면** 발표 중 팝업이 안 뜨고 바로 넘어갑니다.

### 1-5. 조명 / 공간 / 촬영 구도

> ⚠️ 아래 값은 코드에 명시된 요구사항이 아니라, MediaPipe 기반 모션 인식의 특성상 권장하는 **운영 가이드**입니다.

| 항목 | 권장 |
|---|---|
| 조명 | 얼굴·손에 정면광. **역광(창문 앞) 금지** — 손 실루엣이 검게 뭉쳐 인식률이 급락 |
| 배경 | 단색·정돈된 배경. 배경에 다른 사람의 손·얼굴이 지나가지 않도록 |
| 거리 | 카메라에서 약 1~1.5m. `그대로 멈춰라` 는 **상반신 전체**가 들어와야 함 (서버 안내 문구: `카메라에 상반신이 잘 보이게 앉고…`) |
| 공간 | `별따라 손따라` · `모션 낚시` 는 양팔을 좌우로 벌리고 위아래로 휘두름 → **양옆 1m 여유** 필요 |
| 복장 | 배경과 대비되는 색. 손과 비슷한 색의 소품(살구색 벽 등) 피하기 |

### 1-6. 미리 만들어 둘 데이터

| 데이터 | 이유 | 준비 방법 |
|---|---|---|
| **계정 A 포인트 1,500P 이상** | AI 아이템 제작(STEP 21)이 1,500P 소모. **포인트 충전(PG) 기능은 코드로 잠겨 있어 현장 충전 불가** | 게임을 미리 몇 판 플레이해 보상 포인트 적립 |
| **계정 A 보유 아이템 2~3종** | 인벤토리·꾸미기(STEP 22)가 빈 화면이면 `보유한 아이템이 없어요. 상점에서 구매해보세요!` 만 뜸 | 상점에서 스티커·가면 미리 구매 |
| **랭킹 데이터** | `/ranking` 포디움이 비면 임팩트가 없음 | 각 게임을 계정 A/B/C 로 최소 1판씩 플레이해 기록 등록 |
| **친구 관계 A ↔ B** | 친구 목록·귓속말(STEP 23) 시연용 | 사전에 친구 요청 → 수락 |
| **미처리 신고 1~2건** | 관리자 대시보드(STEP 24)의 신고 접수함이 비면 보여줄 게 없음 | 계정 B로 계정 C의 채팅 메시지를 신고해 둠 |
| **DB 초기 데이터** | 게임 5종 · 상점 아이템 8종은 **앱 부팅 시 자동 시딩**됨 (`GameCatalogSeeder`, `RhythmGameSeeder`, `ShopItemSeeder`) | 별도 준비 불필요 |

### 1-7. 시연 30분 전 체크리스트

```
[ ] 3대 PC 모두 https://motok.co.kr 접속 후 F5 (신규 배포분 청크 반영)
[ ] 3대 모두 로비까지 진입해 모션 모델 17MB 선다운로드 완료 (스플래시 100%)
[ ] 3대 모두 /device-setup 에서 카메라·마이크 권한 "허용" 확인
[ ] 계정 A 로그인 · 포인트 1,500P 이상 확인
[ ] 계정 B, C 로그인 상태 유지
[ ] 관리자 계정은 별도 창(또는 4번째 PC)에 재로그인 완료
[ ] 웹캠 프리뷰로 조명·구도 확인 (역광 아님)
[ ] 백업용 녹화 영상 파일 위치 확인 (5장 참고)
[ ] 화면 공유 시 "브라우저 탭" 이 아니라 "전체 화면" 공유 선택 (게임이 전체화면 오버레이라서)
```

### 1-8. 시연에서 **보여주면 안 되는** 화면

| 화면 | 이유 |
|---|---|
| **`/result` (게임 결과 화면)** | 어떤 코드도 이 라우트로 이동시키지 않는 **미연결 목업**입니다. 화면 내용이 하드코딩된 더미(`민지·2위 8,420`, `P1·1위 9,850`, `Alex·3위 7,960`)라 실제 결과가 아닙니다. **실제 결과는 각 게임 화면 안의 오버레이**로 보여주세요. (`MotionTok/Frontend/src/features/game-result/GameResultView.vue`) |
| **포인트 충전** | `POINT_CHARGE_ENABLED = false` 로 잠겨 있습니다(PG 미연동). 헤더의 코인 잔액은 클릭되지 않는 표시용입니다. (`MotionTok/Frontend/src/config/features.ts`) |
| **`/unsupported`** | 어떤 코드도 이 라우트로 보내지 않습니다. 주소 직접 입력으로만 도달. |
| **`/dev/*` 라우트** | 개발용 실험실 화면. `/dev/catch-rhythm`, `/dev/chart-lab` 은 배포본에도 등록돼 있으니 주소창을 화면에 띄운 채 자동완성이 뜨지 않도록 주의. |
| **Swagger (`/swagger-ui/`)** | 운영은 `SWAGGER_ENABLED` 기본값 `false` 라 꺼져 있습니다. 열면 빈 화면이 나옵니다. |

### STEP 2. 회원가입 — 이메일 인증 포함 (라우트: `/auth?mode=signup`)

- **화면**
  단일 카드형 폼. 위에서부터 `이메일` 입력칸 + 우측 `코드 보내기` 버튼, `닉네임` + `중복 확인`, `비밀번호`, `비밀번호 확인`, 하단에 `가입하기` 버튼과 `이미 계정이 있어요` 링크.

- **조작**
  1. **`이메일`** 칸에 실제로 수신 가능한 주소 입력
  2. 우측 **`코드 보내기`** 버튼 클릭 → 버튼이 `전송 중…` 으로 바뀜
  3. 인증번호 입력칸이 새로 나타나고 **5분 카운트다운(`MM:SS`)** 이 표시됨. 버튼 문구는 `재전송` 으로 변경
  4. 메일함에서 제목 **`[모톡] 회원가입 인증번호`** 메일을 열어 6자리 코드 확인
  5. 인증번호 칸에 6자리 입력 → **`인증 확인`** 클릭 (`확인 중…` → 성공 시 **`✓ 이메일 인증이 완료됐어요`** 표시)
  6. **`닉네임`** 칸에 원하는 닉네임 입력 → **`중복 확인`** 클릭
  7. **`비밀번호`** / **`비밀번호 확인`** 입력
     - 화면 규칙 문구: `8자 이상, 영문 대/소문자·숫자·특수기호 중 3가지 이상 조합`
  8. 하단 **`가입하기`** 클릭 (`가입 중…`)

- **결과**
  가입 완료 후 **입력한 값 그대로 자동 로그인**이 이어지고 `/lobby` 로 이동합니다.
  (API 명세상 signup 응답에 토큰이 없어 프론트가 로그인 API를 한 번 더 호출하는 구조)

- **설명 포인트**
  - **메일 발송은 목업이 아니라 실제 SMTP(Gmail)** 입니다. 인증번호 TTL 5분, 재발송 쿨다운 60초, 이메일당 하루 5회 / 검증 시도 5회로 남용을 막습니다.
  - 닉네임은 중복 검사에 더해 **비속어 필터**를 프론트에서 선검사한 뒤 서버가 재검증합니다. 서버 정본 사전은 백엔드 리소스 `MotionTok/Backend/src/main/resources/profanity/wordlist.json` 이고, 프론트는 base64로 인코딩된 폴백 사전(`MotionTok/Frontend/src/utils/profanity/wordlist.ts` 의 `ENCODED_BAD_WORDS`)을 번들에 내장한 채 시작해 `GET /v1/profanity/wordlist` 로 서버 정본을 받아 교체합니다.
  - 에러 코드별 안내가 분리돼 있습니다: `이미 가입된 이메일입니다.` / 재발송 쿨다운 / 하루 한도 초과 / 검증 시도 초과.

- **시연 팁**
  메일 수신이 늦어질 수 있으니, **시연 전에 미리 한 번 코드를 받아 두고** 발표 때는 "이미 받아둔 코드"로 진행하면 안전합니다. 메일이 5분 안에 안 오면 STEP 3(기존 계정 로그인)으로 바로 넘어가세요.

### STEP 3. 로그인 (라우트: `/auth`)

- **화면**
  `이메일`, `비밀번호` 입력칸, `로그인 상태 유지` 체크박스, `아이디 찾기` · `비밀번호 찾기` 링크, `로그인` 버튼. 아래에 `또는` 구분선과 소셜 버튼, 맨 아래 `MoToK이 처음이세요? 회원가입` · `게스트로 시작하기` · `← 시작 화면으로`.

- **조작**
  1. (STEP 2 직후라면) 헤더 아바타 → **`로그아웃`** 으로 로그아웃한 뒤 `/auth` 로 이동
  2. **`이메일`** 에 계정 A 이메일, **`비밀번호`** 입력
  3. **`로그인 상태 유지`** 체크박스 클릭
  4. **`로그인`** 버튼 클릭 (`로그인 중…`)

- **결과**
  `/lobby` 로 이동. 헤더 우측에 닉네임·아바타·포인트 잔액이 표시됩니다.

- **설명 포인트**
  - Access Token(30분) + Refresh Token(14일) 이중 토큰. `로그인 상태 유지` 체크가 Refresh 쿠키 수명에 반영됩니다.
  - **로그인 실패 5회 시 차단**(`AUTH_LOGIN_ATTEMPTS_EXCEEDED`) — Redis 기반 레이트 리밋으로 브루트포스를 막습니다.
  - 제재 계정은 `AUTH_ACCOUNT_NOT_ACTIVE` 로 분리 안내되며, 정지 상태의 원천은 **Redis TTL** 이라 만료 시 자동 해제됩니다.

### STEP 4. 소셜 로그인 (라우트: `/auth`)

- **화면**
  로그인 모드 하단 `또는` 구분선 아래 소셜 버튼 2개 — **google** / **kakao** (각각 아이콘 + `로그인` 텍스트). 네이버 버튼은 없습니다.

- **조작**
  1. `/auth` 하단의 **kakao 소셜 로그인 버튼** 클릭
  2. 카카오 인가 페이지로 이동 → 카카오 계정으로 로그인 · 동의
  3. `https://motok.co.kr/auth?code=...` 로 자동 복귀

- **결과**
  폼 대신 **로딩 화면 `로그인 처리 중…`** 이 표시된 뒤 분기됩니다.
  - **최초 소셜 로그인** → `/auth/nickname` (모톡 닉네임 결정 화면). 이 화면은 가드가 걸려 있어 닉네임을 정하기 전까지 다른 화면으로 못 나갑니다.
  - **이미 같은 이메일로 가입돼 있던 경우** → 로비 진입 후 토스트 `이미 가입된 이메일이에요 · 기존 계정으로 로그인했어요` (최초 연동 1회만)
  - 그 외 → 바로 `/lobby`

- **설명 포인트**
  - **소셜 SDK를 쓰지 않고 인가코드(Authorization Code) 흐름을 직접 구현**했습니다. 프론트가 인가코드만 받아 백엔드로 넘기고, 토큰 교환·사용자 정보 조회는 서버가 수행하므로 **client secret이 브라우저에 노출되지 않습니다.**
  - redirect URI는 `{현재 origin}/auth` 하나로 통일 — 로컬(`http://localhost:5173/auth`)과 운영(`https://motok.co.kr/auth`)이 같은 코드로 동작합니다.
  - 소셜 콜백 대기 시간을 놀리지 않고 **그 사이에 MediaPipe 모델을 미리 내려받기 시작**합니다(`warmUpMotionModels`).
  - 소셜 계정은 **탈퇴 시에도 같은 provider로 재인증**을 요구합니다(STEP은 생략하되 언급).

  - 한 판을 마치면 전환 유도 모달 **`🎉 재밌으셨나요?` / `로그인하시고 다양한 사람들과 더 다양한 게임을 함께 즐겨보세요!`** 가 뜹니다.

### STEP 6. 로비 (라우트: `/lobby`)

- **화면**
  **최초 진입 시 스플래시**가 먼저 뜹니다 — `미니게임 놀이터에 연결 중` + 진행바 + `{손 인식|자세 인식} 모델을 불러오고 있어요… N%` → 완료 시 `준비 완료! 로비로 이동할게요…`
  로비 본화면: 상단 액션 바(`＋ 빠른 입장`, `＋ 코드 입장`), 중앙 `방 목록` + `{n}개의 방` + 검색창 + `＋ 방 만들기` + `새로고침 ↻`, 우측 친구 사이드바(`친구 목록 관리 →`), 하단 `📣 오늘의 소식`.
  방 카드에는 `{n}/{max}명`, `● 대기 중` / `● 게임 중`, `입장` / `입장 불가`, 비밀방이면 `🔒`.

- **조작**
  1. (스플래시가 뜨면) 진행바가 100%가 될 때까지 대기 — **이 화면을 그냥 넘기지 말고 설명 포인트로 활용**
  2. 방 목록을 한 번 훑으며 `＋ 빠른 입장` · `＋ 코드 입장` 위치 설명
  3. 우측 친구 사이드바에서 온라인 친구 표시 확인

- **결과**
  모델 준비가 끝나면 로비가 나타나고, 방 목록이 실시간으로 갱신됩니다.

- **설명 포인트**
  - **모션 인식 모델 17MB를 CDN이 아니라 자체 서버에서 호스팅**합니다(`public/mediapipe/`). 외부 CDN 장애·차단에 영향받지 않고, 브라우저 Cache Storage에 영속화해 두 번째 접속부터는 즉시 로드됩니다.
  - **게임 시작 직전이 아니라 로비 진입 시점에 미리 받는 이유** — 게임 시작 버튼을 누른 뒤 17MB를 받으면 전원이 몇 십 초를 기다려야 하므로, 로비에서 미리 확보해 체감 대기를 없앴습니다.
  - 방 목록·참가자 상태는 **Redis에 저장**됩니다. RDB에 방 테이블이 없습니다 — 휘발성 데이터의 성격에 맞춘 설계입니다.
  - 친구 온라인 여부는 **Presence(TTL 60초)** 기반 실시간 표시입니다.

### STEP 7. 방 만들기 (라우트: `/lobby` — 모달)

- **화면**
  모달 제목 `새 게임방 만들기`. 항목: `방 제목`(비우면 랜덤 기본 제목이 placeholder로 미리 보임), `공개 설정`(`공개방` / `비밀방`), `최대 인원`(스테퍼 `2~8명`, 기본 6), 비밀방 선택 시 `비밀번호`(숫자 6자리).

- **조작**
  1. 로비 우측 상단 **`＋ 방 만들기`** 클릭
  2. **`방 제목`** 에 `SSAFY 최종발표 시연방` 입력
  3. **`공개 설정`** 은 **`공개방`** 유지 (비밀방 옵션이 있다는 것만 언급)
  4. **`최대 인원`** 스테퍼로 `6명` 확인
  5. 하단 **`방 만들기`** 클릭

- **결과**
  방이 생성되고 `/device-setup?game=게임 선택 중&room={roomId}` 로 이동합니다.

- **설명 포인트**
  - 방 생성 즉시 **6자리 초대 코드**가 발급되어 친구를 부를 수 있습니다.
  - 정원은 2~8명. 1인 플레이도 내부적으로는 정원 2인 방을 만들어 같은 코드 경로를 재사용합니다.
  - 비밀방은 숫자 6자리 비밀번호로 보호됩니다.

### STEP 8. 기기 설정 (라우트: `/device-setup`)

- **화면**
  헤더 `카메라와 마이크를 확인해 주세요`, 우측에 `ROOM CODE` + 복사 버튼.
  좌측: 권한 카드 `카메라와 마이크 권한이 필요해요` + **`권한 허용하기`** 버튼(허용 후 **`카메라 연결 완료!`** 로 바뀌며 비활성), `카메라` / `마이크` 선택 드롭다운, **마이크 입력 레벨 미터 10칸**.
  우측: 웹캠 프리뷰 + 토글 `카메라 켜짐/꺼짐`, `마이크 켜짐/꺼짐`, 우하단 보물상자 아이콘 **`카메라 꾸미기`**.
  하단: **`취소`** / **`대기실 입장`**.

- **조작**
  1. 화면 진입 즉시 뜨는 브라우저 권한 팝업에서 **`허용`** 클릭 (사전 허용해 뒀다면 생략)
  2. 권한 카드가 **`카메라 연결 완료!`** 로 바뀌는 것을 확인
  3. **`카메라`** 드롭다운을 열어 장치가 여러 개일 때 선택 가능함을 보여줌
  4. **마이크에 대고 말해** 레벨 미터 10칸이 반응하는 것을 보여줌
  5. 우하단 **`카메라 꾸미기`**(보물상자) 클릭 → 미니 인벤토리에서 스티커를 프리뷰 위로 드래그 배치 → **`꾸미기 저장`** 클릭
  6. 하단 **`대기실 입장`** 클릭

- **결과**
  `/room` (대기실)로 이동하며, 방금 설정한 장치와 꾸미기가 그대로 방에 반영됩니다.

- **설명 포인트**
  - **권한을 얻기 전에는 `대기실 입장` 버튼이 비활성**입니다. 카메라 없이 들어가 "왜 안 보이지"가 되는 상황을 원천 차단합니다.
  - 마이크 레벨 미터는 실제 오디오 입력을 분석해 표시 — 마이크가 물리적으로 음소거된 경우까지 여기서 잡아냅니다.
  - 브라우저가 이미 "차단"으로 저장한 상태를 감지해 **자물쇠 아이콘 → 사이트 설정** 경로를 직접 안내합니다.
  - **꾸미기는 대기실 입장 전에 미리** 할 수 있습니다. 화면 위 스티커·가면 합성은 **로컬 캔버스에서 처리 후 송출**하므로 상대방에게도 그대로 보입니다.

### STEP 9. 대기실 · 실시간 채팅 (라우트: `/room`)

- **화면**
  상단 리본: 방 제목 · **`소리 설정`** · **`신고`** · **`친구 초대`** · **`설정`**(방장 전용) · `ROOM CODE` + 복사 버튼.
  중앙: 참가자 캠 타일 그리드(정원에 따라 레이아웃 자동 변경).
  하단: 스피커 음소거 / 마이크 / 카메라 토글, 채팅 독(placeholder `메시지 입력...`, `{n}/500`, 전송 아이콘, 전체보기), 우측 **`GAME START`** + **`LEAVE`**.

- **조작**
  1. 자기 캠 타일에 STEP 8의 꾸미기가 적용된 것을 확인
  2. 하단 채팅 입력창에 `안녕하세요! 지금부터 모톡 시연을 시작합니다` 입력 후 Enter
  3. 상단 리본 **`ROOM CODE`** 옆 **복사 버튼** 클릭 → 코드를 참가자 PC에 공유

- **결과**
  채팅이 즉시 표시되고, 이후 STEP 10에서 참가자가 들어오면 타일이 실시간으로 추가됩니다.

- **설명 포인트**
  - 영상·음성은 **LiveKit(자체 호스팅 SFU)** 으로 중계합니다. P2P Mesh와 달리 인원이 늘어도 각 클라이언트의 업로드 대역이 1개로 고정돼 **8인까지 안정적**입니다.
  - 채팅은 **STOMP over WebSocket**, 로그는 **Redis Stream** 에 저장됩니다. 신고 시 전후 대화 맥락을 그대로 복원할 수 있는 것이 이 구조 덕분입니다(STEP 24와 연결).
  - 채팅에도 레이트 리밋과 비속어 필터가 걸려 있습니다.
  - 실시간 연결이 끊기면 상단에 배너 `실시간 연결이 끊겼어요 · 채팅과 게임 시작이 동작하지 않아요` + `새로고침` 이 표시됩니다 — 조용히 실패하지 않습니다.

> **참고: "준비" 버튼은 없습니다.**
> 참가자가 준비 버튼을 누르는 방식이 아니라, 게임 시작 시 **서버가 전원의 모델 로드 완료를 자동으로 기다리는 게이트** 구조입니다. 오버레이로 `{게임명} 준비 중` / `모션 인식 모델을 받고 있어요… N%` / `참가자 준비를 기다리고 있어요… {ready}/{total}` 가 표시됩니다.

### STEP 10. 2·3번째 PC 코드 입장 (라우트: `/lobby` → `/device-setup` → `/room`)

- **화면**
  참가자 PC의 로비 상단 액션 바.

- **조작 — 참가자 PC(계정 B) 에서**
  1. `/lobby` 상단 **`＋ 코드 입장`** 클릭
  2. 모달 등장 — 제목 `방 코드로 참가`, 안내 `친구에게 받은 6자리 코드를 입력해주세요.`, placeholder `예: MP4X9K`, 6칸 슬롯 UI
  3. 방장이 공유한 6자리 코드 입력
  4. **`참가 ↗`** 클릭
  5. `/device-setup` 으로 이동 → **`대기실 입장`** 클릭
- **조작 — 3번째 PC(계정 C)** 도 동일하게 반복
- **(대안) 방 목록에서 직접 입장**: 로비 방 목록에서 `SSAFY 최종발표 시연방` 카드를 클릭해도 동일하게 입장합니다.

- **결과**
  방장 PC의 캠 타일 그리드에 참가자가 실시간으로 추가되고, 참가자 화면에도 방장 캠이 보입니다. 채팅에 입장 알림이 표시됩니다.

- **설명 포인트**
  - 입장 경로 4가지 — **코드 입장 / 방 목록 클릭 / 빠른 입장 / 친구 초대**. 상황에 맞는 진입로를 모두 제공합니다.
  - **`＋ 빠른 입장`** 은 조건에 맞는 방을 서버가 자동 매칭합니다. 없으면 토스트 `지금은 입장 가능한 방이 없어요. 새 방을 만들어 보세요` 와 함께 방 만들기 모달이 자동으로 열립니다.
  - **방장 권한 분리**: 게임 시작·방 설정 수정·강퇴·방장 위임은 방장만 가능합니다. 비방장이 게임 목록에서 보는 버튼은 `이 게임 제안하기` 하나입니다.
  - (여유가 있으면 시연) 방장 PC에서 참가자 타일의 메뉴 → 강퇴 모달 `{이름}님을 강퇴할까요?` 에 사유 5종(`비매너 행위`/`부적절한 프로필`/`게임 진행 방해`/`도배·광고`/`기타`)이 준비돼 있음을 보여줌. **실제로 `강퇴하기` 를 누르지는 말 것.**

### STEP 11. 게임 선택 · 설명 함께 보기 (라우트: `/room` — 모달)

- **화면**
  방장이 `GAME START` 를 누르면 모달 `어떤 게임을 해볼까요?` 가 열립니다. 좌측 `GAME LIST` 썸네일 카드 목록, 우측 그림 가이드 캐러셀.
  방장 버튼 2개: **`설명 함께 보기`** / **`바로 시작 →`**.

- **조작**
  1. 방장 PC 하단 우측 **`GAME START`** 클릭
  2. 좌측 `GAME LIST` 에서 **`별따라 손따라`** 카드 클릭
  3. 우측 그림 가이드 5장을 넘기며 캡션 확인
     - `카메라 앞에서 두 손을 쫙 펴요.` → `밤하늘에 별 그림이 나타나요.` → `손가락 끝으로 별을 하나씩 짚어요.` → `게이지를 모두 채울 때까지 가만히!` → `60초 동안 많이 만들면 이겨요.`
  4. **`설명 함께 보기`** 클릭 → **참가자 PC 화면도 같은 가이드로 전환**되는 것을 보여줌
     - 참가자 화면에는 `방장이 설명 중이에요` + `방장이 넘기면 이 화면도 같이 넘어가요.` 표시
  5. 가이드를 다 넘긴 뒤 **`바로 시작 →`** 클릭

- **결과**
  3초 카운트다운 후 게임이 시작됩니다. (전원 모델 준비가 안 됐으면 준비 게이트 오버레이가 먼저 표시)

- **설명 포인트**
  - **`설명 함께 보기`** — 방장이 넘기는 가이드 페이지가 방 전원 화면에 동기화됩니다. 처음 하는 사람에게 규칙을 설명하는 시간이 곧 게임 준비 시간이 됩니다.
  - **비방장은 `이 게임 제안하기`** 로 의사를 표현합니다. 채팅에 `🎮 {닉네임}` 제안 버블이 뜨고 방장에게만 `> 플레이` 버튼이 노출됩니다(쿨다운 있음).
  - **잠금 딱지 2종**: `준비 중`(프론트 미구현) / `점검 중`(관리자가 차단). 관리자 대시보드의 게임 차단(STEP 24)과 연결됩니다.

> **시작이 차단되는 조건 (토스트 문구 그대로)**
> - 카메라 꺼짐 → `카메라를 켜고 시작해 주세요`
> - 인원 미달 → `{게임명} 는 {minPlayers}명부터 시작할 수 있어요`
> - `그대로 멈춰라` + 혼자 → `혼자 있어서 연습 모드로 시작해요 — 랜덤 벽이 계속 날아와요`
> - 진행 중 → 버튼 tooltip `이미 게임이 진행 중입니다`

### STEP 12. 게임① **별따라 손따라** (라우트: `/room`, gameId=1)

- **화면**
  밤하늘 배경에 별자리가 나타납니다.
  상단: `✨ {별자리명} · 완성 {n}`, 홀드 게이지, 남은 시간 타이머, 우상단 `✕`.
  하단: `오른손 ✓/—`, `왼손 ✓/—`, `별 {hit} / {total}`.

- **조작**
  1. 3초 카운트다운 후 시작
  2. **카메라 앞에서 두 손을 쫙 펴고** 화면 속 별 위치에 열 손가락 끝을 맞춤
  3. 모든 별이 동시에 켜지면 홀드 게이지가 차오름 → **3초 유지** → 별자리 완성, 즉시 다음 별자리 등장
  4. 60초 동안 반복

- **결과**
  60초 종료 시 오버레이 **`🏆 최종 순위`** 에 순위·닉네임·점수와 획득 포인트가 표시되고 **`대기실로 돌아가기`** 버튼이 나타납니다.

- **설명 포인트**
  - **MediaPipe Hand Landmarker로 양손 21점씩을 추적**하고, 그중 손가락 끝 5점 × 2손 = **10개 슬롯(R1~R5 / L1~L5)** 을 별에 매핑합니다. 어느 손가락이 어느 별을 짚었는지까지 구분합니다.
  - 승부는 **완성 개수 1순위, 동률이면 평균 점수 2순위**.
  - **멀티플레이는 서버가 내려준 시드로 전원이 완전히 동일한 별자리 순서**를 받습니다 — 운이 아니라 실력으로 갈립니다.
  - 별자리 데이터는 **실제 별의 J2000 적경·적위를 평면 투영**해 만들었습니다(생성 스크립트 `MotionTok/Frontend/scripts/generate-constellations.mjs`, 총 20종).
  - 솔로 모드에는 **`⚔️ 60초 도전`**(신기록 저장)과 **`🚀 연습 라운드`**(별자리 1개 선택) 2종이 있습니다.

### STEP 13. 게임② **캐치캐치리듬** (라우트: `/room`, gameId=2)

- **화면**
  게임 시작 전 **설정 화면**이 먼저 뜹니다 — 제목 `캐치캐치리듬` / 부제 `곡 · 모드 · 난이도 설정`. **멀티에서는 방장만 조작 가능**하고 참가자에게는 `방장이 시작하기를 기다리는 중…` 이 표시됩니다.

- **조작**
  1. STEP 11과 같이 `GAME START` → 게임 목록에서 **`캐치캐치리듬`** 선택 → **`바로 시작 →`**
  2. 설정 화면에서
     - **곡**: **`SSAFY 응원가`** 선택 (또는 `랜덤 채보`)
     - **모드**: **`캐치`** 선택 (그 외 `링 · 슬라이드`, `링 · 탭만`)
       - ⚠️ **`SSAFY 응원가`** 를 고르면 **`링 · 탭만`** 은 자동으로 숨겨지고 **`캐치`** · **`링 · 슬라이드`** 두 개만 남습니다. 세 모드를 모두 보여주려면 **`랜덤 채보`** 를 먼저 선택하세요.
     - **난이도**: 응원가 선택 시 `어려움(풀)` / `어려움(하프)` / `익스트림(하프)` 중 **`어려움(하프)`**
  3. **`시작`** 클릭 (모델이 아직이면 `준비 중 N%` 로 표시됨)
  4. 날아오는 음표에 손을 대어 잡음
     - **파란 음표는 왼손(L)**, **빨간 음표는 오른손(R)**, **보라 음표는 아무 손이나**
     - 음표에 다가오는 원이 판정선과 겹치는 순간 손을 댐
     - 길게 이어진 음표는 경로를 따라 손을 움직임

- **결과**
  곡이 끝나면 점수와 순위가 표시되고 **`대기실로`** 버튼이 나타납니다.

- **설명 포인트**
  - **방 전원이 똑같은 채보로 동시에 플레이**합니다. 음악 재생 시점과 판정 타이밍을 실시간으로 동기화해야 하므로, 이 게임만 **전용 실시간 채널**을 사용합니다.
  - 채보는 자체 제작 도구(`/dev/chart-lab`)로 만들었으며, `SSAFY 응원가` 는 난이도 3종(풀/하프/익스트림)이 준비돼 있습니다.
  - `SSAFY 응원가` 기록은 **랭킹의 별도 이벤트 보드**(만점 41,200)에 등록됩니다 — STEP 18에서 이어서 보여줍니다.

> ⚠️ **주의**: 규칙 안내에 나오는 "금색 음표는 주먹을 쥐어 잡는다" 는 **현재 모든 난이도에서 생성 확률이 0** 이라 실제로는 나오지 않습니다. 시연 중 이 부분을 설명하지 마세요.

### STEP 14. 게임③ **그대로 멈춰라** (라우트: `/room`, gameId=4)

- **화면**
  이 게임만 시작 전 **설정 창(`GameSetupModal`)** 을 한 단계 더 거칩니다.

- **조작**
  1. `GAME START` → **`그대로 멈춰라`** 선택 → **`바로 시작 →`**
  2. 설정 창에서
     - **게임 모드**: **`출제 대결`** 선택
       (`돌아가며 내 포즈로 출제해요. 출제자는 그 라운드를 관전하고, 남은 사람이 그 구멍을 통과합니다.`)
       — 다른 선택지는 `연속 서바이벌`(`랜덤 벽이 끊이지 않고 날아와요…`)
     - **난이도**: **`보통`**(벽이 5초에 걸쳐 옴). 그 외 `쉬움`(6초) / `어려움`(4초)
     - (연속 서바이벌 선택 시에만) **벽 수**: `10개` / `20개` / `30개`
  3. **`시작 ▶`** 클릭
  4. **출제자 차례**: 카메라 앞에서 포즈를 취하면 그 포즈가 **벽의 구멍 모양**이 됨
  5. **나머지 참가자**: 다가오는 벽의 구멍과 같은 포즈를 취해 통과

- **결과**
  라운드마다 일치율 판정 팝업 `일치율 N% · +N점` 이 뜨고, 우측 `참가자 순위` 카드가 갱신됩니다. 출제자 화면에는 `👀 관전 중 — 이번 라운드는 안 뛰어요` 가 표시됩니다.

- **설명 포인트**
  - **MediaPipe Pose Landmarker로 잡은 관절 좌표를 3D 아바타(three.js)에 실시간 리깅**합니다. 단순히 실루엣을 비교하는 게 아니라 관절 각도를 아바타에 옮겨 담습니다.
  - **출제자의 실제 포즈가 그대로 벽의 구멍이 됩니다** — 미리 만든 포즈 세트가 아니라 매 판 새로 생성됩니다.
  - 판정은 이진 통과/실패가 아니라 **일치율(%)** 이라 아깝게 실패해도 점수가 남습니다.
  - 혼자면 출제 대결이 숨겨지고 안내 `혼자라서 연속 서바이벌만 할 수 있어요 — 출제 대결은 2명부터예요` 가 표시됩니다.

- **시연 팁**
  이 게임은 **상반신 전체가 카메라에 들어와야** 합니다. 앉은 자세에서 카메라를 조금 뒤로 빼거나 웹캠 각도를 위로 올리세요.

### STEP 15. 게임④ **모션 낚시** (라우트: `/room`, gameId=11)

- **화면**
  낚시 화면. 상단에 **`그만하기`** 버튼과 `⏱{남은 초}` + HUD 안내 문구, 우하단에 PiP 형태의 내 캠.
  카운트다운 중 안내: `양손으로 대를 쥐고 뒤로 젖혀 던지고, 기다리는 동안 손 높이로 깊이를 맞춰요 — 깊은 층일수록 점수가 큰 물고기!`

- **조작**
  1. `GAME START` → **`모션 낚시`** 선택 → **`바로 시작 →`**
  2. **캐스팅**: 양손으로 낚싯대를 쥔 자세를 만들어 **뒤로 젖혔다가 앞으로 휘두름**
  3. **대기 · 깊이 조절**: 양손 높이를 올리고 내려 미끼 깊이를 조절
     - 얕은 층 = 흰동가리(5점), 가장 깊은 층 = 상어(120점)
  4. **챔질**: 입질이 오면 **손을 위로 번쩍 들어 올림**
  5. **힘겨루기**: 한 손으로 릴 감는 동작 반복
  6. 90초 동안 반복

- **결과**
  종료 시 `🏆 최종 순위` 또는 `⏱ 낚시 종료!` + `{점수}점` + `{n}마리 · 🎣 다른 참가자를 기다리는 중…` 이 표시됩니다.

- **설명 포인트**
  - **제스처 상태 머신**: 캐스팅 → 대기 → 입질 → 챔질 → 힘겨루기 5단계가 각각 다른 손 동작을 인식합니다. 단발 제스처가 아니라 **연속된 동작 시퀀스**를 다룹니다.
  - **깊이 = 어종 = 점수** 라는 전략 요소를 넣어, 아무렇게나 던지는 것과 노리고 던지는 것의 결과가 달라집니다.
  - 90초 동안 총점이 가장 높은 사람이 승리합니다.

### STEP 16. 게임⑤ **그림으로 말해요** — AI 채점 (라우트: `/room`, gameId=10)

> ⚠️ **3명 이상 필수**입니다. 2명 이하면 토스트 `그림으로 말해요 는 3명부터 시작할 수 있어요` 로 차단됩니다.

- **화면**
  상단: `🎨 주제어: {주제어}`, `화가 {n} / {총원} · 내 차례!`
  하단: `✏️ 펜·{손} 엄지검지 그리는 중/이동`, `🧽 지우개·{손} 주먹 지우는 중/대기`, 버튼 **`✋ 손 바꾸기`**, **`차례 마치기 ▶`**(마지막 화가는 **`완성! 채점하기 ▶`**).

- **조작**
  1. `GAME START` → **`그림으로 말해요`** 선택 → **`바로 시작 →`**
  2. 첫 번째 화가 차례: 화면 상단의 주제어를 확인
  3. **펜 손(기본 오른손)의 엄지와 검지를 집으면 그려짐**, 벌리면 이동
  4. **지우개 손(기본 왼손)으로 주먹을 쥐고 문지르면 지워짐**
  5. (필요 시) **`✋ 손 바꾸기`** 로 펜/지우개 손 교체
  6. 자기 몫을 그린 뒤 **`차례 마치기 ▶`** 클릭 → 다음 화가로 카운트다운과 함께 교대
  7. 마지막 화가가 **`완성! 채점하기 ▶`** 클릭

- **결과**
  AI 채점이 실행되고 결과 화면이 표시됩니다.
  - 성공: **`🎯 AI가 {n}순위로 "{주제어}"을(를) 맞혔어요!`**
  - 실패: **`💫 AI 추측 5개에 "{주제어}"이(가) 없었어요`**
  - 아래에 완성된 그림과 AI 추측 5개 목록이 함께 표시됩니다.

- **설명 포인트**
  - **총 90초를 인원수로 나눠** 한 도화지에 이어 그리는 **협동(COOP)** 게임입니다. 점수는 전원 동일하게 배분됩니다.
  - **AI 채점**: 완성된 그림을 백엔드가 SSAFY GMS 릴레이(OpenAI 호환)로 보내 `가능성 높은 순으로 5개 추측` 을 받습니다.
  - **블라인드 채점**이 핵심 규칙입니다 — **정답 주제어를 프롬프트에 넣지 않습니다.** AI가 순수하게 그림만 보고 맞힌 것이라 채점의 공정성이 보장됩니다.
  - **전송 크기 제한 대응**: 릴레이가 요청 본문 65KB를 넘기면 모델을 부르지도 않고 거부하기 때문에, 프론트가 JPEG 화질(0.85→0.7→0.55→0.4) → 해상도(1→2/3→1/2) 순으로 자동으로 낮춰 60KB 이하로 맞춥니다.
  - 주제어 55개는 **서버가 단일 보유**합니다(프론트에 정답 목록이 없음 → 클라이언트 치팅 불가).

- **시연 팁**
  - 그림 그리기는 익숙하지 않으면 시간이 오래 걸립니다. **`사과`, `집`, `나무`** 같은 단순한 주제어가 나오면 진행하고, 어려운 주제어면 부담 없이 넘기세요(AI가 못 맞혀도 결과 화면 자체가 시연 포인트입니다).
  - 백엔드 AI 키(`GMS_API_KEY`)가 미설정이면 채점이 실패합니다. **시연 전 1회 테스트 필수.**

### STEP 18. 랭킹 (라우트: `/ranking`)

- **화면**
  히어로 영역 `MOTIONTOK ARCADE` / `명예의 랭킹 보드` / `MY BEST`(또는 `MY WEEK`) 플래그.
  컨트롤: 닉네임 검색창(placeholder `닉네임으로 순위 찾기`) + **`찾기`** 버튼, 게임 드롭다운, 모드 스위치.
  모드 스위치: **`멀티 플레이`** / **`혼자 플레이`**
  기간 탭: **`전체 랭킹`** / **`주간 랭킹`** / (캐치캐치리듬 선택 시) **`SSAFY 응원가`**
  본문: TOP 3 포디움 + 리더보드(10개/페이지) + 우측 `YOUR RECORD` 카드.

- **조작**
  1. 헤더 nav의 **`랭킹`** 클릭 (또는 주소창에 `/ranking`)
  2. 게임 드롭다운에서 **`별따라 손따라`** 선택 → TOP 3 포디움에 방금 플레이한 기록이 올라온 것을 확인
  3. 모드 스위치를 **`혼자 플레이`** ↔ **`멀티 플레이`** 로 전환해 보드가 갈리는 것을 보여줌
  4. 기간 탭을 **`주간 랭킹`** 으로 전환
  5. 게임 드롭다운을 **`캐치캐치리듬`** 으로 바꾸면 **`SSAFY 응원가`** 이벤트 탭이 추가로 나타나는 것을 보여줌
  6. 검색창에 참가자 닉네임 입력 → **`찾기`** 클릭 → 해당 순위로 스크롤
  7. 리더보드 행 하나를 클릭 → 사용자 프로필 모달 표시

- **결과**
  선택한 조건에 맞는 순위표가 즉시 갱신됩니다.

- **설명 포인트**
  - **`/ranking` 은 로그인 없이 접근 가능**합니다 — 비회원에게도 서비스를 노출하는 유입 경로입니다.
  - **보드를 3축으로 분리**했습니다: 게임 × 모드(멀티/솔로) × 기간(전체/주간). 솔로와 멀티는 경쟁 조건이 다르므로 같은 표에 섞지 않습니다.
  - **주간 랭킹은 최고점이 아니라 점수 합산**입니다(`leaderboard_weekly.score_sum`) — 한 번 잘한 사람이 아니라 꾸준히 한 사람이 올라갑니다. 주 시작은 **KST 월요일** 기준입니다.
  - **`SSAFY 응원가` 는 한시적 이벤트 보드**로, 본 랭킹과 테이블을 분리해 이벤트 종료 시 `DROP TABLE` 한 줄로 정리할 수 있게 설계했습니다.
  - 협동 게임(`그림으로 말해요`)은 전원이 같은 점수라 **`전체 랭킹` 탭 자체를 노출하지 않습니다** — 주간 탭만 보입니다.

- **설명 포인트**

  - **카메라·마이크 권한 상태를 마이페이지에서 직접 확인·재요청**할 수 있습니다. 권한 문제로 게임에 못 들어가는 사용자가 설정을 헤맬 필요가 없습니다.

  5. 카드가 `보유중`(비활성) + `OWNED` 배지로 바뀌는 것과 헤더 포인트가 차감된 것을 확인

- **결과**

- **설명 포인트**

### STEP 21. AI 아이템 만들기 (라우트: `/shop/ai-create`)

- **화면**
  좌측 **드로잉** 카드 — 도구 `연필` / `지우개` / `채우기`, `↶`(실행취소) / `↷`(다시실행), **`전체 지우기`**, 굵기 슬라이더(2~18), 색상 팔레트, 360×300 캔버스.
  우측 **생성** 카드 — `이름`(최대 20자), `분류`는 **`스티커` 고정**, 버튼 **`✨ AI로 생성하기`**.

- **조작**
  1. `/shop` 의 **`AI 아바타 만들기`** 카드에서 **`제작하기`** 클릭
  2. 좌측 캔버스에 **단순한 그림을 직접 그림** (예: 별, 하트, 고양이 얼굴)
     - 색을 바꾸려면 팔레트 클릭, 굵기는 슬라이더 조절
  3. 우측 **`이름`** 칸에 `발표기념 스티커` 입력
  4. **`✨ AI로 생성하기`** 클릭
  5. 확인 다이얼로그 **`AI 제작권을 사용할까요?`** / `AI ITEM PASS` `1,500 P` / `최대 2회 생성 · 최종 1개 선택` → **`생성하기`** 클릭
  6. 생성 진행 모달 대기

- **결과**
  완료되면 **`아이템이 완성됐어요!`** 또는 **`마음에 드는 결과를 골라 주세요`** 가 표시되고, **`이대로 생성`** / **`선택한 아이템 생성`** / **`다시 생성하기 1회`** 버튼이 나타납니다. 확정하면 내 인벤토리에 추가됩니다.

- **설명 포인트**
  - **손으로 그린 낙서를 AI가 게임용 픽셀풍 아이템으로 변환**합니다. 사용자마다 세상에 하나뿐인 아이템을 갖게 됩니다.
  - **1,500P 소모, 최대 2회 생성 후 1개 선택** — AI 결과의 불확실성을 사용자 경험 안에 흡수했습니다.
  - **후처리 파이프라인**: 생성 이미지의 흰 배경을 임계값 기반으로 제거해 **투명 PNG** 로 만든 뒤, S3에 업로드하고 그 URL을 아이템에 연결합니다. 캠 화면에 바로 합성할 수 있는 상태로 저장됩니다.
  - **AI 제공자를 환경변수 하나(`AI_PROVIDER`)로 전환**할 수 있게 설계했습니다: `GPU`(팀 자체 GPU 워커) / `FAL`(fal.ai) / `AUTO`(GPU 우선, 20초 안에 안 가져가면 fal로 인계).
  - **비용 방어**: fal 경로에는 일일 생성 한도가 걸려 있고, 한도 초과 시 대기 중인 작업을 **자동 실패 처리 + 포인트 전액 환불**합니다. 사용자에게는 `오늘의 AI 생성 한도를 모두 사용했어요. 내일 다시 시도해 주세요.` 로 안내합니다.
  - **NSFW 필터**: AI 응답에 유해 판정이 있으면 결과를 폐기합니다.

- **시연 팁**
  생성에 시간이 걸립니다. **캔버스에 그리는 시간을 짧게(10초 내외)** 가져가고, 생성 대기 동안 위 설명 포인트를 이어서 말하면 공백이 생기지 않습니다.

### STEP 22. 인벤토리 · 화면 꾸미기 (라우트: `/inventory`)

  - **장착 한도**: 스티커 5개, 가면·효과·배경 각 1개. 화면이 아이템으로 도배돼 게임 진행을 방해하는 것을 막습니다.
  - 꾸미기 합성은 **로컬 캔버스에서 처리한 뒤 송출**하므로 상대방 화면에도 동일하게 보이며, 서버에 영상 처리 부하를 주지 않습니다.

  - 온라인 상태는 **Presence(TTL 60초)** 기반이라 브라우저를 강제 종료해도 자동으로 오프라인 처리됩니다.

### STEP 24. 관리자 대시보드 (라우트: `/admin`)

- **화면**
  제목 `관리자 대시보드`. 상단에 탭 버튼 **7개**.

  | 탭 버튼 | 카드 제목 | 내용 |
  |---|---|---|
  | **`채팅 신고`** | 채팅 신고 접수함 | 상태 필터(전체/접수/검토 중/종결/기각), 표(방·신고자→피신고자·사유·신고된 메시지·상태·일시), `상세` 버튼 |
  | **`사용자 신고`** | 사용자 신고 접수함 | 표 + 행별 `검토` / `종결` / `기각` / `상세` |
  | **`신고 유저`** | 신고 많은 유저 | 누적 신고 횟수순 목록, `제재 내역` 버튼 |
  | **`제재 내역`** | 계정 제재 내역 | 닉네임 검색, 유형 필터, 현재 상태 카드, `기간 정지 해제` / `영구 정지 해제` / `포인트 내역` |
  | **`포인트 내역`** | 포인트 내역 | 읽기 전용. 닉네임·방향 필터, 요약(받아 간/쓴/현재 잔액), 원장 표 |
  | **`게임 관리`** | 게임 관리 | 범위 필터, 게임 표(`#`·게임·모드·분류·인원·범위·플레이 가능), **`차단`** / **`허용`** 토글 |
  | **`사용중인 유저`** | 사용중인 유저 | 15초 자동 갱신. 닉네임·위치(`방 안`/`로비`)·방·마지막 신호. 최대 500명 |

- **조작**
  1. **관리자 계정으로 로그인된 창**으로 전환 (역할 변경 후 재로그인 필수)
  2. 헤더 우측에 나타난 **`관리자`** 버튼 클릭 → `/admin` 으로 이동
  3. **`채팅 신고`** 탭 — 미처리 신고 행의 **`상세`** 클릭 → **신고된 메시지 전후의 대화 맥락이 복원된 모달** 확인
  4. 상세 모달에서 제재 부과 버튼들을 보여줌 (실제 부과는 시연용 더미 계정에만)
     - **`⚠️ 경고`** — 경고 문구가 당사자에게 전달됨
     - **`⛔ {닉네임} 기간 정지`** — 기간 프리셋 + 사유 입력, 버튼 `{n}일 정지`
     - **`🚫 영구 정지`** — 별도 모달, 버튼 `영구 정지`
     - 공통 안내: `제재하면 이 신고도 종결로 넘어갑니다`
  5. **`게임 관리`** 탭 클릭 → 게임 하나의 **`차단`** 토글 클릭
  6. **일반 사용자 PC로 전환** → 대기실에서 `GAME START` → 게임 목록에서 해당 게임에 **`점검 중`** 딱지가 붙어 선택 불가한 것을 확인
  7. 관리자 창으로 돌아와 **`허용`** 으로 되돌림
  8. **`사용중인 유저`** 탭 클릭 → 지금 접속 중인 시연 계정 3개가 각각 `방 안` / `로비` 로 표시되는 것을 확인
  9. **`포인트 내역`** 탭 클릭 → 전체 포인트 흐름 원장 확인

- **결과**
  게임 차단이 즉시 사용자 화면에 반영되고, 실시간 접속자 현황이 15초마다 갱신됩니다.

- **설명 포인트**
  - **신고 처리의 근거가 남습니다.** 채팅 신고는 신고 시점의 메시지 원문과 **전후 대화 맥락(context)** 을 함께 저장하므로, Redis Stream의 채팅 로그가 만료된 뒤에도 관리자가 판단 근거를 볼 수 있습니다.
  - **중복 신고 방지**: `(room_id, chat_id, reporter_user_id)` 유니크 제약으로 같은 메시지를 한 사람이 여러 번 신고할 수 없습니다.
  - **제재 이력과 현재 상태를 분리**했습니다. 이력은 `sanction_history` 에 append-only로 영구 보관하고, **"지금 정지 중인가" 의 원천은 Redis TTL** 입니다 — 기간이 지나면 별도 배치 없이 자동 해제됩니다.
  - **게임 차단은 단일 플래그(`is_active`) 하나**로 동작합니다. 버그가 발견된 게임을 재배포 없이 즉시 내리고, 고치면 즉시 올릴 수 있습니다.
  - **`사용중인 유저`** 는 Presence 데이터를 그대로 노출해 지금 몇 명이 어디에 있는지 실시간으로 파악합니다.
  - 관리자 권한은 **JWT의 `role` claim** 으로 검증합니다. 권한이 없으면 모달 `접근 권한이 없어요` / `관리자만 접근할 수 있는 페이지예요.` 를 띄우고 로비로 돌려보냅니다. **프론트 가드와 백엔드 인가가 이중으로** 걸려 있어 URL 직접 입력으로도 뚫리지 않습니다.

## 4. 시연 시 주의사항 / 돌발 상황 대처

### 4-1. 카메라 · 모션 인식 관련

| 증상 | 원인 | 대처 |
|---|---|---|
| **`대기실 입장` 버튼이 회색(비활성)** | 카메라·마이크 권한 미획득 | `권한 허용하기` 클릭 → 브라우저 팝업에서 `허용`. 이미 차단 저장 상태면 **주소창 자물쇠 아이콘 → 사이트 설정 → 카메라·마이크 → 허용** 후 **F5** |
| **카메라 프리뷰가 검게 나옴** | 다른 앱(Zoom·Teams·OBS)이 웹캠 점유 | 해당 앱 종료 후 F5. **시연 전 화상회의 앱을 모두 종료할 것** |
| **손 인식이 안 됨 / 별이 안 켜짐** | 역광, 손이 프레임 밖, 배경과 손 색이 유사 | 조명을 정면으로, 카메라에서 1~1.5m, 손을 프레임 안쪽으로. 하단 HUD의 `오른손 ✓/—` `왼손 ✓/—` 로 인식 여부를 즉시 확인 가능 |
| **자세 인식(그대로 멈춰라)이 안 됨** | 상반신이 프레임에 안 들어옴 | 뒤로 물러나거나 웹캠 각도를 위로. 앉은 자세라면 의자를 뒤로 |
| **게임 시작 시 `카메라를 켜고 시작해 주세요` 토스트** | 대기실에서 카메라 토글이 꺼짐 | 하단 카메라 토글을 `CAM ON` 으로 |
| **모션 모델 로딩이 오래 걸림** | 첫 접속 또는 시크릿 창(캐시 없음) | **시연 전 반드시 각 PC에서 로비까지 1회 진입**해 17MB를 미리 받아둘 것. 시크릿 창 사용 금지 |

### 4-2. 네트워크 · 실시간 관련

| 증상 | 원인 | 대처 |
|---|---|---|
| **상단에 `실시간 연결이 끊겼어요 · 채팅과 게임 시작이 동작하지 않아요` 배너** | WebSocket(STOMP) 끊김 | 배너의 **`새로고침`** 클릭. 방은 유지되므로 같은 코드로 재입장 가능 |
| **상대 캠이 안 보임 / 검은 화면** | LiveKit 미디어 UDP 차단 | 발표장 네트워크가 **UDP 50000-50100** 을 막고 있을 수 있음. 자동으로 TCP 7881로 폴백되지만 지연이 늘 수 있음. **가능하면 유선 LAN 또는 개인 핫스팟 사용** |
| **게임 시작 후 `참가자 준비를 기다리고 있어요… {ready}/{total}` 에서 멈춤** | 참가자 중 한 명의 모델 로딩 미완료 | 해당 PC를 확인. 계속 안 되면 그 참가자만 F5 후 재입장 |
| **하단에 `새 버전이 배포됐어요 · 지금 새로고침하지 않으면 게임이 시작되지 않을 수 있어요` 배너** | 시연 도중 재배포됨 | 즉시 **F5**. **시연 시간대에는 main 브랜치에 push하지 말 것**(CI가 자동 배포됨) |
| **응답이 전반적으로 느림** | 서버 부하 | 진행에는 지장 없음. 게임은 클라이언트에서 처리되므로 판정 자체는 영향받지 않음 |

### 4-3. 인원 · 계정 관련

| 상황 | 대처 |
|---|---|
| **PC가 2대뿐 (3인 필요한 `그림으로 말해요` 불가)** | ① 한 PC에서 **시크릿 창을 추가로 열어** 3번째 계정으로 접속 (단, 시크릿 창은 모델 17MB를 새로 받으므로 **미리 열어두고 로비까지 진입시켜 둘 것**) ② 그래도 안 되면 STEP 16을 건너뛰고 **녹화 영상으로 대체**(5장) |
| **PC가 1대뿐** | 멀티 시연 전체를 포기하고, `/games` → `혼자 플레이` 로 **1인 플레이만** 시연. 멀티는 녹화 영상으로 |
| **`{게임명} 는 {minPlayers}명부터 시작할 수 있어요` 토스트** | 인원 부족. `그림으로 말해요` 는 3명, `그대로 멈춰라` 출제 대결은 2명 이상 필요 |
| **관리자 메뉴(`관리자` 버튼)가 헤더에 안 보임** | DB에서 role만 바꾸고 **재로그인을 안 함**. 로그아웃 → 재로그인 |
| **계정 A 포인트가 1,500P 미만** | AI 아이템 제작(STEP 21) 불가. **현장 충전은 불가능**하므로 시연 전에 게임을 몇 판 돌려 확보할 것 |

### 4-4. 진행상의 주의

- **`/result` 는 절대 열지 마세요.** 하드코딩된 더미 데이터(`민지·2위 8,420` 등)가 보입니다.
- **포인트 충전은 시연하지 마세요.** 기능이 잠겨 있습니다.
- **주소창을 화면에 크게 띄운 채 타이핑하지 마세요.** 자동완성에 `/dev/*` 개발용 라우트가 뜰 수 있습니다.
- **화면 공유는 "브라우저 탭" 이 아니라 "전체 화면"** 으로 하세요. 게임이 전체화면 오버레이로 뜨므로 탭 공유 시 잘릴 수 있습니다.
- **회원 탈퇴 버튼을 실수로 누르지 마세요.** 같은 이메일로 **1주일간 재가입이 불가**합니다.
- **강퇴·영구 정지는 시연용 더미 계정에만** 적용하세요.

### 5-3. 최소 시연 코스 (5분 30초 압축판)

6. 랭킹(/ranking)   — 30초  : 3축 랭킹
7. 관리자(/admin)   — 30초  : 신고 맥락 복원 + 게임 차단
```
