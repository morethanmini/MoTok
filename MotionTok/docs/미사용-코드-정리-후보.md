### 조사 방법

- FE: 전 `.ts`/`.vue` 대상 export 심볼 ↔ 참조 카운팅, import 그래프로 고아 모듈 추출, `oxlint no-unused-vars`(--fix 없이) 병행
- BE: 전 `.java` 대상 타입/메서드/enum 상수 선언 ↔ 호출 카운팅, unused import 스캔
- 양방향: BE `@*Mapping` 62개 ↔ FE 호출 경로 대조, BE `@MessageMapping`/토픽 ↔ FE STOMP 목적지 대조

### 자동 스캔의 한계 (정리할 때 반드시 확인)

1. **Spring 빈은 이름 참조가 없다.** `@RestController`/`@Service`/`@Configuration` 클래스는 컨테이너가 생성하므로 "참조 0"이어도 살아 있다. 이 문서에서는 전부 걸러냈다.
2. **enum 상수는 JSON 값으로만 쓰일 수 있다.** `KickReason`, `ReportReason`, `ReportStatus` 상수 대부분은 Java 쪽 참조가 0이지만 FE가 문자열로 쓴다 — 살아 있다.
3. **동적 문자열 참조.** 예: `public/assets/icons/eye-open.svg`는 `` `eye-${open?'open':'closed'}.svg` ``로만 참조된다. 정적 스캔에서는 미사용으로 뜬다.
4. 아래 목록은 위 3가지를 **수동으로 걸러낸 뒤** 남은 것들이다.

## 2. 🟠 백엔드 — RTC/영상 3세대 마이그레이션 잔재

가장 큰 덩어리다. `P2P Mesh → OpenVidu → LiveKit`으로 두 번 갈아탔는데 **앞 두 세대가 통째로 남아 있다.**

### 2-1. 현재 실제로 살아 있는 경로

```
FE  sfuApi.videoToken()  →  GET /api/v1/live-rooms/{roomId}/video-token
                             └ SfuTokenController (VideoAccessMode.SFU_LIVEKIT 하드코딩)
                                └ VideoAccessService → LivekitAccessProvider → LivekitTokenSigner
```

`application.yaml:62`의 `rtc.provider`(기본 `livekit`)는 **통합 API에서만 쓰인다.** 그런데 그 통합 API를 FE가 호출하지 않으므로, `provider`를 `openvidu`/`mesh`로 바꿔도 실제 동작은 바뀌지 않는다.

### 2-4. 정리 시 판단이 필요한 지점

- **B3(`rtc-access`)를 지울 것인가, 반대로 FE를 이행시킬 것인가.** 통합 API는 "나중에 provider를 바꿔도 FE 수정이 없게" 만든 설계다. 멀티 provider 계획이 살아 있다면 B3은 남기고 오히려 FE `sfuApi`를 갈아타야 하고, LiveKit 고정이 확정이면 B3·B6~B12를 다 지우고 `VideoAccessService`도 단순화할 수 있다.
- **API 명세서가 절대 기준**이므로, 명세에 `/rtc-access`·`/rtc/ice-servers`가 실려 있다면 코드보다 명세를 먼저 고쳐야 한다.
- 관련 테스트 8종(`VideoAccess*Test`, `RtcIceServersIntegrationTest`, `MeshAccessProviderTest`, `OpenViduAccessProviderTest`, `SignalRelayIntegrationTest`)이 함께 지워진다.

## 14. 재조사 방법

이 문서의 목록은 `main` `81caf38` 기준이다. 시간이 지나면 다시 돌려야 한다.

```powershell
# FE 미사용 지역 변수·import (--fix 금지)
node ./node_modules/oxlint/bin/oxlint -D no-unused-vars src

# FE 타입 체크
corepack pnpm type-check
```

export 심볼 참조 카운팅·BE 메서드 스캔·엔드포인트 대조는 이번 조사에서 임시 스크립트로 수행했다(세션 스크래치패드에 있으며 저장소에는 커밋하지 않음). 재현이 필요하면 같은 방식으로:

1. `.ts`/`.vue`의 `export (const|function|class|interface|type|enum) X` 수집 → 다른 파일에서 `X` 단어 경계 매칭 카운트
   **주의:** `import * as ns from '...'` 때문에 `ns.X` 형태로 쓰이므로, 앞의 `.`을 제외하면 오탐이 난다
2. `.java`의 메서드 선언 수집 → `X(` / `::X` 카운트. 단 `return foo(`·`throw new Foo(`가 선언처럼 매칭되므로 키워드 필터 필수
3. BE `@*Mapping` 경로 ↔ FE 경로 문자열 대조. **FE가 `` `${BASE}/${id}/join` `` 처럼 변수를 섞으므로 전체 경로 문자열 비교는 오탐**이 난다 — 마지막 정적 세그먼트로 매칭할 것
