# 회원가입 · 로그인 화면 작업 요청 (프론트엔드)

> 기준: **모톡 API 명세서 v0.2.1** (이번에 이메일 인증 흐름이 추가되어 v0.2.0 → v0.2.1로 갱신됨)
> 백엔드 구현 완료 · 로컬 검증 완료. 아래 API는 전부 실제로 동작하는 상태입니다.
> 작성일: 2026-07-20

---

## 0. 먼저 알아야 할 것

현재 `AuthView.vue`는 **로그인/회원가입이 한 화면에서 이메일·비밀번호·닉네임 3개 입력으로 끝나는 구조**입니다.
명세 v0.2.1의 회원가입은 **이메일 인증을 반드시 거치는 다단계 흐름**이라, 화면 구조 자체를 바꿔야 합니다.

가장 중요한 변경점 하나만 꼽으면:

> **회원가입 요청(`POST /auth/signup`)에 `verificationToken`이 필수로 추가되었습니다.**
> 이메일 인증을 통과해야만 받을 수 있는 값이고, 서버가 1회 소비합니다.
> 이 값 없이는 가입이 400으로 거절됩니다. (백엔드에서 실제로 막히는 것을 확인했습니다.)

## 1. 서버 기본 정보

| 항목 | 값 |
|---|---|
| 로컬 Base URL | `http://localhost:8080/api` |
| 인증 헤더 | `Authorization: Bearer {accessToken}` |
| 요청/응답 형식 | JSON (UTF-8) |
| CORS 허용 origin | `http://localhost:5173` (Vite 기본) |

### 응답 형식이 바뀌었습니다

기존 백엔드는 `{ success, message, data }` 래퍼를 썼지만, **명세 기준으로 교체되어 이제 스키마를 그대로 반환**합니다.

성공 응답 — 래퍼 없이 바로 객체:
```
{ "tokenType": "Bearer", "accessToken": "...", ... }
```

실패 응답 — 모든 오류가 아래 `Error` 형식으로 통일:
```
{
  "code": "AUTH_EMAIL_ALREADY_REGISTERED",
  "message": "이미 가입된 이메일입니다.",
  "path": "/api/auth/email/verify-request",
  "timestamp": "2026-07-20T14:23:27.03+09:00"
}
```

> 화면에 띄울 문구는 `message`를 그대로 쓰셔도 되고, 분기 처리가 필요하면 `code`로 판단하시면 됩니다.
> `code` 목록은 아래 4번 항목에 정리해두었습니다.

## 2. 회원가입 화면에 추가해야 할 것

현재 화면에 **없는 것**들입니다. 단계별로 정리합니다.

### 단계 1 — 이메일 입력 + 중복 확인

- 이메일 입력란 (이미 있음)
- **[추가]** 중복 확인 트리거 — 입력 후 자동(디바운스 400~600ms 권장) 또는 버튼
- **[추가]** 결과 표시 — "사용 가능한 이메일입니다" / "이미 가입된 이메일입니다"
- **[추가]** 이메일 형식 오류 안내

`GET /auth/availability/email?email={이메일}` → `{ "available": true }`

> 사용 가능할 때만 다음 단계로 진행시켜 주세요.

### 단계 2 — 인증번호 발송

- **[추가]** "인증번호 받기" 버튼
- **[추가]** 발송 완료 안내 ("메일로 6자리 인증번호를 보냈습니다")
- **[추가]** **재발송 쿨다운 타이머 60초** — 버튼 비활성화 + 남은 초 표시
- **[추가]** 발송 한도 초과 안내 (이메일당 하루 5회)

`POST /auth/email/verify-request` — body `{ "email": "..." }` → **202** (본문 없음)

### 단계 3 — 인증번호 입력 + 검증

- **[추가]** **6자리 숫자 입력란** (현재 화면에 전혀 없음)
- **[추가]** **유효시간 5분 카운트다운** 표시
- **[추가]** 검증 실패 안내 + **남은 시도 횟수 개념** (5회 초과 시 코드가 폐기되어 재발송 필요)
- **[추가]** 만료/폐기 시 "인증번호 다시 받기"로 되돌아가는 동선

`POST /auth/email/verify` — body `{ "email": "...", "code": "123456" }`
→ `{ "verificationToken": "76e126e9-...", "expiresIn": 300 }`

> **이 `verificationToken`을 반드시 상태에 보관했다가 마지막 가입 요청에 실어 보내야 합니다.**
> 유효시간 5분이라, 인증 후 5분 안에 가입을 끝내지 않으면 다시 인증해야 합니다.
> 이 경우 화면에서 "인증 시간이 만료되었습니다. 다시 인증해 주세요"로 단계 2로 되돌려 주세요.

### 단계 4 — 비밀번호 입력

- 비밀번호 입력란 (이미 있음 — 단, **안내 문구 수정 필요**)
- **[추가]** **비밀번호 확인(재입력) 입력란** — 현재 없음
- **[추가]** 두 값 일치 여부 실시간 표시
- **[수정]** 현재 placeholder가 `8자 이상 입력`인데, 실제 규칙과 다릅니다

**실제 적용된 비밀번호 규칙** (백엔드에서 강제):

> 8~64자이며, **영문 소문자 · 영문 대문자 · 숫자 · 특수문자 중 3종류 이상** 조합

- 통과 예: `Passw0rd!`, `motok2026A`
- 거절 예: `password123` (소문자+숫자 = 2종류)

> 비밀번호 확인 필드는 **프론트에서만 대조**합니다. 서버로는 `password` 하나만 보냅니다.
> (명세 `SignupRequest`에 확인용 필드가 없습니다.)

### 단계 5 — 닉네임 입력 + 중복 확인

- 닉네임 입력란 (이미 있음)
- **[추가]** 중복 확인 + 결과 표시
- **[추가]** 길이 안내 — **2~16자**

`GET /auth/availability/nickname?nickname={닉네임}` → `{ "available": true }`

> 한글 닉네임은 **URL 인코딩** 필수입니다. `encodeURIComponent()`를 꼭 쓰세요.
> (인코딩 없이 보내면 서버가 파라미터를 디코딩하지 못합니다.)

### 단계 6 — 가입 완료

- "가입하고 시작하기" 버튼 (이미 있음 — 동작 연결 필요)

`POST /auth/signup` — body:
```json
{
  "email": "tester@motok.com",
  "password": "Passw0rd!",
  "nickname": "테스터",
  "verificationToken": "76e126e9-b677-4440-ba46-ed695ee5ac48"
}
```
→ **201** + `UserProfile`
```json
{ "id": 1, "email": "...", "nickname": "테스터", "role": "USER", "pointBalance": 0, "createdAt": "..." }
```

> ⚠️ **주의: 가입 응답에는 토큰이 없습니다.**
> 명세상 `POST /auth/signup`의 응답은 `UserProfile`이고 `TokenResponse`가 아닙니다.
> 따라서 가입 직후 바로 로비로 보내려면, **가입 성공 후 곧바로 `POST /auth/login`을 한 번 더 호출**해서 토큰을 받으세요.
> 이 시점에 이메일·비밀번호가 이미 화면 상태에 있으므로 사용자에게 재입력을 요구할 필요는 없습니다.
> (이 부분은 명세를 바꿔 가입 응답에 토큰을 포함시킬 수도 있습니다 — 원하시면 백엔드로 알려주세요.)

## 3. 로그인 · 토큰 처리

### 로그인

`POST /auth/login` — body `{ "email": "...", "password": "...", "rememberMe": true }`
(`rememberMe`는 선택 필드, 생략 가능)

→ **200** `TokenResponse`
```json
{
  "tokenType": "Bearer",
  "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
  "refreshToken": "eyJhbGciOiJIUzI1NiJ9...",
  "expiresIn": 1800,
  "user": { "id": 1, "email": "...", "nickname": "테스터", "role": "USER", "pointBalance": 0, "createdAt": "..." }
}
```

### 토큰 정책

| 토큰 | 유효기간 | 용도 |
|---|---|---|
| accessToken | **30분** (`expiresIn: 1800`) | 모든 API 요청의 `Authorization` 헤더 |
| refreshToken | **14일** | access 만료 시 재발급용. 서버 Redis에 저장됨 |

### 갱신

`POST /auth/token/refresh` — body `{ "refreshToken": "..." }` → 200 `TokenResponse`

> **중요: refresh 토큰은 갱신할 때마다 새 값으로 회전(rotation)됩니다.**
> 응답으로 받은 **새 refreshToken으로 반드시 교체 저장**하세요.
> 옛 refreshToken은 즉시 무효가 되어 401이 납니다.

권장 구현: HTTP 인터셉터에서 401을 만나면 자동으로 refresh → 원요청 재시도.
refresh도 401이면 로그아웃 처리하고 로그인 화면으로 보내세요.

### 로그아웃

`POST /auth/logout` — **인증 필요** (`Authorization` 헤더 필수), 응답 **204**

> 현재 프론트 `session.ts`의 `logout()`은 로컬 상태만 지웁니다.
> 이러면 **서버의 refresh 토큰이 14일간 살아있게 됩니다.** 반드시 이 API를 호출하도록 바꿔주세요.

### `session.ts` 수정 필요 사항

현재 스토어에 **토큰을 담을 자리가 아예 없습니다.** 아래가 필요합니다.

- `accessToken`, `refreshToken` 보관
- 프로필 필드를 명세 `UserProfile`에 맞추기
  - 현재 `Profile { nickname, email, coins }` → 명세는 `{ id, email, nickname, role, pointBalance, createdAt }`
  - **`coins` → `pointBalance`**로 이름이 다릅니다
  - `role`은 현재 `'guest' | 'member'`로 쓰고 있는데, 명세의 `role`은 **`USER | ADMIN`(권한)**입니다. 의미가 충돌하니 게스트 여부는 별도 필드로 분리해 주세요.
- 저장 위치: `rememberMe`가 true면 `localStorage`, 아니면 `sessionStorage` 정도를 권장합니다.

## 4. 오류 코드 목록

화면 분기가 필요할 때 `code` 값으로 판단하세요.

| HTTP | code | 상황 | 화면 처리 제안 |
|---|---|---|---|
| 400 | `COMMON_INVALID_INPUT` | 입력 형식 위반 | `message`를 필드 아래 표시 |
| 400 | `AUTH_VERIFICATION_CODE_INVALID` | 인증번호 불일치·만료 | 재입력 유도 |
| 400 | `AUTH_VERIFICATION_TOKEN_INVALID` | 인증 토큰 없음·만료·재사용 | 이메일 인증 단계로 되돌리기 |
| 401 | `AUTH_INVALID_CREDENTIALS` | 로그인 실패 | "이메일 또는 비밀번호를 확인해 주세요" |
| 401 | `AUTH_INVALID_TOKEN` | 토큰 만료·무효 | refresh 시도 → 실패 시 로그아웃 |
| 401 | `COMMON_UNAUTHORIZED` | 인증 없이 접근 | 로그인 화면으로 |
| 403 | `AUTH_ACCOUNT_NOT_ACTIVE` | 정지·차단된 계정 | "이용이 제한된 계정입니다" |
| 409 | `AUTH_EMAIL_ALREADY_REGISTERED` | 이메일 중복 | 이메일 입력란에 표시 |
| 409 | `AUTH_NICKNAME_ALREADY_USED` | 닉네임 중복 | 닉네임 입력란에 표시 |
| 429 | `AUTH_RESEND_COOLDOWN` | 60초 쿨다운 중 | 남은 시간 표시 |
| 429 | `AUTH_SEND_LIMIT_EXCEEDED` | 1일 5회 초과 | "내일 다시 시도해 주세요" |
| 429 | `AUTH_VERIFY_ATTEMPT_EXCEEDED` | 코드 검증 5회 초과 | 재발송 유도 |

## 5. 로컬 개발 팁

**메일이 실제로 오지 않습니다.** SMTP 계정이 아직 설정되지 않아서, 인증번호는 **백엔드 콘솔 로그**로 출력됩니다.

```
WARN ... VerificationMailSender : [메일 미설정] tester@motok.com 인증번호 = 569634 (SMTP 미설정이라 실제 발송하지 않음)
```

프론트 개발 중에는 이 로그에서 6자리 숫자를 복사해 쓰시면 됩니다.
실제 메일 발송은 백엔드에서 `MAIL_HOST` 등 환경변수를 설정하면 자동으로 전환됩니다.

**백엔드 실행 순서**
```
cd MotionTok/Backend
docker compose up -d     # MySQL(3307) + Redis(6379)
./gradlew bootRun        # http://localhost:8080
```

## 6. 아직 백엔드에 없는 것 (이번 범위 밖)

회원가입/로그인 화면에서 링크나 버튼을 만들더라도, 아래는 **아직 동작하지 않습니다.**

- 소셜 로그인 (`POST /auth/social/{provider}`) — 구글·카카오·네이버 **미구현**
  - 현재 화면 하단의 Google / Kakao / Naver 버튼은 아직 붙일 API가 없습니다
- 아이디 찾기 (`POST /auth/find-id`) — 미구현
- 비밀번호 재설정 (`POST /auth/password/reset-request`, `/reset`) — 미구현
- 게스트 시작 (`POST /auth/guest`) — 토큰은 나오지만, 명세의 `GuestResponse`(임시 닉네임 서버 부여 + 1인방 자동 생성)와는 아직 다릅니다

이 항목들은 다음 작업에서 붙일 예정입니다. 화면은 미리 만들어두시되, 연동은 보류해 주세요.

## 7. 질문·요청

- 가입 직후 자동 로그인을 위해 **`POST /auth/signup` 응답에 토큰을 포함**시키는 게 편하다면 알려주세요. 명세를 함께 수정하면 됩니다.
- 인증번호 입력 UI에서 **남은 시도 횟수를 표시**하고 싶다면, 검증 응답에 잔여 횟수를 내려주도록 추가할 수 있습니다. 현재 명세에는 없습니다.
