② 소셜 로그인 닉네임: provider 닉네임을 더 이상 가져오지 않는다. 최초 소셜 로그인 계정은 임시 닉네임(pending_*, 28자라 사용자가 선점 불가) + nicknamePending=true 상태로 생성되고, TokenResponse.nicknameSetupRequired가 true면 클라이언트는 닉네임 설정 화면으로 보낸다. 확정은 기존 PATCH /users/me(중복 검사 409)가 처리하며 저장 시 pending이 해제된다.
③ 탈퇴 본인 확인: DELETE /users/me에 WithdrawRequest 본문 추가 — 자체 가입은 비밀번호, 소셜 전용 계정(비밀번호 없음)은 소셜 재인증. 소셜 계정의 탈퇴를 막지 않는다(탈퇴 수단이 사라지는 문제).
④ 재가입 제한: 탈퇴 후 1주일 동안 같은 이메일·소셜 계정으로 재가입 불가(409 AUTH_REJOIN_COOLDOWN). 판정 근거는 식별자 해시만 남기는 withdrawn_accounts 테이블(ERD 추가분). 탈퇴 계정의 포인트·전적·아이템·친구는 복구되지 않으며 재가입 시 새 계정으로 시작한다.
⑤ 타인 프로필 조회: GET /users/{userId} 신규 — 닉네임·가입일만 담은 PublicUserProfile. 랭킹에서 이름을 눌러 조회하며, 탈퇴·정지 계정은 404.
⑥ 접근 제어: GET /live-rooms가 🔓 공개 → 회원 전용으로 바뀐다(게스트는 자동 생성된 1인방만 사용하고 로비 목록을 열지 않는다). 로그인 이후 플로우(로비·상점·인벤토리·친구·마이페이지)는 전부 인증 필수.

인증 · 오류 규격 공통

인증 — 대부분의 엔드포인트는 Authorization: Bearer <accessToken> 필요. 로그인/가입/소셜/게스트/공개 조회(게임·곡·리더보드)는 인증 불필요. 방 목록(GET /live-rooms)은 v0.2.12부터 회원 전용이다. Access 만료 시 POST /auth/token/refresh로 갱신, Refresh는 Redis auth:refresh:{userId}(TTL 14d)에 저장되어 로그아웃 시 삭제=무효화.
토큰 수명과 갱신 전략 (v0.2.12) — Access 1시간 · Refresh 14일(발급마다 회전) · 게스트 토큰 12시간(Refresh 없음).
한 세션(로비→방→게임)이 30분을 쉽게 넘기는데 그동안 REST 요청이 거의 없다. 요청이 있을 때만 갱신하면 게임을 마치고 나올 때 토큰이 이미 죽어 로비로 못 돌아간다. 그래서 클라이언트는 ① 만료 5분 전 타이머로 선제 갱신하고(탭 복귀 시에도 확인), ② 요청 직전 만료가 임박했으면 먼저 갱신하며, ③ 그래도 401이면 1회만 갱신 후 재시도한다. Refresh는 회전되므로 동시 요청이 여러 번 갱신하지 않도록 단일 비행(single-flight)으로 묶어야 하고, 갱신까지 실패하면 로컬 토큰을 지운 뒤 세션 만료 안내 후 로그인 화면으로 보낸다. 게스트는 갱신 수단이 없어 토큰 자체를 길게 두고, 탭을 닫으면 sessionStorage와 함께 소멸한다.
회원가입 이메일 인증 — 가입은 3단계다. ① GET /auth/availability/email 중복 확인 → ② POST /auth/email/verify-request 6자리 코드 발송(Redis auth:email:code:{email}, TTL 5m) → ③ POST /auth/email/verify 코드 검증 후 발급된 verificationToken(TTL 5m)을 POST /auth/signup에 실어 보내면 서버가 1회 소비한다. 토큰이 없거나 만료·재사용이면 가입은 400으로 거절된다.
